Build

Build menu (enabled when a project is open and Play is stopped):

  • Build Settings... opens a modal with one setting, Start Scene: a dropdown of every *.scene in the project that would ship in game.pak (no dotfiles or dot-directories), as sorted project-relative / paths, listed when the modal opens. It starts on the current startScene; one that is set but not listed shows as <path> (missing). With no scenes the dropdown is disabled and the modal says No scenes in project. Save a scene first. Save (enabled once a listed scene is chosen) checks that the scene loads, then writes it as startScene to project.kast (nothing else changes: not the open scene, its unsaved changes or .kast/editor.json); a failure shows in the modal and writes nothing. Cancel / Escape closes without writing. There is no way to set startScene back to null here.
  • Online Services... opens a modal editing the project's online block: Enabled, Auth URL and CA File (typed as a project-relative path, or Browse... for a .pem/.crt; a file outside the project shows as an error; Clear removes it). It is checked as you edit (while enabled: URL set and http(s), CA file exists inside the project, holds a valid PEM certificate and is not in a dot-folder); the first problem shows in red and disables Save. Opening it shows a problem already in the saved settings (e.g. a deleted CA file). Save writes only the online block to project.kast; Cancel / Escape writes nothing.
  • Build... asks for an output folder, then builds the game into it.
  • Build and Run builds into the project's last output folder (asks if there is none), then starts the game as a separate process.

Both first offer to save unsaved scene changes (the same prompt as File > Open), because the game is built from the files on disk. The last output folder is remembered per project in <project>/.kast/editor.json ({"buildFolder": "..."}), never in project.kast. Errors go to the Console and an Error popup.

If startScene is not set, outside the project or doesn't load, Build... and Build and Run log why and open Build Settings instead (after the unsaved-changes prompt, before any folder dialog); saving there doesn't resume the build, run it again. Headless --build fails instead (exit 1), its error pointing at Build > Build Settings.

Before writing anything, Build checks that startScene is set, inside the project and loads, that the Online Services settings pass the modal's checks (nothing extra while disabled), that the output folder isn't the project folder itself, and that kast_player.exe and its DLLs are next to the editor. Then it writes, into the output folder (created if needed, overwriting only these files):

<Name>.exe   copy of kast_player.exe
game.pak     the project's files
SDL3.dll     runtime DLLs kast_player.exe imports, directly or through RmlUi (dumpbin /dependents)
lua51.dll
rmlui.dll    game GUI, with FreeType and its libraries: freetype.dll, zlib1.dll, bz2.dll, libpng16.dll,
             brotlidec.dll, brotlicommon.dll (a debug build: freetyped.dll, zlibd1.dll, bz2d.dll, libpng16d.dll)

<Name> is the project name with each of < > : " / \ | ? * and control characters replaced by _, surrounding spaces and trailing dots removed, _ appended to a reserved device name (CON, NUL, COM1, ...) and Game if nothing is left: Switch Test -> Switch Test.exe, My: Game? -> My_ Game_.exe.

game.pak holds every file under the project folder except dotfiles, anything in a dot-directory (.kast/, .git/) and the output folder if it is inside the project. It is uncompressed: a KPAK magic and format version, an index of (project-relative / path, offset, size) entries, then the raw bytes. The exact byte layout is in engine/pak.h. The player checks the magic, the version and that every entry lies inside the file.

The game (kast_player.exe under its new name) opens the game.pak next to it, loads project.kast and its Lua components from it, titles its window with the project name and plays startScene as editor Play mode does (C++ systems, Lua systems, Lua components, kast.loadScene), rendering through the scene's Main Camera. It has no console window and doesn't hot reload. Its scene's game GUIs show over the scene and take mouse and keyboard input. Flags (for tests): --frames N and --screenshot out.png, as in the editor, --gui-click <id> (click that GUI element on frame 10), --sim-key frame,key (repeatable: push a press of that SDL key on that frame, e.g. 30,F3 for the stats overlay), --size WxH (window size, default 1280x720), --window-pos X,Y (window position, as in the editor; also KAST_WINDOW_POS), --no-audio-device (silent null audio backend), --gpu-stats (log the average GPU time of the frame's views, after 10 warmup frames, on exit), and --no-instancing and --no-culling (turn off instancing and culling, as in the editor). A missing or corrupt game.pak, an invalid project.kast, Online Services enabled with a CA file missing from game.pak or not a valid certificate, or a startScene that is missing or doesn't load shows an error message box and exits 1; with --frames the message is only logged (stdout), so tests never block.

Ship from a release build: a debug build copies the debug player, which needs Visual Studio's debug runtime. Players need the Microsoft Visual C++ Redistributable (x64); Build doesn't copy it.
