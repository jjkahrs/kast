Shaders in the editor

A user shader (.kshader) changes how the meshes of a material are drawn: their color per pixel, their shape per vertex, how lights shade them. This page is the workflow; the language, every built-in and the samples are in the engine's Shaders reference. You edit .kshader files in your own text editor; Kast compiles them in the background and shows the result live.

1. Create a shader

In the Assets panel, open the folder you want (e.g. shaders/) and choose Create > Shader. Kast writes new_shader.kshader (new_shader_2.kshader, ... if taken) and logs Created shader 'shaders/new_shader.kshader'. The starter compiles as is and is commented throughout: three params (a color, a ranged float and a texture), a fragment() that uses them, and a commented-out vertex() to start from.

Double-click a .kshader to open it in the external editor (the command is set in File > Preferences, as for Lua scripts). Renaming or moving it in the Assets panel updates every .mat that uses it.

2. Use it from a material

Select a .mat in the Assets panel. The Inspector's Shader section has a picker listing the project's .kshader files; None is the built-in shader. Every mesh using that material (a MeshRenderer's material, a ModelRenderer's materials) draws with the shader from then on. The material's other fields (base color, textures, alpha mode, cull mode, unlit, UV scale and offset) still apply: they are what the shader starts from. Under the picker the section shows:

  • the status: Compiling..., a green Compiled, or in red Compile failed: renders magenta (never compiled) / Compile failed: the last good version renders, followed by the full error with the line in your .kshader;
  • a red line if the material and shader don't fit together, e.g. Renders magenta: SCREEN_TEXTURE is only for blend and additive materials ... (set the material's alpha mode to blend);
  • one widget per param, in declaration order:
    ParamWidget
    float with range(min, max)slider over that range
    float without range, vec2, vec3, vec4drag fields
    colorcolor picker (linear values)
    texture2Dtexture picker of the project's images; Default (white) etc. is the declared default
  • values the material still holds for params the shader no longer declares, marked not a param of the shader (ignored).

A widget shows the material's value, else the param's default. Every edit saves the .mat at once and is an undo step (one per drag): Edit > Undo / Ctrl+Z and Redo with the Inspector focused restore and save the previous values. A param the material never set uses the .kshader's default, so changing that default changes every such material.

Selecting the .kshader itself shows its status and error, its params with their line numbers, and whether it has a vertex().

3. Edit, save, see it

  • Hot reload: every save of the .kshader recompiles it in the background; the Scene and Game views show the new version typically within a quarter of a second, while the editor keeps running at full speed. The log says Recompiled shader 'shaders/x.kshader' in 0.14 s.
  • Mistakes are safe: if a save doesn't compile, the last good version keeps rendering, and the error (with your file's line number) appears in the Inspector and the log (...; the last good version keeps rendering). Fix and save again. A shader that has never compiled renders magenta instead.
  • Animated shaders (TIME) move in the Scene view in edit mode as well as in Play.
  • Fast restarts: compiled shaders are cached in <project>/.kast/shader_cache/, so reopening the project doesn't recompile unchanged files (Compiled shader '...' (cache hit)). Delete the folder to clear it; it never ships.

4. Drive it from Lua in Play

Scripts set params per entity, as they set material fields: kast.setMaterialProperty(entity, "threshold", 0.5), kast.getMaterialProperty(entity, "threshold"). The entity gets its own copy of the material, so others using the same .mat don't change; Stop discards the copies and the .mat file is never touched. See the Lua details and the dissolve sample's scripts/dissolve_driver.lua.

5. Build

Build compiles every .kshader that ships into game.pak and fails, naming the file and line, if one doesn't compile or a shipped material misuses one. The built game never compiles shaders. Keep unfinished shaders in a dot-folder such as .wip/ to leave them out.

Try it

Open tests/project and its custom_shaders.scene: scrolling emissive lines, wind-swept grass and a character, a dissolving sphere, water with refraction and foam, and toon shading. Press Play to watch the sphere dissolve and re-form. Select materials/shader_water.mat and drag its params, or open shaders/toon.kshader, change bands to 2.0 and save.

For tests and screenshots without a mouse the same actions have flags: --assets-create shader:<folder>, --material-set <field>=<json>, --material-undo N, --material-redo N (see Command line).
