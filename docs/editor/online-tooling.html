Editor tooling

Window > Online (editor/online.h is the model, no ImGui; editor/online_panel.h draws it) lets you run and test the backend from the editor. For a project with Online Services disabled it only says "Online Services disabled for this project", with a button opening Build > Online Services.... Otherwise it has five sections:

  • Status: auth's GET /health (ok, database down on a 503 db_unavailable, or unreachable; hover for why) and, while logged in, the realm list (name, host:port, region, status) with each realm's world server checked by a TLS connect (reachable, TLS certificate not trusted when the project's CA file doesn't cover it, or unreachable). Refresh checks at once; while the panel is shown it also checks every 10 s. Every check is asynchronous: the editor never waits on the network.
  • Local services (docker compose): Start (docker compose up -d --build), Stop (docker compose down, never -v: the databases survive) and Status (docker compose ps, shown as a service / state / health table) in the compose folder. They run in the background; their output streams to the Console line by line, and Start and Stop end with Status and a status refresh. Disabled, with the reason, when docker is not on PATH or the folder is unset, missing or has no docker-compose.yml. The folder is File > Preferences > Local services compose folder; by default services/world of the Kast source tree the editor was built from, if it is there (an editor copied elsewhere starts with none).
  • Test login: email and password; Log in shows the account's email and role, Log out ends the session (and revokes it on the server). While logged in, Play starts logged in as that account: kast.auth adopts the session before the first update and Lua gets auth.session {accountId, email, role}. Not logged in, Play starts logged out as before. Refresh tokens rotate (reusing one ends the session), so the session is handed to Play, not shared: the editor stops refreshing it during Play and takes it back at Stop, refreshed or not; if the game logged out during Play, the editor is logged out too. Errors (invalid_credentials, account_locked, ...) show under the button.
  • World server override (Editor Play only): a host:port every realm connects to in editor Play (kast.world), e.g. a world server on your machine. Built games ignore it; --world-address wins over it.
  • Admin, only for an admin login: the realms with Edit / Delete and New realm... (name, host, port, region, status, sort order); Ban (account id, reason, optional ISO 8601 expiry), Unban and Set role (player / gm / admin). Delete, Ban and Set role ask first. The service's error code and message show inline (realm_name_taken, cannot_modify_self, validation_error, ...). Accounts are picked by id: the auth service has no account search or listing. The admin calls are editor code only; they never ship in the player.

Secrets: the password field is wiped when you press Log in, and tokens live in editor memory only. The per-user editor settings (%APPDATA%/Kast/Editor/editor_settings.json, also holding the external editor command) remember the email (onlineEmail), compose folder (composeFolder) and override (worldOverride), never a password or token; nothing goes into project.kast or game.pak, and nothing logs a password or token.

Seeding an admin: the compose stack creates no admin account unless SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD are set in services/world/.env (see Auth Server configuration). Otherwise register an account (e.g. with the kast.auth sample), verify it through Mailpit (http://localhost:8026) and promote it in a MySQL shell (docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' in services/world): UPDATE accounts SET role='admin' WHERE email='you@example.com';, then log in again.

Sample: tests/project/online_session.scene (scripts/online_session_demo.lua) logs auth.session and whether Play started logged in.
