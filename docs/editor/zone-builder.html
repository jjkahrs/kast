Zone Builder

The editor's Zone tab and the Scene view create and edit a project's zone maps (maps/<folder>/, see Maps and Terrain) in 3D and save them in place, in the formats the engine and the world server load. The zone logic is the kast_zone library (engine/zone/); the tab and the Scene view tools are editor code (editor/zone_*).

A zone is the scene's Terrain map

The zone is the map whose id is in the open scene's first entity with a Terrain component (the same rule Play's terrain streaming follows). Picking another map or creating a New Map in the Zone tab sets that Terrain.map (and marks the scene unsaved); editing Terrain.map in the Inspector opens that map instead. One zone is open at a time.

  • No project: the tab says a project is required (maps live in the project's maps/ folder).
  • No Terrain entity: the tab says so and offers Add Terrain entity (created, selected, scene marked unsaved); picking or creating a map adds one too.
  • Several Terrain entities: the first one is used, and a note names it.
  • Map not found or broken: a Terrain.map id no project map has, or a map that fails to load, shows the error in the tab (and once in the Console); nothing of the zone is drawn.

One scene per zone. A zone's scene is the one whose Terrain entity names that map: open it to edit the zone in the Zone tab. It holds that zone's own client content (props such as its portal arch) and instances of the prefabs every zone shares (player, camera, replication, NPC templates, in-world GUI), so a change to a shared prefab reaches every zone. At run time the game loads the zone's scene when the player enters the world or a portal moves it to another map (a world.entered / world.mapChanged subscriber calling kast.loadScene; replication carries the player and what is in view across). samples/starter-mmo: scenes/meadow.scene is the Meadow (map 10), scenes/cavern.scene the Cavern (map 11), and scripts/world_flow.lua holds the map-to-scene table.

Scene view

In edit mode the Scene view draws every declared tile of the zone with the map's material (and the generated terrain texture, if any), plus every zone object as its prefab, from the zone's in-memory state: edits show straight away. The camera's near and far planes widen while a zone is shown, for 2 km maps. Overlays: tile borders, the player spawn (with its heading), areas (portals in blue, the selected one with corner handles), spawns (with heading), patrol paths, zone objects (a dot each; obstacles' and interactables' shapes outlined on the ground) and the brush ring. They are drawn over the terrain, not hidden by hills.

Play does not use the in-memory zone: as before, the terrain streams around the player by Terrain.radius from the saved map files. Starting Play with unsaved zone edits logs a Console warning saying so.

Input. The editor camera keeps its controls (Editor controls: right drag flies, Alt + left drag orbits, middle drag pans, the wheel zooms).

  • With a zone tool active (Raise, Lower, Flatten, Area Rect, Area Polygon, Place Spawn, Path Points, Place on terrain, Place Object, Scatter), left mouse in the Scene view goes to that tool: it never selects an entity or moves the gizmo. Esc first cancels an area being drawn, then clears the tool. Clicking an active tool's button turns it off.
  • With no zone tool, left click selects entities and the gizmo works as usual, except that while the Zone tab is the front tab the zone's handles (area vertices, spawns, path points, object dots) take priority when hit: click to select, drag to move (snapped to the ground, one undo step per drag).
  • Any left click on the terrain also picks the tile the Heightmap import/export works on.

The tab sits beside Hierarchy in the left dock (also added there on the first run with an older imgui.ini). Objects

Zone objects are prefabs placed on the map's tiles (formats: World Server, Maps, Objects; in game: Engine, Terrain). The project's .prefab files are listed in the Objects section.

  • Types: Visual (grass, flowers: client only, blocks nothing), Obstacle (rocks, walls, trees: blocks players and NPCs; the server knows only its shape) and Interactable (blocks like an obstacle, and a player can activate it; the server publishes its event).
  • Place Object: pick the prefab and the type, then click the terrain: the object stands on the ground there (y snapped), yaw 0, scale 1. A new obstacle or interactable gets a 1 m box shape; a new interactable gets the next free id on the map and a server entry (range 3, event <prefab name>.activated).
  • Select and move: with no tool and the Zone tab in front, click an object's dot to select it (or pick it in the list) and drag to move it on the ground. Moving one into another tile moves it to that tile's file, an interactable's server entry with it.
  • Fields: type (an interactable turned obstacle loses its id and server entry; a visual keeps an old shape unused), prefab, position (x, z; y follows the ground), yaw (degrees here, radians in the file), scale (the prefab only), shape (Box half extents, turned by yaw, or Cylinder radius and height, in metres, standing on the object). An interactable also has its id (unique on the map: a used one is not taken), name, and the server-only range, event and data (a JSON object, checked as you type: text that isn't one shows the problem and keeps the last valid data; empty removes it). The server entry's pos, yaw, shape and name always follow the object.
  • Overlays: a dot per object (green visuals, orange obstacles, blue interactables with #id name, the selection in yellow) and each shape's outline on the ground (16 points for a cylinder). The Scene view draws each object's prefab, scaled and turned; a tile's objects are rebuilt when they change.
  • Scatter (visuals only): tick prefabs (one is picked at random per object), set the radius, how many per dab, random yaw or not, the scale range and the seed. Drag on the terrain: a dab on mouse down and another each time the brush has moved its radius, each placing that many visuals at random points of the circle, on the ground (points off the map are skipped). The whole stroke is one undo step. Erase visuals turns the brush into an eraser that removes every visual inside the circle (obstacles and interactables stay). The random numbers come from the seed (xorshift32, the same on every machine): changing the seed or pressing Restart starts its sequence again, so the same seed and strokes give the same objects.
  • Save writes each changed tile's objects/ and .server/interactables/ file and deletes a tile's files once it has none. Unknown keys in the files are kept. Re-bake the navmesh (Bake) after placing, moving or removing an obstacle or interactable.

Generated terrain

Generate heights (Terrain section) replaces the heights of every declared tile with fBm Perlin noise: Seed (or Randomize), Scale (metres per noise feature, default 256), Octaves (5), Persistence (the amplitude ratio between octaves, 0.5) and Lacunarity (the frequency ratio, 2). The noise is sampled at each sample's map position, so tiles sharing an edge get the same samples (no seams, whatever the tile layout), and it is stretched over the whole height range: the lowest sample is the range's min, the highest its max. The same seed and settings on the same tiles give the same heights. The player spawn moves up or down onto the new ground. One Generate heights is one undo step.

Height colors is a gradient over the height range: stops at a position (0 % = the range's min, 100 % = its max) with a color. Between two stops the color blends linearly; below the lowest and above the highest it is that stop's. Add stop, Remove (at least 2 stay), drag a position or pick a color; each change is one undo step. The default is sand, grass, rock, snow. It is kept in map.json as "terrainColors" (see Terrain).

Create texture & material (Terrain section) sets the map's material to materials/<folder>_terrain.mat, "terrainUv": "map" (one texture over the whole map) and the default colors if the map has none, as one undo step. The Scene view shows the result straight away; nothing is written until you save. Then every save writes:

File Content
textures/<folder>_terrain.png 8-bit RGB, the color of the ground at each pixel: 1 px per metre over the bounding box of the declared tiles (256 px per tile), shrunk to fit 4096 px on the longest side; grey where no tile is. Row 0 is the box's min z
materials/<folder>_terrain.mat white base color times that texture, metallic 0, roughness 0.9

Both are re-baked on every save of the map, so the texture follows sculpting and color edits. These two paths are the only files a zone save writes outside maps/: other materials and textures are never touched, and if one of them already exists before the map has been saved using it (someone else's file), the save is blocked with a problem on that file. Picking another material in the Map section keeps it; the generated files are then no longer written.

Saving, undo and Play

Save Zone (the tab), and File > Save / Ctrl+S (the scene, then the zone if it has unsaved edits), first check the map as the world server would load it: kast_map's parse_manifest, parse_areas and parse_spawns for every tile's file, spawn ids unique on the map, spawn files on declared tiles, the map id unused by the project's other maps, portals to an existing map, onto its tiles and not into a portal there, valid terrainColors, no foreign file at the generated terrain texture or material path, every objects file (parse_objects: any bad entry) and interactables file (parse_interactables) on a declared tile, interactable ids unique on the map, and each interactable object with a server entry of the same id in its tile's file (and each entry with an object). Any problem: nothing of the zone is written, the tab comes to the front with Problems listing them all (file and message, as the server reports them), and the Console repeats them; the scene itself still saves. Only files that changed are written; a map opened and saved unchanged keeps every byte.

Undo / Redo (the tab's buttons, and Edit > Undo / Redo, Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z while the Zone tab has focus) cover every zone edit, and a brush or scatter stroke, a drag or one field edit is one step. The map has its own history, apart from the scene's: see Undo and redo.

Unsaved changes. The editor's Save / Don't Save / Cancel prompt (New, Open, Open Recent, switching project, quitting) counts unsaved zone edits too, and so does changing the map in the Zone tab or the Inspector (Don't Save reloads the zone from disk).

Read-only. During Play and in prefab edit mode the tab is read-only (tools off, no zone overlays in the Scene view); a note at the top says why.

Command line

kast_editor runs the same edits from the command line (tests and scripts), e.g.:

build\debug\kast_editor.exe --project samples\starter-mmo --map meadow ^
  --scatter 128,128,40,200,7,0.8,1.4,prefabs/grass.prefab --add-object obstacle,prefabs/rock.prefab,141,108,0.3,1,cylinder,1.2,1.4 ^
  --save-zone --headless
build\debug\kast_editor.exe --project samples\starter-mmo --new-map dunes,2,2 --generate-heights 7 ^
  --terrain-colors 0,0.76,0.7,0.5,40,0.33,0.52,0.21,100,0.95,0.95,0.97 --create-terrain-material --save-zone --headless
