Projects

A project is a directory marked by a project.kast file (exactly that name):

{
  "version": 1,
  "name": "My Game",
  "startScene": "scenes/start.scene",
  "stateMachines": ["game_flow"],
  "audio": {"Music": {"volume": 0.6, "muted": false}},
  "online": {"enabled": true, "authUrl": "https://auth.example.com", "caFile": "certs/dev_ca.pem"}
}
  • version must be 1, name a non-empty string, startScene a project-relative path or null (only its type is checked; opening the project opens it, and a built game starts there, see Build). These three keys are required.
  • stateMachines (optional): the game state machines every Play session runs, as definition names; an array of unique non-empty strings. A name without a valid definition is an error at Play start, not here. The State Machines panel's Global checkbox edits it.
  • audio (optional): the default bus levels applied at Play start, {"<bus>": {"volume": 0..1, "muted": bool}}; a missing bus or key is 1.0 / unmuted. The Mixer panel edits it. Written (every bus) only when some bus is not at 1.0 unmuted.

  • online (optional): the project's opt-in to Online Services, the built-in integration with the repo's auth and world servers (services/); while enabled, Lua gets kast.auth (later engine features check it too). A missing block (every older project) means disabled. Keys, all optional:

    • enabled (bool, default false).
    • authUrl: the auth service's http:// or https:// base URL. Required while enabled; checked whenever set. World server addresses are not configured here: they come from the auth service's realm list.
    • caFile: a project-relative PEM file of extra trusted CA certificates (e.g. the world stack's self-signed dev certificate), trusted besides the Windows ROOT store for both auth HTTPS and world TLS. It ships in game.pak like every project file, so it must not be in a dot-folder.

    Loading checks the shape, the URL and that caFile is a path inside the project; that the file exists and holds a valid certificate is checked by the Online Services modal's Save, by Build and when the built game starts (only while enabled), so a deleted CA file never stops the project from opening. Written only when some key differs from the defaults, so disabling keeps the URL and CA file. Older editors reject the online key; projects that never set it stay readable by them. Never put secrets (tokens, passwords, admin credentials) here: it ships in game.pak.

  • Unknown keys are rejected. Saved with 2-space indent in this key order; stateMachines is written only if the file had it or a machine was made Global (unchecking the last one leaves []), so other projects keep identical bytes.

  • Active project: opening a scene (File > Open, --scene) activates the project found by walking up from the scene's directory (the nearest ancestor-or-self with a project.kast; none = no project; an invalid one is warned about and treated as none). New (Untitled) keeps the current project. Save / Save As re-run the walk-up from the saved file. --project (how the Project Manager opens a project) sets it directly.
  • Project-relative paths (systems, kast.loadScene, startScene) use / separators and must stay inside the project: absolute paths and .. out of the root are rejected.
  • Without an active project the scene can still be edited and played (C++ systems run), but every Lua system is disabled with a "no project" error.
