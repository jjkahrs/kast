Assets and asset ids

The Assets panel lists the files of the open project. Every asset file has a stable asset id kept in a .meta file beside it, and every reference to an asset in a project file stores that id next to the asset's path. Renaming or moving an asset (in the editor, or in Explorer together with its .meta) therefore never breaks a reference, in any project file, opened or not. Ids are an editor and project-file concept only: the engine, the built game, game.pak and Lua keep loading assets by path (Asset references).

.meta files

models/knight.glb has its id in models/knight.glb.meta:

{
  "id": "3f0c2a9e-5b1d-4c7a-9e2f-8a6b4d1c0e57"
}
  • The id is a lowercase UUID (version 4), made when the file first gets its .meta.
  • Only files have one. Folders, dot-entries (.kast/, .server/, .env), project.kast, the Build output folder, .tmp files and the .meta files themselves have none.
  • The editor creates the missing ones whenever it scans the project: on project open, after every Assets panel operation and every half second while it runs. Opening an older project without .meta files is the migration; the Console logs Created N asset id file(s) (.meta).
  • .meta files are hidden in the Assets panel and in every asset picker, and never ship in game.pak.
  • Commit them to version control with their assets: a clone without them gets new ids, and its references fall back to their paths.

Editor operations

Every Assets panel operation carries the .meta with its file:

  • Rename and Move (drag onto a folder) move the .meta too; a .rml or GUI prefab rename moves its linked .rcss and that file's .meta. If a step fails, the files and their .meta files are put back.
  • Delete sends the file and its .meta to the Recycle Bin.
  • Created files (materials, shaders, shader graphs, GUIs, prefabs, Lua from templates) get their .meta at once.
  • A file can't be named *.meta.

After a rename or move, one pass rewrites the path hint of every reference to the moved asset (or to anything inside a moved folder) in every project file that holds references, opened or not: scenes, prefabs, materials, project.kast (startScene), maps (map.json, objects/*.json), .rml and GUI prefabs. The Console logs Updated asset references in '<file>' for each file it changed. What is open follows in memory as well: the open scene (its own path too), the prefab being edited, the GUI Builder, Shader Graph, Model Preview and the open zone, so a later save writes no stale path.

Lua string paths ("models/x.glb" in a script) are not tracked: rename those by hand.

Renaming and moving in Explorer

Close the editor or not; the next scan sorts it out:

  • File and its .meta together (the recommended way): the id moves with the file and every reference resolves by id. A document opened with an out-of-date path hint is marked changed, so its next save writes the current path; project.kast is saved at once when its startScene hint is out of date.
  • Only the file: its old .meta is left behind as an orphan. If that folder holds exactly one orphan .meta and exactly one file without a .meta with the same extension, the file takes the orphan's id (the .meta is renamed; logged '<new>' took the asset id of missing '<old>' (its .meta was left behind)). Anything more ambiguous (two renamed files of one type in one folder, a move to another folder) is not paired: the file gets a new id and its references fall back to their paths.
  • Leftover orphans (a .meta whose file is gone and that nothing adopted) go to the Recycle Bin, logged Moved orphan '<file>.meta' to the Recycle Bin: '<file>' is gone.
  • Copies (a file copied with its .meta): files sharing an id keep it only for the oldest one (the newer of creation and modification time; on a tie the first path A-Z). Each other file gets a new id, with a warning naming both files.
  • A .meta that holds no valid id is replaced, with a warning.

References in the editor

  • A reference resolves by id first; if the id is unknown it uses its path hint.
  • When neither the id nor the path exists, the reference is missing: it is kept exactly as written (never dropped or rewritten, also on save), the Inspector shows (missing) <path>, and the Console logs once per load Missing asset '<path>' (id <id>): no file has that id or path; the reference is kept.
  • On save, every string value that exactly names an asset of the project becomes a reference with its id. Files written by older versions (plain path strings) load as they are and are upgraded by their next save.
  • Build re-resolves every reference in the shipped copies of scenes, prefabs, materials, GUI files, maps and project.kast, so game.pak always has the current paths, even for files not saved since a rename in Explorer (logged Shipping '<file>' with its asset references' current paths). The source files are not changed.

Command line

--assets-rename <path>=<name> renames that project-relative Assets entry to a new name at frame 10, as the panel's Rename does (its .meta and the rename pass included), for tests:

kast_editor --project tests/project --scene tests/project/scene_a.scene --assets-rename models/cube.gltf=cube_renamed.gltf --frames 20

The test asset_ids_rename (cmake/asset_ids_test.cmake) runs the whole cycle on a copy of tests/legacy_project, the legacy fixture (plain path strings, no .meta files): it opens, builds and plays, its saves upgrade the references, Assets renames rewrite the unopened scenes and project.kast, and an Explorer rename with the .meta ships fresh paths in game.pak.
