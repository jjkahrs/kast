Undo and redo

Every in-memory edit in the Scene (and a prefab in prefab edit mode), the GUI Builder and the Zone builder can be undone and redone. Each document keeps its own history of steps; a step is one user gesture with a name ("Move Cube", "Delete Panel", "Edit Terrain"). Nothing on disk is ever undone: file writes, asset create / rename / delete, project and build changes are not steps.

Menu and shortcuts

InputAction
Edit > Undo <step>, Ctrl+ZUndo the last step of the focused panel's document.
Edit > Redo <step>, Ctrl+Y, Ctrl+Shift+ZRedo the step last undone.

The menu items name the step they act on and are greyed (just "Undo" / "Redo") when there is none or undo is blocked. The shortcuts are ignored while a text field is being edited (its own text undo wins), while a drag or the gizmo is in progress, and while a modal dialog is open. Each undo / redo logs Undo <step> / Redo <step> in the Console.

Which document: the focused panel

  • Scene: Scene view, Hierarchy, Inspector, Lighting, Post Processing, Physics and every other panel not listed below (menus keep the panel focused before them). In prefab edit mode these act on the open prefab instead.
  • GUI Builder: GUI Hierarchy, GUI Inspector, GUI Style and GUI Preview act on the open GUI.
  • Zone: the Zone tab acts on the open zone map (a sculpt in the Scene view is the zone's step, undone from the Zone tab).

The histories are independent: undo in the GUI Builder never touches the scene, a zone undo never touches the scene or a GUI, and so on.

What is undoable

Scene and prefab edit mode

  • Create object, model or prefab instance (drop), delete, duplicate.
  • Rename, reparent and reorder in the Hierarchy.
  • Every Inspector field, component add / remove, Lua system add / remove / move.
  • Gizmo move / rotate / scale.
  • Lighting, Post Processing and Physics panel settings.
  • Prefab Revert and Unpack (scene only, no file written).

GUI Builder

  • Add, delete, move and reparent elements.
  • Inspector edits of id, class, text and data-event.
  • Style (.rcss) text edits.

Zone builder

Every edit that marks the zone unsaved: terrain sculpt / flatten strokes, height range, heightmap import and generation, terrain colors, tiles added / removed, the map's fields and spawn point, areas and their vertices and portals, spawns and their paths, objects placed / moved / deleted / edited and scatter / erase strokes. A step holds only the parts of the map the edit changed (the tiles a stroke touched, the areas file, a tile's objects), as they were before and after. Steps are named for what changed: Edit Terrain, Edit Map, Edit Areas, Edit Spawns, Edit Objects. The tab's own Undo / Redo buttons use the same history.

One step per gesture

A gizmo drag, a slider or drag-number drag, a text field from activation to commit, a brush, scatter or erase stroke and a handle drag in the Scene view are each one step. An edit that changes nothing (a field typed and restored, a click that moves nothing) records no step, and leaves the unsaved mark as it was.

History rules

  • Cap: 100 steps per document; the 101st drops the oldest.
  • Redo branch: a new edit after an undo discards the steps that could have been redone.
  • Save point: undoing or redoing back to the state that was last saved clears the unsaved * in the title (the Zone tab's * unsaved for a map); moving away sets it again. A saved state that was discarded from the redo branch or dropped by the cap is out of reach: the document stays unsaved.
  • Selection follows undo / redo: the entity (by its id) or GUI element the step affected is selected again; if it no longer exists the selection is cleared.

What clears a history

  • Scene: New, Open, and the operations that write files and change the scene: Create Prefab, prefab Apply, asset rename / move that rewrites the scene's paths, New Lua Component, a Lua component hot reload that migrates fields, and a prefab refresh (for a scene with prefab instances).
  • Prefab edit mode: opening a prefab gives it a fresh history and the scene's waits behind it; switching to another prefab drops the prefab's; Back drops it and the scene's history returns. Apply in prefab mode also clears the waiting scene's history if it has instances.
  • GUI Builder: opening another GUI, reloading it from disk, or closing it.
  • Zone: opening another map or creating a New Map (each map loads with an empty history).

Play mode

During Play and Pause, Undo and Redo are greyed and the shortcuts do nothing; edits made while playing are never recorded. Stop restores the scene as it was before Play, so the history is intact and usable after Stop. The Zone tab is read-only during Play and in prefab edit mode, and its undo is blocked then too.
