GUI Builder

Four editor panels on one open GUI. Assets > Create > GUI writes new_gui.rml + new_gui.rcss (a Panel holding a Text and a Button with data-event="ui.clicked", the .rml linking the .rcss) into the chosen folder, as new_gui_2, new_gui_3, ... when a name is taken (ignoring case), never overwriting, and starts renaming the .rml. Renaming an .rml in Assets also renames the sibling <stem>.rcss it links and rewrites the link (refused, nothing changed, if either new name is taken); moves and renames of the open files are followed. Double-click an .rml in Assets to open it (one GUI at a time; with unsaved builder changes, Save / Discard / Cancel first); its four panels come to the front.

  • GUI Hierarchy (tab beside Hierarchy): the elements under Body. + Panel / + Text / + Rich Text / + Button and the form widgets + Toggle / + Slider / + Dropdown / + Spinbox / + Progress and the lists + List Box / + Virtual List add into the selected Panel, else into Body (the buttons wrap to the panel's width); Delete, Up, Down act on the selection; the right-click menu has the same (Add Toggle, ...). Drag an element onto a Panel or Body to move it there (into itself or its own children is refused). Unknown elements are greyed and labelled <tag>.
  • GUI Inspector (tab beside Inspector): the selection's id and class, its text (Text and Button holding only text; one with child elements says so), a Rich Text's markup, toolbar and warnings, data-event for a Button, the input widgets and the lists, and a widget's properties and options or a list's properties and rows. Then, on any element (Unknown ones too), Data binding: one field per RmlUi binding attribute it has (data-model, data-for, data-if, data-visible, data-value, data-checked, data-rml, data-text, data-attr-*, data-attrif-*, data-class-*, data-style-*, data-event-*, data-alias-*); emptying one removes it from the file. Type a binding attribute's name and press Add binding for a new one (written once it has a value). Other attributes are listed read-only; Unknown elements' are. Edits apply as you type; each field edit is one undo step (Edit > Undo / Redo while a builder panel is focused) and is saved with Save.
  • GUI Style (tab beside Console): the .rcss text, applied to the preview 0.3 s after the last keystroke. A sheet RmlUi reports problems for (in the Console) is not applied: the preview keeps the last good style and the panel says so in red.
  • GUI Preview (tab beside Scene and Game): the document as RmlUi renders it at 1280x720, 1920x1080 or the Panel size, scaled to fit. Click selects the deepest element under the cursor (Body if none); the selection has a yellow outline, drawn by the editor, never saved. A document with data-model previews as authored, with no live data: its models are created empty (no RmlUi warning), so data-for rows don't show and {{...}} is empty; select a row template in the GUI Hierarchy. A Virtual List is the exception: it shows 20 placeholder rows made from its template (see Lists).

Rich Text

+ Rich Text adds <p class="rich">[b]Rich[/b] text</p>: a paragraph whose text is BBCode, converted to styled RML in the preview, in Play and in the built game. Any <p> with class rich (among others too) is Rich Text; a plain <p> stays Text, its text shown as typed. The markup is saved verbatim (line breaks included; the file escapes only & < >), so it round-trips.

  • markup: a multiline field (Enter makes a line break). Like the other fields, one edit is one undo step from activation to letting go, and the preview follows as you type.
  • Toolbar under it: B, I, U, S wrap the field's selection in [b]...[/b], [i], [u], [s], or put an empty pair at the cursor when nothing is selected. Color (a colour picker), Size (pixels, 4..200), Font (a family name, Roboto or a project font from fonts/) and Link (a target) ask for their value in a popup, then Apply wraps the same way ([color=#ffaa00]...[/color]). Image asks for a path (relative to the .rml) and an optional width / height (0: automatic) and inserts [img=path w=N h=N] at the selection's start. Each button is one undo step (Rich Text [b], ...). The selection used is the field's last one, so select text, then click.
  • Warnings under the toolbar list what the converter reports, with its byte offset in the markup: unknown tags, bad values, closing tags that close nothing, unclosed tags, mis-nesting and a font family that isn't loaded. Play shows those as documented (literal text, closed at the end, reopened); Markup OK when there are none.

The preview loads the project's fonts/ and resolves [img] paths next to the .rml. Clicking rich text in the preview selects the paragraph. --gui-add RichText and --gui-rich-wrap b,0,7 (the toolbar's edit on bytes 0..7 of the selection's markup) do the same from the command line.

Form widgets

Elements are recognised by their markup (Game GUI: Form widgets), so hand-written controls are editable too: an <input type="range"> is a Slider, a <select> a Dropdown, an <input type="checkbox"> with class toggle a Toggle (a plain checkbox stays Unknown), a <progress> a Progress, and a <div class="spinbox"> holding exactly a button, an input and a button a Spinbox (otherwise it is a Panel). A Dropdown, a Spinbox and a Toggle inside its <label> are one node in the tree: their insides are not listed, a click on them in the preview selects the widget, and the Inspector edits them. The preview draws them with the engine's default widget style under the GUI's own sheet, as Play does.

Kind Added as Inspector fields
Toggle <label><input type="checkbox" class="toggle"/>Toggle</label> checked (a checkbox: checked="" on the input), label (the label's text; only for a labelled toggle). id, class, data-event and bindings are the input's.
Slider <input type="range" min="0" max="100" step="1" value="50"/> min, max, step, value
Dropdown <select> with options option1..option3, the first selected Options: one row each with the selected radio button, its value and label fields, up / down and X (remove); Add option appends optionN / "Option N".
Spinbox <div class="spinbox" data-min="0" data-max="10" data-step="1"> with -, <input type="text" value="0"/>, + min, max, step (the div's data-min, data-max, data-step), value and data-value (its input's: the starting value and the two-way binding)
Progress <progress value="0.5" max="1"/> value, max

A text field edit is one undo step from activation to letting go, a checkbox click or option button one step each; all mark the GUI dirty, update the preview at once and are written by Save. Emptying a min / max / step / value field removes that attribute. The attributes the fields stand for are not repeated under "Other attributes"; every other attribute and child is kept as written. --gui-add Toggle (or any kind) and --gui-set-prop name=value do the same from the command line.

Selection is shared by the three. Any edit marks the GUI dirty: * after the file name in the builder panels' titles. Save (GUI Hierarchy, GUI Style) or Ctrl+S while a builder panel is focused writes the .rml and .rcss (elsewhere Ctrl+S still saves the scene). Quitting with unsaved builder changes asks Save / Discard / Cancel first, then the scene's own prompt if it is dirty. When the open files change on disk (the 0.5 s poll), a clean builder reloads them (keeping the selection by id and, if the new sheet is broken, the last good style); with unsaved changes it asks Reload / Keep mine. A deleted .rml closes a clean builder.

Lists

A <div class="listbox"> is a List Box, and a <div class="virtuallist"> holding exactly one element that has a data-for (its row template) a Virtual List (any other virtuallist is a Panel); see Game GUI: Lists. Each is one node in the tree (its rows aren't listed; a click on a row in the preview selects the list), drawn with the default style in the preview.

Kind Added as Inspector fields
List Box <div class="listbox"> with rows <div class="row" data-value="row1">Row 1</div> .. row3, none selected data-event, follow (a checkbox: data-follow=""), Rows: one line per row (children with class row) with the selected radio button (class="row selected"; clicking the selected one selects none), its value (data-value; empty: removed, the row's value is then its index) and label (its text) fields, up / down and X; Add row appends rowN / "Row N". A data-for row template is listed too (its label is its {{...}} text); its bindings are kept and edited in the .rml.
Virtual List <div class="virtuallist" data-model="list" data-row-height="24"><div class="row" data-for="item : items">{{item.name}}</div></div> data-event, model (its own data-model; empty when an ancestor's is used), source (the array its template's data-for names; the item alias is kept), key (data-key), row-height (data-row-height), follow, and template: the row template's text with its bindings ({{item.name}} x{{item.count}}; only for a template holding just text). Other bindings of the template are kept and edited in the .rml.

The preview shows a Virtual List with 20 placeholder rows made from its template at its row height, each {{a.b}} read as b <n> (name 1, name 2, ...); the file is unchanged. Edits are undo steps, mark the GUI dirty, update the preview at once and are saved, as for the form widgets; --gui-add ListBox / VirtualList and --gui-set-prop row-height=30 (or follow=true, source=loot, ...) do the same from the command line.

GUI prefabs

A GUI prefab is a reusable element subtree saved as a .guiprefab file (one element, children allowed), with an optional sibling .rcss holding its styles. GUIs place linked instances of it: editing the prefab updates every instance, and each instance can override attributes and text of the prefab's elements. It is the GUI counterpart of scene prefabs. The file format, the markup and the runtime side are in Game GUI: GUI prefabs. Prefabs need a project; paths are project paths.

Creating a prefab

  • Drag an element from the GUI Hierarchy onto the Assets panel's background (the project root) or onto a folder, or right-click it > Create GUI Prefab (the Assets panel's current folder: the selected folder, else the selected file's folder, else the root).
  • It writes <id>.guiprefab (an element without an id: its kind, panel.guiprefab), _2, _3, ... if that name or its .rcss is taken; nothing is overwritten. The new .rcss holds only a comment: the element keeps the look the GUI's own sheet gives it there; move rules into the prefab's sheet for it to look the same everywhere.
  • The element becomes an instance with the same id. Ids inside it that started with <its id>_ are saved without that prefix, so the instance's ids stay as they were (card_title in #card is title in the prefab and card_title again in the instance); other ids gain the prefix.
  • One undo step: undo puts the original element back (the files stay). Refused (a GUI Prefab message, also in the Console) for an element that is, or is inside, an instance (unpack it first), and for a prefab that would hold itself (a missing-prefab placeholder inside it naming the new file).

Placing instances

  • Drag a .guiprefab from Assets onto the GUI Hierarchy: onto a Panel or Body it becomes their last child. Or onto the GUI Preview: into the deepest Panel under the cursor, else Body.
  • The instance gets the prefab's file stem as id, made unique in the document (prefab_button, prefab_button_2, ...: no element has it and no id starts with it plus _), and is selected. One undo step.
  • Refused if the prefab doesn't load, if the target is inside an instance, or if the prefab holds (directly or nested) the prefab being edited.

Instances in the builder

The GUI Hierarchy shows an instance as one node with the prefab marker (a small cube) after its label, its tooltip naming the prefab. Its prefab elements are listed under it and can be selected (in the tree or the preview) to override their attributes and text, but they can't be moved, deleted, dragged, reparented or receive children: Delete / Up / Down and the + buttons are disabled, their menus leave those items out, and the command-line equivalents are refused with a warning. The instance root itself moves, deletes and reparents like any element. A Dropdown's options and a List Box's rows in an instance can't be added, removed or reordered.

The GUI Inspector shows a Prefab card on any element of an instance: the prefab's path (and the nested prefab the element belongs to, if any), Select Root (on a prefab element), Open Prefab, and on the root Revert All, Apply All and Unpack. The instance root's id is the instance's: changing it renames the ids inside that start with the old id plus _; it is never an override and can't be emptied.

Overrides, Revert, Apply, Unpack

  • Any field of a prefab element (id, class, text, Rich Text markup, data-event, data bindings, widget properties) can be changed; the field is then overridden for this instance only, marked with a #ffcc00 bar at the Inspector's left edge. Overrides are worked out by comparing with the prefab when the GUI is saved, so a value changed back to the prefab's is no longer one.
  • Right-click a marked field: Revert (back to the prefab's value; one undo step) or Apply to X.guiprefab: writes the value into the prefab file at once (into the outermost prefab: a nested element's value becomes that prefab's override of its nested instance). As a scene prefab's Apply, Apply clears the GUI's undo history. Every instance in the open GUI follows; other GUIs pick it up when they load.
  • Revert All drops every override of the instance (one step). Apply All writes them all into the prefab (ids without the instance prefix).
  • Unpack replaces the instance with plain elements, ids as expanded, rendering exactly as before (one step). Instances nested in it stay linked, with what it changed on them as their own overrides.

Editing a prefab

Double-click a .guiprefab in Assets: it opens in the four GUI panels like an .rml (the same Save / Discard / Cancel prompts, undo and reload rules). Its one element is under Body (Body takes no second element and its element can't be deleted); GUI Style edits its sibling .rcss (Save creates it once it has text). The preview shows it alone, in Roboto white text unless its sheet says otherwise. Instances of other prefabs in it are edited as above; placing one that would hold this prefab is refused. Save rewrites the file. A GUI open in the builder that holds instances of a prefab refreshes them when the prefab changes on disk (the 0.5 s poll; unsaved edits are kept, the undo history is cleared), and Play reloads the documents that use it (hot reload).

Missing prefabs, renames

  • An instance whose prefab doesn't load (deleted, broken XML, not exactly one element, a cycle) is a red missing prefab <path> node; its card says so. The Console has a warning naming the GUI and the path. Saving keeps the reference and its overrides unchanged, so once the prefab is back the instance is too.
  • Renaming or moving a .guiprefab in Assets takes its .rcss along and rewrites the references to it in every .rml and .guiprefab of the project (as scene prefabs do) and in the open GUI.

Testing hooks: --gui-create-prefab, --gui-place-prefab, --gui-revert, --gui-apply, --gui-unpack, --gui-delete, --gui-move, --gui-reparent and --open-gui file.guiprefab (Command line); the gui_builder_prefab_* tests use them on the tests/project/ui/prefab_* fixtures, and kast_self_check --guiprefabs checks the document model.
