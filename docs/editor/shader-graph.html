Shader Graph

The Shader Graph builds a mesh surface shader from connected nodes, without writing code, like Unity's Shader Graph. A graph is a .kshadergraph file; Kast generates .kshader text from it, and everything after that is the .kshader path: a material uses a graph through its Shader picker, its params get the Inspector's widgets and Lua's kast.getMaterialProperty / setMaterialProperty, and Build ships it. The file format, the type rules and the code generation are in the engine's Shader graphs reference.

Create and open a graph

  • Create: in the Assets panel, open a folder and choose Create > Shader Graph. Kast writes new_shader_graph.kshadergraph (new_shader_graph_2.kshadergraph, ... if taken) and logs Created shader graph '...'. The starter compiles as is: a tint color param, through a Swizzle (rgb), into the Fragment Output's ALBEDO.
  • Open: double-click a .kshadergraph in the Assets panel. Selecting one (single click) shows its compile status and params in the Inspector, with an Open in Shader Graph button. From the command line: --open-graph <file>.
  • One graph is open at a time. Opening another while the open one has unsaved changes asks Save / Discard / Cancel. Renaming or moving the open graph in the Assets panel keeps it open under its new path.

Panels

Three dockable panels, docked by default next to the views (Shader Graph with Scene and Game, Graph Inspector with the Inspector, Shader Preview with the Hierarchy). Opening a graph brings them to the front. Their titles show the file name, with a * while it has unsaved changes.

  • Shader Graph: the canvas. A summary line at its top reads Compiled, Compiling..., or in red Errors: the last good version renders - 1 error, 1 warning - node 12: ....
  • Graph Inspector:
    • always: Save and the node and link counts;
    • with one node selected: its title, id, type and the stages it may run in, its settings (a Param's param, a constant's value, a Swizzle mask, a Noise kind, a Custom Expression's pins and code), a constant field for each unlinked number input (inputs whose default is a built-in, e.g. uv: UV when unlinked, have none; a texture input reads link a texture2D), and the node's errors and warnings;
    • with a comment frame selected: its title;
    • with nothing selected: the graph's params, the .kshader's param lines. Each has a name, a type (float, vec2, vec3, vec4, color, texture2D), a default, and a range (floats) or sRGB (textures); + Param adds one, Remove deletes one. Renaming a param renames it on its Param nodes; changing its type drops the links the new type can't make. A material sets its own values in the Inspector.
  • Shader Preview: the graph as it is now, saved or not, on a lit Sphere, Cube or Plane, with a directional light, ambient light, the sky and TIME running. Drag to orbit, wheel to zoom. The preview material is the built-in material's defaults plus the params' defaults; a graph that samples the screen or depth texture gets alpha mode blend, so it can render. View generated code shows the .kshader text the library compiles, read-only, with Copy to clipboard.

The canvas: nodes, links, the add menu

  • Pan by dragging the background with the right mouse button, zoom with the wheel.
  • Nodes have an orange header with their title (a Param node shows its param, Param: speed), inputs on the left and outputs on the right. Pins are colored by type: float green, vec2 cyan, vec3 purple, vec4 blue, texture2D pink, and grey for a math node's dynamic pins (they take the widest number linked in). A filled pin is linked.
  • Link by dragging from an output to an input (or back). A link Kast refuses (a texture into a number, a number into a texture, a link that would close a cycle) shows red with the reason, Can't link: a texture2D can't go into a float input, and is not made. A wider vector into a narrower input is allowed and truncated, with a warning on that node. An input takes one link: a new one replaces the old. Select a link and press Delete to unlink.
  • The add menu opens at the cursor with a right-click on the background or Space over the canvas. Type to search; entries are grouped by category (Output, Input, Constant, Params, Vertex, Material, Light, Math, Vector, Texture, Effect, Custom, and Comment). The graph's params are listed as Param: name, which adds a Param node set to it.
  • From a pin: drop a link dragged from a pin on empty canvas, and the add menu opens filtered to the nodes that can link to it (Nodes that link from 11.out); the chosen node is added there already linked, through its first pin that takes the link without a warning. Adding and linking is one undo step.
  • Select: click a node; Ctrl+click adds to the selection; drag a box on the background to select every node in it.

Copy and paste, comments, delete

  • Ctrl+C copies the selected nodes, the links between them and the params their Param nodes use, as .kshadergraph text on the clipboard. Ctrl+X copies, then deletes. Ctrl+V pastes at the mouse cursor, Ctrl+D duplicates the selection there. Pasted nodes get fresh ids, keep the links among themselves (links from nodes that weren't copied are dropped) and are left selected. Pasting into another graph also adds any param its Param nodes need that the graph lacks.
  • Delete removes the selected nodes and links, and the links into and out of those nodes.
  • Comment frames: choose Comment in the add menu to frame the selected nodes (or make a 300 x 200 frame at the cursor). A frame has a title (edit it in the Graph Inspector), resizes from its edges, and dragging it moves the nodes inside it. Frames are only for reading the graph; they generate no code.

Undo, Save and files changed on disk

  • The graph has its own undo history: Ctrl+Z / Ctrl+Y while the Shader Graph or the Graph Inspector is focused undo and redo graph edits, not scene edits. One step each: add, delete, link, unlink, a move (one per drag), paste, a setting edit (from grabbing a field to releasing it), a constant, a param edit, and adding, moving or resizing a comment. The history is cleared when a graph is opened or reloaded.
  • Save (the Graph Inspector's button, or Ctrl+S while a graph panel is focused) writes the file; the title's * goes away. Undoing back to the saved state also clears it.
  • Changed on disk (by another program, or version control): with no unsaved changes the graph reloads; with some, Kast asks ... changed on disk, and the Shader Graph has unsaved changes Reload / Keep mine.
  • Quitting with unsaved changes asks Save / Discard / Cancel, as opening another graph does.

Preview and live update

Edits show before you save. 0.3 s after the last edit (each edit restarts the wait) Kast generates the graph's .kshader text and compiles it on the shader library's worker thread, so the editor keeps drawing frames while it compiles. When it is done, the Shader Preview and every material using the graph in the Scene and Game views (in Play too) draw the new version. From an edit to the new image takes about half a second (0.51 s measured with an empty shader cache, 0.35 s on a cache hit, debug build); the log says Shader Graph: 'shaders/x.kshadergraph' live-updated 0.51 s after the edit (13 frames drawn while it compiled). Moving nodes and editing comments doesn't recompile.

  • The file on disk only changes when you Save. The Shader Preview says Unsaved edits shown while the graph differs from it.
  • While a compile runs, and after one fails, the last good version keeps rendering. A graph that has never compiled renders magenta, like a broken .kshader.
  • Closing the graph without saving (Discard, or the file being removed) drops the unsaved version: the library compiles the file on disk again and the views go back to it.

Errors

Errors are always on a node. The node is outlined red for an error and #ffcc00 (yellow) for a warning; hovering it shows the message (Error: line 31: error X3004: undeclared identifier 'undefinedThing'), and selecting it lists them in the Graph Inspector. The canvas's summary line counts them, the log has them ([error] Shader 'shaders/x.kshadergraph': node 12: line 31: ...), and the material Inspector of every .mat using the graph shows them in its Shader status. Where they come from:

  • Validation, before compiling: a node in a stage it isn't available in (Light Direction is not available in fragment() (only in light())), a required input with no link (input 'texture' needs a link), a Param node naming a param the graph doesn't have, a second output node of a kind, bad settings (a Swizzle mask, a Custom Expression pin list), too many params or textures, a param named like a built-in. The graph doesn't compile; the last good version renders.
  • Warnings: a wider vector truncated into a narrower input (input 'ALBEDO': vec4 truncated to vec3). The graph still compiles.
  • shaderc, the compiler: its errors come back with a line of the generated .kshader, which Kast maps to the node whose code is on that line, e.g. a Custom Expression's body.
  • The screen / depth texture rule, on the node that samples them.

Use a graph from a material

Select a .mat: the Inspector's Shader picker lists the project's .kshadergraph files with its .kshader files. With a graph picked, the section shows its compile status and a widget per param, as for a .kshader. Param edits are undoable and saved to the .mat's params, exactly as for a .kshader; see Shaders in the editor. In Lua, kast.setMaterialProperty(entity, "speed", 2) changes a graph param on one entity in Play, and Stop puts it back. A .mat names the graph as "shader": "shader_graphs/water.kshadergraph".

Node reference

Columns: the node's type id (as in the file) and title; its inputs, with the value an unlinked input takes in brackets (req: it must be linked); its outputs and the code each generates ({pin} is that input's code); the stages it may run in: V = vertex(), F = fragment(), L = light(). Unlinked number inputs can be given a constant in the Graph Inspector instead of their default. Each node's code is written once per stage it reaches, as <type> n<id>_<pin> = <code>; after a // @node <id> <type> line. dyn (dynamic) pins take the widest of the node's dynamic inputs; a float into a wider pin is splatted, a narrower vector padded with zeros, a wider one truncated (with a warning).

Output

One of each at most. Their linked inputs are written into the built-ins; an unlinked one keeps what the built-in material computes (so an empty graph renders as the built-in material). vertex() and light() are only generated when their output node has a linked input.

Custom Expression

For what no node does: a block of shader code with typed pins you declare. Use it sparingly; the samples need none.

  • Settings: inputs, e.g. vec3 color, float amount, texture2D mask (float, vec2, vec3, vec4 or texture2D); outputs, e.g. vec3 result, float glow (float to vec4; no textures); and code, the body. Each pin becomes a pin of the node. Changing the lists drops the links of pins that went away.
  • Names must be identifiers, unique within the node, not a .kshader built-in (UV, ALBEDO, ...), not a generated temp (n<digits>_...) and not one of the graph's params (params are macros and would rename them).
  • The code is .kshader GLSL. It reads the inputs and assigns the outputs as local variables; the outputs start at zero; it may use the built-ins of the stages it runs in, the params, and texture inputs with texture2D(mask, UV). It is generated inside its own block after the node's marker: 
        // @node 7 custom_expression
    vec3 n7_result;
    {
        vec3 color = n3_out;
        float amount = 0.0;
        vec3 result = vec3_splat(0.0);
        result = color * amount;     // the code, each line indented
        n7_result = result;
    }
    so a compile error in it is reported on that node (node 7: line 31: error X3004: undeclared identifier ...).
  • The text is shader source only: Kast passes it to the shader compiler and never runs it in the editor.

SCREEN_TEXTURE and DEPTH_TEXTURE

Scene Color, Depth Fade and the Screen Texture / Depth Texture inputs read the opaque scene drawn before the surface. Like a .kshader that samples them (why), a graph using any of them only works on materials whose alpha mode is blend or additive (drawn after that scene). On an opaque or mask material it renders magenta and the error names the node:

node 4 (Scene Color) samples SCREEN_TEXTURE, which is only for blend and additive materials (drawn after the opaque scene it copies); this material's alphaMode is opaque

The Shader Preview picks blend for such a graph by itself. Shadow passes never sample these textures.

Limits

  • The .kshader limits: at most 16 number params and 4 texture params; param names follow the .kshader rules (identifiers, not a built-in's name).
  • One Vertex Output, one Fragment Output and one Light Output at most; links may not form a cycle; an input takes one link.
  • Each node only runs in its stages (the tables above). A node feeding two stages is generated in each.
  • Mesh surface shaders only (as .kshader): not post-processing, particles, the sky or game GUIs. No subgraphs, reroute nodes or per-node preview thumbnails, and no conversion of a .kshader into a graph.

Samples

tests/project/shader_graphs/ rebuilds the five hand-written .kshader samples as graphs, with no Custom Expression nodes. tests/project/shader_graphs.scene is custom_shaders.scene (same camera, lights, fog, objects and skinned character) with its materials switched to materials/graph_*.mat, and renders the same image: the tests compare the two pixel for pixel at frames 60 and 120, in the Scene view and in Play.

  • pulse.kshadergraph: scrolling, pulsing emissive lines. UV.y (Swizzle y) times lines minus TIME times scroll_speed, Fraction, two Smoothsteps for the band; Surface albedo times a Lerp darkens under it; Material Emission plus glow times band, pulse and intensity into EMISSION.
  • wind.kshadergraph: grass bending in the wind (instanced, shadows sway). In the vertex stage, Model Matrix gives the mesh's world origin (the phase) and its X / Z scale (Length of a transformed axis); the bend grows with the height above base, offsets VERTEX through a Combine, and tints COLOR toward tip. Fragment: Surface albedo times Vertex Color.
  • dissolve.kshadergraph: the noise texture param's R against threshold (Step) times the base color's alpha into ALPHA (on an alpha mode mask material, so the shadow is cut too), and a glowing edge into EMISSION. scripts/dissolve_driver.lua animates threshold in Play with kast.setMaterialProperty.
  • water.kshadergraph: waves in vertex() (two sine trains from the world position, through Model Matrix), a normal from their slopes in fragment(), Fresnel toward sky_color, Depth Fade toward deep_color, Scene Color refraction offset by the normal, and foam where the scene behind is close. Blend, unlit. The two wave chains share k, the time terms and wave_height; each stage gets its own copy of them.
  • toon.kshadergraph: Light Output only. N dot L times Attenuation into Toon Bands, times Surface albedo and Light Color into DIFFUSE_LIGHT; a hard highlight (Step of N against the half vector) and a rim (Step of one minus N.V) into SPECULAR_LIGHT.
