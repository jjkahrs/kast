Map Builder

A large map is easier to build as many scenes than as one: each 256 m tile of a zone can have its own scene file. The editor's Map tab shows the open zone's tiles top-down and opens, closes and creates their scenes; in Play the engine streams them in and out around the player like the terrain (Terrain, tile scenes). The tab is editor/map_panel.*; the tile scene logic (paths, cell states, the streaming diff) is engine/tile_scenes.h.

Tile scenes

  • Tile tx, tz's scene is maps/<folder>/scenes/<tx>_<tz>.scene (project-relative). The file exists exactly when the tile has one: there is no manifest, and map.json does not change.
  • Its entities use world coordinates: tile tx, tz spans x [tx * 256, (tx + 1) * 256) and z likewise, so an entity at (300, y, 40) belongs in 1_0.scene. There is no per-tile offset.
  • The zone's root scene (the one with the Terrain entity: the sun, the camera, shared prefabs) stays the active scene; tile scenes open beside it as additive scenes and are never made active by the tab.
  • Tile scenes are ordinary scene files: File > Open Scene Additive, Save Scene and Remove Scene work on them as on any other.

The Map tab

The tab sits beside Hierarchy and Zone in the left dock (also added there on the first run with an older imgui.ini). It shows the zone of the open scene by the Zone tab's rule (the first Terrain entity's map), with the same messages when there is no project, no Terrain entity, or the map does not load. Below the map's folder: the grid, a legend, and Problems.

The grid is the map's full 8 x 8 bounds from its lowest declared x and z, +z up (as the Zone tab's tile grid and the default camera). The cells fit the dock's width (24 to 96 px). Each cell shows:

  • its tx_tz label (top left, * after it while the tile scene has unsaved changes);
  • its tile scene's entity count (bottom right): from the open scene when it is open, else read from the file (cached; read again when the file changes, every half second at most, and when the open scenes change);
  • a terrain thumbnail made on the CPU from the zone's in-memory heights, colored by map.json terrainColors (grayscale without them); a tile's thumbnail is made again when a Zone tab edit changes its heights or the colors change;
  • the map's player spawn (a white dot with a line for its heading) and its portal areas from areas.json (filled outlines; an area crossing tiles is drawn across each of them).

Hover a cell for its tooltip: the tile scene's path, its state and its entity count.

Create. A click on a declared tile without a scene adds an empty scene (no entities, default settings) named for maps/<folder>/scenes/<tx>_<tz>.scene, open and unsaved: nothing is written until File > Save / Ctrl+S (or its header's Save Scene) writes it there, making scenes/ if needed. Closing it before then asks first; Don't Save leaves no file.

Every action logs a Map: ... line to the Console (Map: opened tile 1_0 (...), Map: close tile ..., Map: created ...), as do the zone it shows (Map: maps/tilegrid (9 tiles, 5 tile scenes)) and the warnings.

Read-only. During Play and in prefab edit mode clicks do nothing and a note says why. In Play the cells show the scenes that streamed in as open.

Validation

The tab checks the zone's tile scenes and lists each problem under its Problems header; each is also logged once to the Console as a warning ([warn] Map: ...) when it appears. None of them blocks saving the scene or the zone.

  • Orphan tile scene: a scene file on a tile map.json does not declare. Removing a tile in the Zone tab does not delete its scene, so it becomes an orphan: declare the tile again, or move its entities into another tile scene and delete the file.
  • Entity out of bounds: a root entity of a tile scene whose world x/z is outside that tile's square, named with the tile it actually stands in (maps/tilegrid/scenes/0_1.scene: root entity 'Stray Rock' at (600, 400) is in tile 2_1, outside tile 0_1). It is allowed and saves fine; it streams with its own tile's scene.
  • Bad file name: a file in scenes/ that is not <int>_<int>.scene (editor .meta files aside) is ignored, with a warning.
  • A tile scene file that cannot be read or is not a scene: its error.

Play

Play starts from the open scenes, then streaming takes over: tile scenes out of Terrain.radius of the player (or camera) unload, even ones you had open, and those in range load, one a frame. Stop restores the open set exactly as it was, unsaved changes included.

Command line

--map-click tx,tz (repeatable) clicks that cell, one click a frame from frame 12, for tests and screenshots (Command line):

build\debug\kast_editor.exe --scene tests\project\scenes\tilegrid.scene --focus-panel Map --map-click 1,0

Sample: tests/project/scenes/tilegrid.scene with tests/project/maps/tilegrid (map 7, 3 x 3 tiles; scenes on 0_0, 1_0, 0_1 and 1_1, the out-of-bounds Stray Rock in 0_1, and an orphan on 3_1). The editor_map_* and player_tilegrid_stream tests use it (cmake/map_tests.cmake).
