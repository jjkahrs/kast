Map Builder

The editor's Map tab and the Scene view create and edit a project's maps (maps/<folder>/, see Maps and Terrain) in 3D and save them in place, in the formats the engine and the world server load. The tab's Tiles section shows the map's tiles top-down: it adds and removes tiles, and opens, closes and creates their tile scenes. The map logic is the kast_mapedit library (engine/mapedit/), the tile scene logic (paths, cell states, the streaming diff) engine/tile_scenes.h; the tab and the Scene view tools are editor code (editor/map_*).

Quick start

From an empty (saved) scene to a saved map with terrain, two zones and a sculpted hill, in 10 actions:

  1. Click the Map tab.
  2. New Map... (Setup sub-tab).
  3. Type a Name (2 x 2 tiles, 0 .. 100 m, flat by default).
  4. Create: adds the Terrain entity, makes the map with one zone of every tile, frames it in the Scene view and saves.
  5. Click the Zones sub-tab.
  6. Add Zone (selected, ready to paint).
  7. Drag over the terrain in the Scene view (or the tab's tile grid): those tiles go into the new zone.
  8. Click the Terrain sub-tab (Raise is active; the brush cursor follows the mouse).
  9. Drag on the terrain in the Scene view: a hill.
  10. Ctrl+S: the scene, the map and its zones.

Before this (commit 64261dd) the same result took 11 or 12: Map tab, New Map..., type the folder, Create, expand the collapsed Zones section, Add Zone, scroll up to the Tiles grid, drag on the grid, Raise in the top bar, drag in the Scene view, Ctrl+S (the panel's separate Save Map suggested one more). A map whose height range was empty also needed the Terrain section expanded, Min / Max typed and Apply range before any stroke changed anything, with no message at the brush.

A map is the scene's Terrain map

The map is the map whose id is in the open scene's first entity with a Terrain component (the same rule Play's terrain streaming follows). Picking another map or creating a New Map in the Map tab sets that Terrain.map (and marks the scene unsaved); editing Terrain.map in the Inspector opens that map instead. One map is open at a time.

  • No project: the tab says a project is required (maps live in the project's maps/ folder).
  • No Terrain entity: the tab says so and offers Add Terrain entity (created, selected, scene marked unsaved); picking or creating a map adds one too.
  • Several Terrain entities: the first one is used, and a note names it.
  • Map not found or broken: a Terrain.map id no project map has, or a map that fails to load, shows the error in the tab (and once in the Console); nothing of the map is drawn.

Tile scenes. A large map can also be split into one scene per 256 m tile next to its root scene: see Tile scenes.

One scene per map. A map's scene is the one whose Terrain entity names that map: open it to edit the map in the Map tab. It holds that map's own client content (props such as its portal arch) and instances of the prefabs every map shares (player, camera, replication, NPC templates, in-world GUI), so a change to a shared prefab reaches every map. At run time the game loads the map's scene when the player enters the world or a portal moves it to another map (a world.entered / world.mapChanged subscriber calling kast.loadScene; replication carries the player and what is in view across). samples/starter-mmo: scenes/meadow.scene is the Meadow (map 10), scenes/cavern.scene the Cavern (map 11), and scripts/world_flow.lua holds the map-to-scene table.

Scene view

In edit mode the Scene view draws the declared tiles within 4 tiles of the camera's pivot (9 x 9 at most, so an 8 x 8 map whole) with the map's material (and the generated terrain texture, if any), plus every map object as its prefab, from the map's in-memory state: edits show straight away. Every tile's heights stay in memory; a tile's mesh is built when the pivot comes within range (the Console logs Map view: N terrain meshes) and freed when it leaves, and a map.json edit rebuilds only the meshes it changes (id, height range, material, UV mode, or with Map UVs the bounding box). Focus on a map wider than 9 tiles frames the 9 x 9 around its centre. While a map is shown the camera's near and far planes are 0.5 m and 8 km (the farthest dolly is 5 km), so the meshed tiles stay in view. Overlays (drawn on the meshed tiles only): tile borders, the player spawn (with its heading), areas (portals in blue, the selected one with corner handles), spawns (with heading), patrol paths, map objects (a dot each; obstacles' and interactables' shapes outlined on the ground) and, with a sculpt tool, the brush cursor: its radius as a highlight circle on the ground under the mouse and, inside it, an accent ring where the falloff starts (full strength inside it; none at falloff 0). They are drawn over the terrain, not hidden by hills.

Play does not use the in-memory map: as before, the terrain streams around the player by Terrain.radius from the saved map files. Starting Play with unsaved map edits logs a Console warning saying so.

Input. The editor camera keeps its controls (Editor controls: right drag flies, Alt + left drag orbits, middle drag pans, the wheel zooms).

  • With a map tool active (Raise, Lower, Flatten, Area Rect, Area Polygon, Place Spawn, Path Points, Place on terrain, Place Object, Scatter), left mouse in the Scene view goes to that tool: it never selects an entity or moves the gizmo. Esc first cancels an area being drawn, then clears the tool. Clicking an active tool's button turns it off.
  • With no map tool, left click selects entities and the gizmo works as usual, except that while the Map tab is the front tab the map's handles (area vertices, spawns, path points, object dots) take priority when hit: click to select, drag to move (snapped to the ground, one undo step per drag).
  • Any left click on the terrain also picks the tile the Heightmap import/export works on.

New Map wizard

New Map... (Setup sub-tab; the unsaved-map prompt first if the open map has unsaved edits) opens one dialog:

  • Name: the map's name. The folder is made from it (lower case; letters, digits, - and _ kept, anything else _), shown under the fields with the id.
  • Tiles X / Tiles Z: 1 to 64 each (Map size limits); 2 x 2 by default.
  • Height Min / Height Max: the height range, 0 .. 100 m by default; Max must be above Min.
  • Start terrain: Flat, or Generated (Generate's fBm with the Terrain sub-tab's current settings, over the whole height range).
  • Advanced (collapsed): Folder (typing one stops it following the name) and Id (the lowest unused by default).

Create is disabled, with the reason in red, while the name is empty, maps/<folder> already exists, the id is used or Max is not above Min (a folder that is not a plain name is refused on Create, the reason shown). On Create: the map is made with one zone of every tile (zones.json), the height range and the start terrain (its first state, not an undo step), the scene's first Terrain entity is pointed at it (added if there is none; one scene undo step), the Scene view camera frames the map (as Focus), and File > Save writes the scene (asking where if it is untitled) and then the map. If the scene's Terrain already names a map, Create first asks Replace map link?: Replace goes on, Cancel goes back to the wizard. The old map's files are never touched.

Everything the tab does is also logged to the Console (Map: ... lines: loads, strokes, placements, saves, problems, Bake output).

Instance maps

The Map section's Type combo makes the map a world server instance map ("type": "instance": a copy per group, destroyed once empty) or a world map again (every instance field removed). For Instance it shows:

  • Unlimited players / Max players: no maxPlayers, or players per copy (1 or more).
  • Empty timeout (s): emptyTimeoutSec, 0 to 31536000 (default 300).
  • Exit: Exit map (the project's other world maps), Exit x, y, z typed and Exit heading: where a character goes when its copy is gone. Picking a map puts the exit at that map's spawn. The exit is on another map, so it is typed rather than clicked in this map's Scene view. Switching to Instance sets the exit to the first other world map's spawn.

Each field is one undo step (Edit Map). The fields are read straight from map.json, so they stay editable while the manifest is invalid; a bad value shows on the map.json: error line (the server's message, such as "maxPlayers" must be an integer >= 1), and an exit the server would refuse (an unknown or instance map, off its tiles, inside one of its portal areas) as map.json: "exit": ... under the fields and in Problems; either blocks the save.

Tiles

The Tiles section holds the map's one tile grid. Click: picks what a click on a cell does: Tile scenes (the default) or Add / remove tiles. Below the grid: a legend, and the tile scene problems.

The grid is +z up (as the default camera). In Tile scenes mode it covers the map's bounds from its lowest declared x and z (at least 8 x 8 cells), cells up to 96 px; in Add / remove tiles mode the bounds and one free cell around them, smaller cells. It opens fitted whole to the tab's width (a 64 x 64 map's cells, the largest (Map size limits), are a few pixels). The mouse wheel zooms about the mouse (out to the whole map, in to twice the widest cell) and a drag with any button pans (never past the map's edges); a click without a drag picks a cell. Only the cells on screen are drawn. Labels and counts show on cells wide enough for them (24 px, more for two-digit names). Each cell shows:

  • its tx_tz label (top left, * after it while the tile scene has unsaved changes);
  • its tile scene's entity count (bottom right): from the open scene when it is open, else read from the file (cached; read again when the file changes, every half second at most, and when the open scenes change);
  • a terrain thumbnail made on the CPU from the map's in-memory heights, colored by map.json terrainColors (grayscale without them); a tile's thumbnail is made again when a Map tab edit changes its heights or the colors change. Only the cells on screen have one (64 made a frame at most), freed when they scroll off; cells under 8 px, or more than 1024 on screen, show their state color instead (each thumbnail is a GPU texture);
  • the map's player spawn (a white dot with a line for its heading) and its portal areas from areas.json (filled outlines; an area crossing tiles is drawn across each of them).

Hover a cell for its tooltip: in Tile scenes mode the tile scene's path, its state and its entity count; in Add / remove tiles mode what a click does.

Create. A click on a declared tile without a scene adds an empty scene (no entities, default settings) named for maps/<folder>/scenes/<tx>_<tz>.scene, open and unsaved: nothing is written until File > Save / Ctrl+S (or its header's Save Scene) writes it there, making scenes/ if needed. Closing it before then asks first; Don't Save leaves no file.

Every action logs a Map: ... line to the Console (Map: opened tile 1_0 (...), Map: close tile ..., Map: created ...), as do the map it shows (Map: maps/tilegrid (9 tiles, 5 tile scenes)) and the warnings.

Add / remove tiles. Free cells show a +: a click adds that tile (one undo step), a click on a tile asks to remove it (not the map's last tile). Cells that would make the map wider or deeper than 64 tiles show no + and refuse.

Read-only. During Play and in prefab edit mode clicks do nothing (zoom, pan and tooltips still work); the note at the top of the tab says why. In Play the cells show the scenes that streamed in as open.

Zones

A zone is a named set of a map's tiles (maps/<folder>/zones.json, format: Maps, zones). Every declared tile is in exactly one zone, and a zone's tiles are connected through shared edges (diagonal neighbours do not connect). A map without zones.json has one implicit zone: id = the map's folder, name = the map's name, every tile. Nothing is written for it: the first zone edit (add, paint, rename, name, flags, delete) makes it explicit, and Save Map then writes zones.json. Saving a map whose zones did not change writes no zones.json; keys of a zone the tab does not edit stay as they were.

  • Add Zone appends a zone with no tiles (zone, zone_2, ...), selects it and switches the grid to Paint zone mode. A zone with no tiles blocks the save until painted.
  • Paint. The Zones sub-tab shows the tile grid right under the zone list, in Paint zone mode: a click, or a drag with the left button, moves every declared tile it crosses into the selected zone (one undo step per stroke; a right or middle drag pans). Cells show a thick white line where neighbouring tiles are in different zones, each zone's name on its top-left visible tile, and the selected zone tinted. The grid overlay shows on every grid mode once the map has a zones.json.
  • Paint in the Scene view. While the Zones sub-tab is in front (and painting is on: Stop painting turns it off), the Scene view paints too: the tile under the mouse is outlined, and a left drag over the terrain moves every tile it crosses into the selected zone, as on the grid. Each zone's tiles are tinted a color of their own with the zone's name on a label (the selected zone's label is outlined); the overlay shows only on the Zones sub-tab.
  • Refused tiles. A tile whose move would break a zone rule (leave a zone in pieces, give the selected zone a tile that touches none of its others, or leave a zone with no tiles) is not painted, on the grid or in the Scene view: the Console logs Map: can't paint tile 0_1 into zone east: zone "east": not contiguous (...), and the Zones sub-tab shows it in red until the next stroke. The zones stay as they were. The --paint-zone command-line edit is not checked (tests use it to make invalid zones).
  • Id is applied when the field is left (letters, digits, _, -; not starting with -; unique, else it reverts with an error); Name and Flags are one undo step per field edit. Flags are checked as you type: the last valid JSON object is kept, an empty field removes them.
  • Delete Zone: its tiles go to the zone of an edge neighbour (below). With none (the last zone) they are in no zone, which blocks the save.

Edge neighbour order. A tile's edge neighbours are tried in the order -x, +x, -z, +z. A tile added in Add / remove tiles mode joins the zone of its first neighbour that is in a zone (else the first zone); a deleted zone's tiles go to the zone of the first neighbour, of its tiles sorted by z then x, that is in another zone. A removed tile leaves its zone.

Problems block the save (listed in the Zones section as you edit, and in Problems after a save attempt; nothing of the map is written): a zone split in two (a removed tile, a command-line paint), a zone with no tiles, a declared tile in no zone, a tile in two zones, a bad or duplicate id, a zone tile not declared in map.json, and a renamed zone whose new zones/<id>.scene is already taken.

Zone scenes

Each zone can have its own scene, maps/<folder>/zones/<zoneId>.scene, like a tile scene: world coordinates, opened additively beside the map's root scene and never made active. The selected zone's Create Scene adds an empty, unsaved scene (File > Save / Ctrl+S writes it, making zones/); Open Scene / Close Scene open and close it (asking first if it has unsaved changes). Renaming a zone keeps its scene: until the next save the zone's scene is still the file of its old id, and Save Map renames it (and its .meta); an open one follows. Each action logs a line: Map: opened zone west (maps/tilegrid/zones/west.scene), Map: close zone ..., Map: created ... for zone east (unsaved: ...), Map: zone vale renamed from west: its scene is ....

Warnings (the Zones section's Zone scene problems and the Console, once each; they never block a save): a scene of no zone (an orphan: deleting a zone leaves its scene file), a root entity outside its zone's tiles (root entity 'West Gate' at (300, 300) is in zone east, outside zone west), a file in zones/ that is not <zoneId>.scene (ignored), and a scene file that does not read.

The Zones section is read-only during Play and in prefab edit mode, as the rest of the tab. In Play (and kast_player) a zone's scene streams in while any of its tiles is within Terrain.radius of the player or camera and out when none is, and Lua gets zone.left / zone.entered and kast.map.zone(): see Zones.

Tile scenes

Each 256 m tile of a map can have its own scene file; in Play the engine streams them in and out around the player like the terrain (Terrain, tile scenes).

  • Tile tx, tz's scene is maps/<folder>/scenes/<tx>_<tz>.scene (project-relative). The file exists exactly when the tile has one: there is no manifest, and map.json does not change.
  • Its entities use world coordinates: tile tx, tz spans x [tx * 256, (tx + 1) * 256) and z likewise, so an entity at (300, y, 40) belongs in 1_0.scene. There is no per-tile offset.
  • The map's root scene (the one with the Terrain entity: the sun, the camera, shared prefabs) stays the active scene; tile scenes open beside it as additive scenes and are never made active by the tab.
  • Tile scenes are ordinary scene files: File > Open Scene Additive, Save Scene and Remove Scene work on them as on any other.

Validation

The tab checks the map's tile scenes and lists each problem under the Tiles section's Tile scene problems; each is also logged once to the Console as a warning ([warn] Map: ...) when it appears. None of them blocks saving the scene or the map.

  • Orphan tile scene: a scene file on a tile map.json does not declare. Removing a tile does not delete its scene, so it becomes an orphan: declare the tile again, or move its entities into another tile scene and delete the file.
  • Entity out of bounds: a root entity of a tile scene whose world x/z is outside that tile's square, named with the tile it actually stands in (maps/tilegrid/scenes/0_1.scene: root entity 'Stray Rock' at (600, 400) is in tile 2_1, outside tile 0_1). It is allowed and saves fine; it streams with its own tile's scene.
  • Bad file name: a file in scenes/ that is not <int>_<int>.scene (editor .meta files aside) is ignored, with a warning.
  • A tile scene file that cannot be read or is not a scene: its error.

Tile scenes in Play

Play starts from the open scenes, then streaming takes over: tile scenes out of Terrain.radius of the player (or camera) unload, even ones you had open, and those in range load, one a frame. Stop restores the open set exactly as it was, unsaved changes included.

Objects

Map objects are prefabs placed on the map's tiles (formats: World Server, Maps, Objects; in game: Engine, Terrain). The project's .prefab files are listed in the Objects section.

  • Types: Visual (grass, flowers: client only, blocks nothing), Obstacle (rocks, walls, trees: blocks players and NPCs; the server knows only its shape) and Interactable (blocks like an obstacle, and a player can activate it; the server publishes its event).
  • Place Object: pick the prefab and the type, then click the terrain: the object stands on the ground there (y snapped), yaw 0, scale 1. A new obstacle or interactable gets a 1 m box shape; a new interactable gets the next free id on the map and a server entry (range 3, event <prefab name>.activated).
  • Select and move: with no tool and the Map tab in front, click an object's dot to select it (or pick it in the list) and drag to move it on the ground. Moving one into another tile moves it to that tile's file, an interactable's server entry with it.
  • Fields: type (an interactable turned obstacle loses its id and server entry; a visual keeps an old shape unused), prefab, position (x, z; y follows the ground), yaw (degrees here, radians in the file), scale (the prefab only), shape (Box half extents, turned by yaw, or Cylinder radius and height, in metres, standing on the object). An interactable also has its id (unique on the map: a used one is not taken), name, and the server-only range, event and data (a JSON object, checked as you type: text that isn't one shows the problem and keeps the last valid data; empty removes it). The server entry's pos, yaw, shape and name always follow the object.
  • Overlays: a dot per object (green visuals, orange obstacles, blue interactables with #id name, the selection in yellow) and each shape's outline on the ground (16 points for a cylinder). The Scene view draws each object's prefab, scaled and turned; a tile's objects are rebuilt when they change.
  • Scatter (visuals only): tick prefabs (one is picked at random per object), set the radius, how many per dab, random yaw or not, the scale range and the seed. Drag on the terrain: a dab on mouse down and another each time the brush has moved its radius, each placing that many visuals at random points of the circle, on the ground (points off the map are skipped). The whole stroke is one undo step. Erase visuals turns the brush into an eraser that removes every visual inside the circle (obstacles and interactables stay). The random numbers come from the seed (xorshift32, the same on every machine): changing the seed or pressing Restart starts its sequence again, so the same seed and strokes give the same objects.
  • Save writes each changed tile's objects/ and .server/interactables/ file and deletes a tile's files once it has none. Unknown keys in the files are kept. Re-bake the navmesh (Bake) after placing, moving or removing an obstacle or interactable.

Generated terrain

Generate heights (Terrain section) replaces the heights of every declared tile with fBm Perlin noise: Seed (or Randomize), Scale (metres per noise feature, default 256), Octaves (5), Persistence (the amplitude ratio between octaves, 0.5) and Lacunarity (the frequency ratio, 2). The noise is sampled at each sample's map position, so tiles sharing an edge get the same samples (no seams, whatever the tile layout), and it is stretched over the whole height range: the lowest sample is the range's min, the highest its max. The same seed and settings on the same tiles give the same heights. The player spawn moves up or down onto the new ground. One Generate heights is one undo step.

Height colors is a gradient over the height range: stops at a position (0 % = the range's min, 100 % = its max) with a color. Between two stops the color blends linearly; below the lowest and above the highest it is that stop's. Add stop, Remove (at least 2 stay), drag a position or pick a color; each change is one undo step. The default is sand, grass, rock, snow. It is kept in map.json as "terrainColors" (see Terrain).

Create texture & material (Terrain section) sets the map's material to materials/<folder>_terrain.mat, "terrainUv": "map" (one texture over the whole map) and the default colors if the map has none, as one undo step. The Scene view shows the result straight away; nothing is written until you save. Then every save writes:

File Content
textures/<folder>_terrain.png 8-bit RGB, the color of the ground at each pixel: 1 px per metre over the bounding box of the declared tiles (256 px per tile), shrunk to fit 4096 px on the longest side (1 px/m up to 16 tiles, 0.5 at 32, 0.25 at 64); grey where no tile is. Row 0 is the box's min z
materials/<folder>_terrain.mat white base color times that texture, metallic 0, roughness 0.9

Both are re-baked on every save of the map, so the texture follows sculpting and color edits. These two paths are the only files a map save writes outside maps/: other materials and textures are never touched, and if one of them already exists before the map has been saved using it (someone else's file), the save is blocked with a problem on that file. Picking another material in the Map section keeps it; the generated files are then no longer written.

Saving, undo and Play

File > Save / Ctrl+S saves everything in one go, from any panel: every open scene with unsaved changes (the edited scene and any open zone or tile scenes), then the map if it has unsaved edits. Save Map (the tab) saves only the map. Both first check the map as the world server would load it: kast_map's parse_manifest, parse_areas and parse_spawns for every tile's file, spawn ids unique on the map, spawn files on declared tiles, the map id unused by the project's other maps, portals to an existing map, onto its tiles and not into a portal there, valid terrainColors, no foreign file at the generated terrain texture or material path, every objects file (parse_objects: any bad entry) and interactables file (parse_interactables) on a declared tile, interactable ids unique on the map, and each interactable object with a server entry of the same id in its tile's file (and each entry with an object). Any problem: nothing of the map is written, the tab comes to the front with Problems listing them all (file and message, as the server reports them), and the Console repeats them; the scene itself still saves. Only files that changed are written; a map opened and saved unchanged keeps every byte.

Edit > Undo / Redo, Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z act on the most recent edit, map or scene, whichever panel has focus: sculpt, then move an entity, and Ctrl+Z undoes the move, a second Ctrl+Z the sculpt. The tab's own Undo / Redo buttons act on the map only. Every map edit is covered, and a brush or scatter stroke, a drag or one field edit is one step. The map keeps its own history beside the scene's, the two ordered by when each step was made: see Undo and redo.

Unsaved changes. The editor's Save / Don't Save / Cancel prompt (New, Open, Open Recent, switching project, quitting) counts unsaved map edits too, and so does changing the map in the Map tab or the Inspector (Don't Save reloads the map from disk).

Read-only. During Play and in prefab edit mode the tab is read-only (tools off, no map overlays in the Scene view); a note at the top says why.

Map size limits

A map is at most 64 x 64 tiles (16 km a side; mapedit::kMaxMapTiles in engine/mapedit/map_io.h): its declared tiles' bounding box may not be wider or deeper than that. New Map..., --new-map, the tile grid and --add-tile refuse more (tiles 65 x 1: 1 to 64 each way); the map format, kast_mapbake, the world server and the client have no cap. 64 is the largest of 16, 32 and 64 that met every budget in the map size benchmark (tools/map_bench, Tests; Release, one machine, 2026-10-30; full tables in tools/map_bench/results.md):

"Before" is the 8 x 8 code (main, every tile meshed); "after" the median of three passes on a slower day for the machine (8 x 8 itself at 85 instead of 117 FPS). The server's tick p99 is the same at every size (today's default map: 10.6-11.0 ms; the bench maps' terrain, navmesh and NPCs add 4-6 ms at 8 x 8 too). What made it fit: the Scene view meshes only the tiles near the camera (above), the Map tab and tile grid draw and thumbnail only the cells on screen, and the Assets panel rescans only on a file change.

Generated terrain texture: 4096 px on the bounding box's longest side, so 1 px per metre up to 16 tiles, 0.5 at 32 and 0.25 at 64 (accepted; a bigger texture or one per tile would lift it).

Known limits (measured where cheap, not fixed):

  • Streaming hitch: the frame a row of tiles loads (synchronously) takes 50-66 ms up to 32 x 32 (8 x 8 included, as before) and 82-109 ms at 64 x 64. Not size-gated, cause not found.
  • Edit radius: the Scene view meshes 9 x 9 tiles around the pivot, fixed (mapedit::kEditRadius 4); farther tiles show nothing in edit mode. Map objects are still built for every tile.
  • Lightmap and VoxelGI bakes gather every tile: about 9 MB per tile (~37 GB at 64 x 64), time linear in tiles.
  • Navmesh: Detour's 32-bit poly refs allow 16,384 polygons per tile at 16 x 16, 4,096 at 32 x 32 and 1,024 at 64 x 64; the bench maps' busiest tile has 419 (2.4x headroom; 358 at 64 x 64, 2.9x). kast_mapbake fails on a tile over the limit (World Server, Navmesh); DT_POLYREF64 is the upgrade path. Paths are capped by kMaxNodes 4096, kMaxPathPolys 1024 and kMaxPathPoints 256, so a very long kast.map.path can fail.
  • Generate heights noise repeats every 256 x Scale m (4 km at the minimum Scale 16).
  • kast_mapbake bakes serially and keeps every navtile in memory: 1,114 s and 596 MB peak at 64 x 64 (15.5 s at 8 x 8).
  • World server startup loads every tile's heights and navtile at once: 1.97 s and 582 MB at 64 x 64 (warm disk cache; 14.9 s cold).
  • kast_player reads the whole game.pak: 989 MB RAM at 64 x 64 (516 MB of heights).
  • Bigger than 64 x 64 would need streaming for the editor's heights, the server's and mapbake's loads, and the player's pak, and DT_POLYREF64; positions are f32 (fine to 16 km).

Command line

kast_editor runs the same edits from the command line (tests and scripts), e.g.:

build\debug\kast_editor.exe --project samples\starter-mmo --map meadow ^
  --scatter 128,128,40,200,7,0.8,1.4,prefabs/grass.prefab --add-object obstacle,prefabs/rock.prefab,141,108,0.3,1,cylinder,1.2,1.4 ^
  --save-map --headless
build\debug\kast_editor.exe --project samples\starter-mmo --new-map dunes,2,2 --generate-heights 7 ^
  --terrain-colors 0,0.76,0.7,0.5,40,0.33,0.52,0.21,100,0.95,0.95,0.97 --create-terrain-material --save-map --headless

Every flag and its syntax: Command line, Map edits. For the Tiles grid, --map-click tx,tz (repeatable) clicks that cell in Tile scenes mode, one click a frame from frame 12; --grid-mode scenes|tiles picks the mode; --grid-view tx,tz,zoom centres the grid on tile tx, tz at zoom times the fitted cells after 10 frames (the tab logs Map: view <first>..<last> (<n> px cells, <n> thumbnails) in Tile scenes mode, on a new map too, and Map: tile grid view <first>..<last> (<n> px cells) in Add / remove tiles mode):

build\debug\kast_editor.exe --scene tests\project\scenes\tilegrid.scene --focus-panel Map --map-click 1,0
build\debug\kast_editor.exe --scene tests\project\scenes\tilegrid.scene --focus-panel Map --map-section Tiles --grid-mode tiles

Sample: tests/project/scenes/tilegrid.scene with tests/project/maps/tilegrid (map 7, 3 x 3 tiles; scenes on 0_0, 1_0, 0_1 and 1_1, the out-of-bounds Stray Rock in 0_1, and an orphan on 3_1). The editor_map_* and player_tilegrid_stream tests use it (cmake/map_tests.cmake).
