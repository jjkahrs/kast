Editor controls

Scene view (only while the mouse is over the Scene panel; a drag that starts there keeps control until released):

Input Action
RMB held + mouse Look around (fly)
RMB held + W/A/S/D, Q/E Fly forward/left/back/right, down/up. Shift = 4x speed
Alt + LMB drag Orbit around the pivot
MMB drag Pan
Mouse wheel Zoom (dolly toward the pivot)
LMB click Select the nearest mesh or camera under the cursor (a camera is picked within 0.25 m of its origin); empty space clears the selection (with a Zone tab tool active the click is the tool's, and with the Zone tab in front a zone handle under the cursor wins: see Zone Builder)
F Frame the selected entity
W / E / R Gizmo: move / rotate / scale (also the toolbar)
X Toggle gizmo Local / World space (also the toolbar button)
Numpad 5 Toggle the view between perspective and orthographic (also the toolbar's Persp / Ortho button)
Delete, Ctrl+D Delete / duplicate the selected entity and its children
Ctrl+P Play / Stop (works anywhere in the editor)

Letter shortcuts work only when the Scene panel is focused and no text field is active.

Orthographic view: the toolbar's Persp / Ortho button (after Local / World) or Numpad 5 switches the Scene view's projection. The orthographic view's height matches what the perspective view showed at the pivot, so toggling keeps the framing; the wheel zooms by changing that height, and pan, F, click select, the gizmo and prefab drops work the same. The choice is saved with the scene's editor camera.

The Scene view draws each Camera as white frustum lines out to 2 m (a preview at 16:9, not the far plane): a pyramid from a perspective camera, a box from the near plane for an orthographic one. Select a camera and the gizmo moves/rotates it like any entity.

Debug views: the Scene view toolbar's Debug button (after Post and World UI) opens a menu of views for LOD and occlusion. They are not saved.

  • LOD tint: every draw in a flat colour by the level it draws at: LOD0 green, LOD1 yellow, LOD2 orange, LOD3 red, LOD4 and up purple. Terrain chunks show their stride the same way (1 green, 2 yellow, 4 orange, 8 red).
  • Occluded boxes: the bounds of the draws occlusion culling skipped this frame, as orange (#ff9900) boxes drawn through whatever hides them.
  • Hi-Z mip: a quarter-width picture at the view's bottom-right of one mip of the depth pyramid occlusion tests against (brighter is nearer), outlined in the accent colour; the slider picks the mip (0 is the finest).

The same views start on with --lod-tint, --show-occluded and --show-hiz <mip> (Command line).

Game panel (a tab beside Scene; Scene is the front tab on first run): renders the scene through the active camera, the first entity with a Camera component in hierarchy (depth-first) order, at the panel's aspect ratio. No grid, axes, gizmos or frustum lines. It renders live in edit mode too; systems only tick while playing, so it animates while playing and holds still while paused. With no camera it shows "No Camera in scene", and Play logs a warning but still runs. Layouts saved before the Game panel existed get it docked beside Scene automatically.

While the Game panel is focused and playing, editor shortcuts (W/E/R, X, F, Delete, Ctrl+D, Hierarchy keys) don't apply, since they need their own panel focused; Ctrl+P still stops Play. Keyboard and mouse input then goes to Document::input (kast::Input in engine/input.h: scancodes and mouse buttons held down, mouse delta and wheel notches this frame) for game systems to read; Lua systems read it through kast.input. It is cleared (keys and buttons released, cursor unlocked) whenever the Game panel or the editor window loses focus, Play stops or kast.loadScene switches scenes; kast_player.exe clears it the same way on window focus loss and scene switches. The cursor stays normal unless a system locks it with kast.input.setCursorLocked(true) (kast::CursorLock: SDL relative mouse mode, the cursor hidden; on unlock it reappears where the lock began).

Stats overlay (F3): during Play (playing or paused), with the Game panel focused, F3 shows or hides one line at the bottom-left of the Game image: FPS 144 Ping 42 ms (then VoxelGI 0.31 ms while VoxelGI volumes relight and SDFGI 0.40 ms while SDFGI is on: the GPU time of their compute views), then the Game view's last camera pass: Tris 580.6k Draws 3 Occluded 72 LOD 3/0/0/504 (triangles submitted, draw calls, draws occlusion culled, draws per LOD level; see Stats). FPS is averaged over the last 0.5 s; Ping is the world server round-trip time (Networking, World round-trip time), -- when not connected or when a Ping has gone unanswered for more than 5 s. F3 does nothing while stopped or with another panel focused, and Stop hides the overlay. It is off at every start and never saved. It also works in the built game (kast_player.exe), where F3 toggles it at any time. The editor draws it with ImGui over the Game image; the player draws it as bgfx debug text at the window's bottom-left (bgfx debug text always lands at the window's corner, not over a panel). kast_player --sim-key frame,key (repeatable) presses a key on that frame (tests, e.g. --sim-key 30,F3), like the editor's --sim-key.

Systems panel (below Hierarchy): the scene's Lua systems in run order. Add Script... picks an existing .lua file inside the active project (a file outside it is rejected with an error), New from Template writes <project>/scripts/new_system.lua (then new_system_2.lua, ...) and adds it; both store project-relative paths. The arrows reorder and Remove drops an entry (the file stays). With no active project both add buttons are disabled (tooltip "Open a scene inside a project"); New from Template also needs a saved scene (tooltip "Save the scene first"). The list can't be edited during Play. Each edit marks the scene dirty. While playing, each entry shows OK or Disabled with its last error. Layouts saved before the panel existed get it docked as a tab beside Hierarchy.

Components panel (below Systems): the active project's Lua components, one row per definition file: OK or Error, the type name and its project-relative path, and the error message for a rejected file. New from Template writes <project>/components/new_component.lua (type NewComponent; then new_component_2.lua with NewComponent2, ...), a valid definition with one field and every field type shown commented, and loads it at once. It is disabled with no active project (tooltip "Open a scene inside a project") and during Play ("Stop Play to add components"). Layouts saved before the panel existed get it docked as a tab beside Systems.

State Machines panel (tabbed with Console): the active project's state machine definitions, one row per file: OK or Error, the machine name and its project-relative path, and the error message for a rejected file. A valid one has a Global checkbox that adds it to (or removes it from) project.kast "stateMachines" and saves that file at once; while playing, a Global machine shows its live State:. A listed name with no valid definition is shown in red with Remove. New State Machine... opens a modal like New Lua Component: type a name (e.g. TrafficSignal), Create writes a template definition (states idle and active, every option shown) to <project>/fsms/<snake_case>.lua and rescans. Create is disabled, with the reason in red, for an empty name, a non-identifier, the name of any listed definition (even one in error) or an existing file (case-insensitive); it never overwrites. Global and New State Machine are disabled with no active project and during Play ("Stop Play to change state machines"). The list is rescanned every 0.5 s, also during Play (Play itself reloads its own copy). Layouts saved before the panel existed get it docked as a tab beside Console.

LOD Group (LODGroup): Add Component > LOD Group on an entity with a Model Renderer overrides its model's LOD thresholds. Its Inspector section: Screen Heights (a list, one per level, 0..1, not increasing; 1 to 8 entries), Bias (above 0; above 1 keeps detail further away), Cull Below Last, and a live readout of the level the Scene view drew it at last frame: Current LOD: 2, Current LOD: culled (below the last threshold with Cull Below Last), or Current LOD: not drawn in the Scene view. Without a Model Renderer it says Needs a Model Renderer on this entity: the LOD Group does nothing without one. Invalid values (an increasing list, a bias of 0) are refused like other fields.

Fog Volume (FogVolume): Add Component > Fog Volume adds a local fog region to the entity, a box or sphere sized by its Transform. Its Inspector section: Shape (Box / Sphere), Density (>= 0), Albedo (color), Edge Falloff (0..1) and Height Falloff (optional, >= 0), each edit an undo step. While the entity is selected the Scene view outlines the box or sphere in yellow. It only shows while the scene's volumetric fog is on (Window > Post Processing > Volumetric Fog).

World UI (WorldUI): Add Component > World UI floats a game GUI over the entity in Play. Its Inspector section: Path (a combo of the project's .rml files and None; a path that is not among them shows as (missing) with the red warning No file "..." in the project: kept as-is, and Play logs it once and draws nothing for it), Visible, Mode (Overlay / World), Facing and Pixels Per Meter (greyed out unless Mode is World), Offset (meters, in the entity's local space), Width (px) and Height (px) (at least 1), Max Distance (m) (0: unlimited), Occlude and Interactive (mouse hover and clicks in Play, World-space UI), each edit an undo step. The Game view draws panels during Play only, never while Stopped; the Scene view previews them always (below).

World UI preview: the Scene view draws every WorldUI panel from the editor camera, while Stopped and in Play, as the Game view would: Overlay panels flat at their pixel size over their anchor, World panels as quads in the scene. It shows each document's static content (what the .rml says: no Lua runs while Stopped, and Lua's kast.gui writes in Play reach only the Game view). Inspector edits (Path, Mode, Facing, Offset, Width, Height, Pixels Per Meter, Max Distance, Visible) show the next frame. Panels take no input there: clicks select what is under them and the gizmo works over them. A selected WorldUI entity shows its anchor as a yellow (#ffcc00) cross on a line up from the entity and its panel's outline: the quad's in World mode, the panel's screen rectangle (drawn over it) in Overlay mode. The Scene toolbar's World UI box (after Post) hides and shows the preview; it starts on (--no-scene-world-ui starts it off). A missing .rml shows nothing and is not logged (the Inspector warns). World UI documents have no hot reload: the editor doesn't watch their .rml / .rcss files.

New Lua Component... (first item of the Inspector's Add Component popup) creates a Lua component and adds it to the selected entity in one step. Type a name (e.g. PlayerHealth) and choose Create (or Enter; Esc cancels): it writes the New from Template definition with that type name to <project>/components/<snake_case>.lua (player_health.lua; HTTPServer -> http_server.lua), loads it and adds it. The name is checked as you type, with the reason shown in red and Create disabled: empty, not an identifier (letters, digits, _; not starting with a digit), a built-in name, the name of any listed definition (even one in error), or a file that already exists (case-insensitive). It never overwrites a file. Disabled with the same tooltips as New from Template.

Hierarchy: click to select, right-click for Create / Rename (F2) / Duplicate (Ctrl+D) / Delete (Del). Creating from an entity's menu makes the new entity its child; right-click empty space creates at the root. Drag an entity onto another to reparent it (world transform kept; dropping onto a descendant is rejected), or onto empty space to move it to the root. The GameObject menu creates at the root.

Inspector: the name, then one collapsible section per component, with widgets generated from the component's registered fields (rotation as Euler degrees, colors as color pickers, enums as combos). The x on a section header removes that component (not shown for Transform); Add Component lists the registered types the entity doesn't have.

Particles (ParticleEmitter): GameObject > Particle System (also in the Hierarchy's Create menu) creates an entity named "Particle System" with a Transform and a default ParticleEmitter (an upward cone of soft white particles), selected, as one undo step like the other GameObject entries. Emitters play in the Scene and Game views in edit mode too (a preview; nothing about it is saved). The selected entity's emitter shows its emission shape as orange (#ffaa00) lines in the Scene view, in the entity's transform (scale included): a cone's base disc and its spread over the first metre (a cylinder at Cone Angle 0), a sphere's three circles, or the box's twelve edges. The ParticleEmitter section starts with a Preview (not saved) row: Restart kills the live particles and plays the cycle from the start (even with Play On Start off), Pause / Resume freezes and continues the simulation, and N alive is the live count, the same CPU estimate as kast.particles.alive (Alive count). These work in edit mode and during Play, are not undo steps and never mark the scene dirty. Field edits are ordinary undoable edits and show in the preview at once.

Reflection probes (ReflectionProbe): GameObject > Reflection Probe (also in the Hierarchy's Create menu) creates an entity named "Reflection Probe" with a default probe (a 10 x 4 x 10 m box, resolution 128, not baked), selected, as one undo step. The selected probe's box shows as yellow (#ffcc00) lines in the Scene view, axis-aligned around its position (rotation and scale don't apply to it). Its Inspector section: Box Size (floored at 0.01 m per axis), a Resolution combo (64, 128, 256), Intensity, Priority, Baked Path, then a Bake row: the status (Not baked, Baked, or in red why its files can't be used, e.g. cannot read the file or baked at 64, but its resolution is 128 (bake it again)) and the Bake button, which renders the probe's cube from the scene, writes <scene-name>_probes/<entity id>.ktx and .json next to the scene, sets Baked Path and marks the scene dirty (not an undo step). Bake is disabled during Play and until the scene is saved in a project (the tooltip says why); Window > Lighting's Bake All Probes bakes every probe of the scene.

Global illumination (Lightmaps and GI): Mesh Renderer and Model Renderer have a GI Mode combo (Off, Static, Dynamic; a skinned model's Static is greyed out with a tooltip) and Lightmap Scale (floored at 0.01); every light has a Bake Mode combo (Realtime, Indirect, Full); Terrain has Bake Lightmap. All are ordinary undoable fields. Window > Lighting's Bake Lightmaps bakes the scene in the background (Lighting panel).

VoxelGI volumes (VoxelGI): Add Component > Voxel GI on an entity (usually an empty one centered in a room). The selected volume's voxel grid shows as orange (#ffaa00) lines in the Scene view, axis-aligned around its position (rotation and scale don't apply to it; the box is whole voxels, so a little past Box Size on its shorter axes). Its Inspector section: Box Size (floored at 0.01 m per axis), a Resolution combo (64, 128, 256 voxels along the longest axis), Intensity, a Quality combo (Low, Medium, High), Priority, Enabled, Baked Path, then a Bake row: the status (Not baked, Baked, Out of date in #ffcc00 once a Static mesh moved or the box changed, or in red why its files can't be used, e.g. baked at resolution 128, the volume is 64 (bake again), logged when it changes) and the Bake button, which voxelizes this volume in the background (a progress bar and Cancel while it runs), writes <scene-name>_voxelgi/<entity id>.kvox and .json next to the scene, sets Baked Path and marks the scene dirty (not an undo step). Bake is disabled during Play and until the scene is saved in a project; the field edits are ordinary undoable edits; Intensity, Quality, Priority and Enabled apply at once, the rest at the next bake.

Play mode (the Play / Pause / Stop icon buttons at the right of the Scene / Game tab bar, whichever tab is shown, or of the Scene title bar while it floats; hidden when the bar is too narrow. Or Ctrl+P): Play snapshots the scene in memory and runs the systems (e.g. Rotator) every frame; Pause holds them, Play or Pause again resumes; Stop restores the snapshot exactly (scene, unsaved-changes flag, selection by id; the editor camera stays where it is). Play (from stopped, including --play) brings the Game tab to the front; Stop brings the Scene tab back; Pause and resume leave the tabs alone. While playing, the Scene panel has an orange border and the title says (Playing) or (Paused). Edits during Play are allowed and are discarded on Stop; they never mark the scene dirty. File New/Open/Save/Save As are disabled during Play; Exit or closing the window stops Play first. A Lua kast.loadScene switch replaces the running scene: Hierarchy, Inspector, Scene, Game and the Systems panel status show the new scene, the selection is cleared, the editor camera stays, and the title shows (Playing: <scene>) / (Paused: <scene>). The edited scene's file and path are never touched; Stop restores the pre-Play scene, path, project, dirty flag and selection however many switches happened.

GUI Builder (GUI Hierarchy, GUI Inspector, GUI Style, GUI Preview): double-click a .rml in Assets. See GUI Builder.

File: New (Ctrl+N), Open... (Ctrl+O), Save (Ctrl+S), Save As... (Ctrl+Shift+S), Exit. Projects are created and opened from the Project Manager, not the editor. The title shows Kast Editor - <project> - <scene> with an active project, Kast Editor - <scene> without, plus * when there are unsaved changes; New, Open, Exit and closing the window ask Save / Don't Save / Cancel first. Opening an invalid scene shows an error and keeps the current scene. Moving the camera does not mark the scene dirty, but Save stores the current camera pose.

  • Save / Save As never rewrite systems paths. If Save As moves a scene with systems into another project or out of any project, the Console warns that its system paths may no longer resolve.
