Run

build\release\kast_editor.exe
Flag Effect
--frames N Run N frames, then quit cleanly (exit 0).
--screenshot <path.png> With --frames: capture the backbuffer after frame N, write a PNG, then exit. Exit 1 if it can't be written.
--size WxH Initial window size (default 1280x720; Project Manager 1024x600).
--window-pos X,Y Initial window position: the top-left corner in desktop coordinates (negative = a monitor left of or above the main one). Without it, the environment variable KAST_WINDOW_POS (same format, or secondary for the first display that isn't the primary one, as ctest sets it; a bad value is a warning and ignored), else wherever Windows puts it. The editor, the Project Manager and the player log Window at X, Y on display '<name>' when either is set.
--ui-scale F Force UI scale F (positive number, clamped to 0.75–3.0) instead of the monitor's display scale.
--project <dir> Open <dir>/project.kast at startup (its startScene, else a new Untitled scene). Exit 1 if it is missing or invalid. With --scene, the scene opens afterwards and its own project (walk-up) wins. Once the editor window opens, the project is added to the top of the recent-projects list.
--scene <path> Open this .scene at startup (inside a project or not). Exit 1 if it can't be loaded.
--save-scene <path> With --scene or --project: save the startup scene to path and exit 0 without opening a window. Exit 1 on write failure.
--projects-file <path> Use this recent-projects list instead of %APPDATA%\Kast\Editor\projects.json (Project Manager and editor; the Project Manager passes it on to the editor it starts). Tests always set it.
--select <id> Select the entity with this persistent id at startup (shows it in the Inspector). Exit 1 if there is none.
--play Enter Play mode right after the startup scene loads. Works with --frames, --screenshot, --scene, --select.
--select-network-entity With --play: select the first replicated clone (an entity with NetworkEntity) as soon as one exists, so a screenshot shows it in the Inspector (see Replication).
--add-component-popup Open the Inspector's Add Component popup for the --selected entity (after the first 10 frames, once the layout has settled).
--new-component-prompt <Name> Open the Inspector's New Lua Component modal at startup with Name prefilled (validation shown). Creates nothing by itself.
--new-state-machine-prompt <Name> Open the State Machines panel's New State Machine modal at startup with Name prefilled (validation shown). Creates nothing by itself.
--new-component <Name> Create Lua component <Name> (as the modal's Create does) and add it to the --selected entity at startup. On failure logs an error and keeps running.
--launcher Run the Project Manager (what no --project/--scene/--save-scene/--build already does), e.g. with --frames 120 --screenshot.
--new-project <name> <dir> Project Manager: open its New Project modal at startup with Name and Directory prefilled (quote values with spaces), e.g. for --frames 120 --screenshot. Creates nothing by itself.
--launcher-open <dir> Project Manager without a window: open <dir> exactly as double-clicking it does (add it to the top of the list, start kast_editor --project <dir>), wait for that editor and exit with its exit code; exit 1 if the project is invalid or the editor can't start.
-- <flags...> Project Manager: every argument after -- is appended to the editor it starts, e.g. --launcher-open tests/project -- --frames 120 --screenshot out.png makes that editor take a screenshot and exit.
--build <dir> With --project: build that project's game into <dir> (see Build) and exit without opening a window or any dialog. Exit 0 on success, 1 on failure (no --project, invalid startScene, ...). Does not remember the folder.
--open-menu <Name> Open that main menu (e.g. Build) after the first 10 frames, for screenshots; with --focus-panel after 20 frames, once the panel took the focus (e.g. --focus-panel Zone --open-menu Edit shows the zone's undo step).
--open-build-settings With --project: open the Build > Build Settings modal after the first 10 frames, for screenshots. Writes nothing by itself. Without --project it is an invalid argument.
--open-online-settings With --project: open the Build > Online Services modal after the first 10 frames, for screenshots. Writes nothing by itself. Without --project it is an invalid argument.
--focus-panel <Window> Bring that editor window (e.g. Events, "State Machines", "GUI Preview") to the front of its dock after the first 10 frames (with --open-graph: 3 frames after the graph's panels took the focus, e.g. --focus-panel Scene to watch a live update), for screenshots. Lighting, "Post Processing", Physics, Mixer, Network and Online also open those hidden panels.
--zone-section <Name[,Name...]> Expand these sections of the Zone tab (e.g. Map,Problems) and collapse the others after the first 10 frames, for screenshots; pair it with --focus-panel Zone to bring the tab to the front.
--zone-tool <Tool> Make that Zone tab tool active after the first 10 frames, as its button does: Raise, Lower, Flatten, SetSpawn (Place on terrain), AreaRect, AreaPolygon, PlaceSpawn, PathPoints, PlaceObject or Scatter. Pair it with --sim-mouse (without --play it acts on the Scene view) for tests and screenshots of the tools: a click or drag uses the tool, a hover shows the brush ring.
--zone-select <id>|object:tx,tz,i Select that zone area or spawn (by id), or the zone object at index i of tile tx, tz's objects file, in the Zone tab after the first 10 frames, for screenshots.
--bake Press the Zone tab's Bake Navmesh after the first 10 frames (see Bake). The --frames count holds until kast_mapbake ends, then N frames drawn while kast_mapbake ran is logged; exit 1 if the bake fails. With --headless: bake without a window, waiting for it.
--mapbake <exe> The kast_mapbake.exe Bake Navmesh runs, for this run only (the Bake section's setting is not changed).
--file-save File > Save (as Ctrl+S: the scene, then a zone with unsaved edits) after the first 10 frames, for tests.
--no-scene-post Start with the Scene toolbar's Post box off (scene without post effects).
--assets-menu <path>\|/ Open that Assets entry's context menu (/ = the panel background) with its Create submenu open, for screenshots.
--assets-create system\|fsm\|gui\|material\|shader\|shadergraph:<folder> Run Assets > Create > Lua System / State Machine / GUI / Material / Shader / Shader Graph in that project folder (empty = the root) after the first 10 frames, as the menu does (the new file's rename starts).
--material-set <field>=<json> (repeatable), --material-undo N, --material-redo N With --assets-select of a .mat: set that field or .kshader / .kshadergraph param as an Inspector edit does (saved, one undo step each, in order), then Undo N times, then Redo N times, at frame 11. For tests of the material Inspector's undo.
--open-gui <file.rml> Open that .rml in the GUI Builder at startup (relative paths: to the project, else the working directory) and bring its four panels to the front.
--gui-select <id> With --open-gui: select the element with this id (logs an error if there is none).
--gui-preview-size WxH Add WxH to the GUI Preview's resolutions and pick it.
--gui-pick X,Y With --open-gui: click the GUI Preview at (X, Y) in preview pixels after 16 frames, as the mouse does, and log --gui-pick X,Y selected '<id>'.
--gui-add Panel\|Text\|Button\|Toggle\|Slider\|Dropdown\|Spinbox\|Progress With --open-gui: add that element as the GUI Hierarchy's + buttons do (into the selected Panel, else <body>), after 17 frames.
--gui-set-prop <name>=<value> With --open-gui: set a widget property of the selection (min, max, step, value, data-value, checked = true / false, label) as one GUI Inspector edit step, after 17 frames; logs --gui-set-prop name="value" on '<id>', or an error if the selection has no such property.
--gui-set-attr <name>=<value> With --open-gui: set (empty: remove) that attribute of the selection (--gui-select) as one GUI Inspector edit step, as typing it does, after 17 frames; logs --gui-set-attr name="value" on '<id>'. The value can't hold spaces (the test scripts split arguments on them).
--gui-undo <N>, --gui-redo <N> With --open-gui: Edit > Undo on the open GUI N times, then Redo N times, after 18 frames (after --gui-add). Each logs Undo <step> / Redo <step>. With --open-gui, --open-menu opens its menu after 20 frames.
--gui-save With --open-gui: save the GUI as its Save button does, after 19 frames.
--drop-model <path> Add this project model file (project-relative) as dropping it from the Assets panel on the Scene view does: an entity at the origin named after the file, with a ModelRenderer and, if the model has clips, an Animator (selected).
Prefab steps (Prefabs): run at startup in command-line order, after --select and before --save-scene, so they work headless with --save-scene and before a window's first frame. A step that fails logs why and exits with 1. IDs are PersistentIds; paths are project-relative.
--create-prefab <folder>|/ Hierarchy > Create Prefab on the --select entity: writes <folder>/<name>.prefab (/ = the project root) and makes the entity an instance of it.
--drop-prefab <path>[,<parentId>] Drop the prefab on the Hierarchy: a new instance at the root, or as the last child of parentId (selected).
--drop-prefab-view <path>,<u>,<v> Drop the prefab on the Scene view at (u, v), 0–1 from its top-left: a root instance where that ray of the scene's editor camera (a 16:9 view) first hits a mesh, else crosses y = 0, else 10 m along it (selected).
--set-field <ID>,<Component>.<field>,<json> Set one field as an Inspector edit does, e.g. 5,PointLight.range,4 (an override on an instance entity); <ID>,Name,"text" renames.
--prefab-revert <spec> Inspector Revert. spec is ID (Revert All, on an instance root), ID:Component, ID:Component.field, ID:Name or ID:#local (a deleted child by its prefab-local id, on the root).
--prefab-apply <spec>[@<hop>] Inspector Apply, the same specs (ID = Apply All). @hop picks the nesting level written: 0 (default) the outermost prefab, 1 the one nested in it, ...
--prefab-unpack <ID> Inspector Unpack on an instance root.
--edit-prefab <path> Open the prefab in prefab edit mode, as double-clicking it in Assets does; later steps act on the prefab.
--prefab-save In prefab edit mode: Save (Ctrl+S), writing the .prefab.
--prefab-back In prefab edit mode: Back to the scene without a prompt (unsaved prefab changes are discarded), refreshing its instances.
--scene-undo <N>, --scene-redo <N> After the steps above: Edit > Undo on the scene (or the open prefab) N times, then Redo N times, e.g. to screenshot a --set-field undone. Each logs Undo <step> / Redo <step>.
--assets-delete <path> Open the Assets Delete Asset confirmation for this entry after 12 frames, for screenshots (for a prefab it lists the scenes and prefabs using it).
--prefab-back-prompt In prefab edit mode (--edit-prefab): press the Hierarchy's Back after 12 frames, so unsaved prefab changes (e.g. from --set-field) show the Save / Don't Save / Cancel prompt, for screenshots.
--inspector-apply-menu <Component>.<field> Open the --select entity's override context menu of that field (or Component, its header) after 12 frames, with the Apply submenu open when the entity is nested, for screenshots. The field must be overridden.
--fixed-dt <seconds> Play and the edit mode preview (animation, particles) advance this many seconds every frame instead of the real frame time, so screenshots of moving scenes come out the same every run (e.g. --fixed-dt 0.016666667 with --frames 120: exactly 2 seconds). Tests use it.
--no-vsync Present frames as fast as possible instead of at the display's refresh rate (with --log-fps, to measure headroom).
--no-instancing The Scene and Game views draw every mesh with its own draw call instead of batching same-mesh, same-material draws into GPU-instanced ones (see Instancing and culling). For comparing output and performance.
--no-culling The Scene and Game views draw every mesh in every pass (camera, shadow cascades, point light cube faces) instead of only those whose bounds are inside that pass's view (see Instancing and culling). For comparing output and performance.
--no-audio-device Play sound on miniaudio's null backend (silent), as if there were no output device: one warning, everything else behaves normally. Tests use it.
--log-fps Log once a second: frames per second (vsync caps it at the display's refresh rate), the editor's CPU time per frame and bgfx's GPU frame time, and the draw call count.
--world-address <host:port> Editor Play only: every kast.world.connect goes to this address instead of the realm's (see kast.world). Not a player flag. Wins over the Online panel's override.
--settings-file <file.json> Use this per-user editor settings file instead of %APPDATA%/Kast/Editor/editor_settings.json (tests use a fresh one per run).
--online-login-env The Online panel's test login at startup, from the environment variables KAST_ONLINE_EMAIL and KAST_ONLINE_PASSWORD (never a password on the command line, where logs would show it); with --play, Play starts once the login has answered. See Editor tooling.
--online-compose up\|down\|ps Press the Online panel's Start, Stop or Status at startup (e.g. with --log-fps to watch the frame rate while the stack starts).
--sim-mouse <frame,button,dx,dy,wheel[,sx,sy[,hold]]> With --play (without it: the Scene view's image instead, e.g. for --zone-tool, or the Shader Graph canvas that covers it with --open-graph): on frame frame, move the mouse to the center of the Game panel's image (or sx, sy pixels from it), press button (left, right or none) and turn the wheel by wheel notches; the next frame move it by dx, dy pixels (with none: a hover there, held until the run ends), then keep the button down there for hold frames (default 1) and release it (a game GUI sees a drag and drop; the Shader Graph canvas needs a hold of a few frames to accept a link). Each run logs --sim-mouse: press at X,Y in window points. left+shift / right+shift also hold Shift from the press until after the release. Synthetic SDL events, so kast.input and the game GUIs get them as from a real mouse while the Game panel is focused. kast.input.setCursorLocked is not applied to the window in such a run, so the real cursor is never grabbed. Example: --sim-mouse 600,left,240,-40,0.
--sim-key <frame,[ctrl+]key> With --play or --open-graph, repeatable: on frame frame press key (an SDL key name: B, Escape, Tab, Delete) on the Game panel (with --open-graph: the focused panel, e.g. the canvas); ctrl+ holds Ctrl with it (ctrl+C, ctrl+V; it types nothing), with the character it types (a letter or digit, lower case) for a focused game GUI text field, and release it two frames later. Synthetic SDL events, like --sim-mouse. Example: --sim-key 600,B.
--sim-on-log <text> With --sim-mouse or --sim-key: their frames count from the first log line containing text instead of from the start, for input that must wait for something in the game (a corpse to right-click). Example: --sim-mouse 30,right,0,0,0 --sim-on-log CLICK.
--screenshot-on-log <frames,text> With --frames N (and usually --screenshot): end the run, taking the screenshot, frames frames after the first log line containing text (everything after the first comma); N stays the upper bound if it never appears. For waits that depend on the network or a server, e.g. --screenshot-on-log 30,Bat dies. Requires --frames.
--gui-click <id> With --play: click the game GUI element with this id (topmost visible document holding one) after 10 frames, as the mouse does; logs an error if there is none.

Without --project, --scene, --save-scene or --build, kast_editor runs the Project Manager instead of the editor. Editor-only flags (--select, --play, --select-network-entity, --add-component-popup, --new-component[-prompt], --new-state-machine-prompt, --open-menu, --open-build-settings, --open-online-settings, --focus-panel, --zone-section, --zone-tool, --assets-*, --open-gui, --gui-*, --open-graph, --graph-*, --zone-select, --bake, --mapbake, --file-save, the zone edits) then are invalid arguments, as are Project Manager flags (--launcher, --new-project, --launcher-open, --) together with the editor's.

Shader Graph

The Shader Graph panels' edits, for tests and screenshots. They need a project (--project, or a --scene inside one) and --open-graph. --open-graph opens the graph at startup; every other flag below (and a later --open-graph) is a step: the steps run in command-line order at frame 17, through the same model the panels edit, each one undo step on the graph's history, and the canvas then zooms to fit the graph. Node ids are those in the file; pins are N.pin (12.out, 1.EMISSION). A step that fails logs [error] --graph-... <value>: <why>. In PowerShell, quote values with commas ('7.out,6.b'), which it would otherwise split.

Flag Effect
--open-graph <file.kshadergraph> Open the graph in the Shader Graph, Graph Inspector and Shader Preview panels (relative paths: to the project, else the working directory) and bring them to the front. Opening compiles it (for the preview). With unsaved changes, a later --open-graph asks Save / Discard / Cancel.
--graph-add <type>[,x,y] Add a node of that type id (node reference) at canvas position x, y (default: the view's center); logs --graph-add <type>: node N with its new id.
--graph-link <N.pin,M.pin> Link output N.pin into input M.pin (replacing that input's link). A link Kast refuses logs [warn] --graph-link ... refused: <why> and shows the red link and why on the canvas for 5 s, as a refused drag does.
--graph-unlink <N.pin> Remove the link into input N.pin.
--graph-select <N[,M...]>, --graph-delete <N[,M...]> Select those nodes, or delete them (with their links).
--graph-set <N.setting=json> Set a node's setting as the Graph Inspector does, e.g. 12.value=[1,0,0], 4.mask="zyx", 9.param="speed". In ctest arguments, which split on spaces, write a space in a JSON string as .
--graph-comment <title,x,y,w,h> Add a comment frame.
--graph-paste <x,y> Copy the nodes of the last --graph-select and paste them with their top-left at x, y (fresh ids, their links kept), then select them; logs --graph-paste x,y: nodes 12,13,14.
--graph-undo <N>, --graph-redo <N> Undo, or redo, N steps of the graph's history (each logs Undo <step> / Redo <step>).
--graph-save Save the graph as its Save button does.
--graph-add-menu <N.pin>\|/ Open the add menu at the view's center: filtered to the nodes that link to that pin, or (/) all of them.
--graph-preview sphere\|cube\|plane Show the Shader Preview on that mesh.
--graph-view-code Open the Shader Preview's View generated code window (the .kshader text the library compiles).

Canvas gestures run through --sim-mouse (offsets from the Scene view's image center, which the canvas covers: 800,352 in the 1600x900 default layout) and --sim-key, e.g. a link dragged from a pin and held over another (--sim-mouse 30,left,201,-164,0,86,160,8), a box selection then --sim-key 45,Delete, or --sim-key 45,ctrl+C --sim-key 55,ctrl+V. The canvas logs what they did (Shader Graph: linked 11.out to 1.EMISSION, deleted 3 nodes, copied 3 nodes, pasted 3 nodes at x,y, add menu, N entries that link from 11.out), and a live update logs Shader Graph: '<path>' live-updated X s after the edit (N frames drawn while it compiled) (or live-update failed ...), which --screenshot-on-log 10,live-updated can wait for. Example: kast_editor --scene tests/project/shader_graph_demo.scene --open-graph shaders/graph_demo.kshadergraph --focus-panel Scene --graph-add constant_vec3,900,500 --graph-set 12.value=[1,0,0] --graph-link 12.out,1.EMISSION turns the demo's meshes red in the Scene view without saving.

Screenshots are compared with kast_self_check --diff-png and read with --probe-png; see Tests: image checks.

Model Preview

With --project; see Model Preview.

Flag Effect
--preview-model <path> Open the Model Preview panel on that model (project-relative, e.g. models/cube.obj) at startup, as double-clicking it in Assets does, and bring it to the front.
--preview-clip <name> With --preview-model: play that clip instead of the default one. A name the model doesn't have logs Model Preview: '<path>' has no clip '<name>'; playing '<default>'.

Zone edits

The Zone Builder's edits, for tests and scripts. They need a project (--project <dir> with a project.kast, or a --scene inside one) and run in command-line order before the window opens, each one undo step. --map or --new-map comes first: it opens that map of the project as the zone. The window then shows it, the scene's first Terrain entity pointing at it (one is added if there is none) and the camera framing it. A failed edit or save logs why and exits 1. Positions are world metres on the ground (y follows the terrain), headings radians, tiles tx,tz. The full list is also in the editor's invalid-argument message.

Flag Effect
Map
--map <folder> Open maps/<folder> of the project.
--new-map <folder>[,W,H[,id]] A new map (named after its folder) of W x H tiles (default 2 x 2, 1-8 each) with that id (default: the lowest unused). Nothing is written until --save-zone.
--map-id N The map's id.
--material <path> The map's material (a project-relative .mat; empty = the default material).
--set-spawn x,z[,heading] The player spawn.
--add-tile tx,tz, --remove-tile tx,tz Add a tile (its edges take its neighbours' heights); remove one (not the last; its files are deleted on save).
Terrain
--falloff F The brush falloff (0..1) for the following --sculpt / --flatten.
--sculpt x,z,radius,metres A Raise stroke of that radius at (x, z); negative metres lower.
--flatten x,z,radius,height[,fraction] A Flatten stroke toward height, fraction (default 1) of the way.
--height-range min,max Apply a new height range (world heights kept, samples outside it clipped).
--import-png tx,tz,file, --export-png tx,tz,file Import / export that tile's heights as a 257 x 257 16-bit grayscale PNG.
--generate-heights seed[,scale,octaves,persistence,lacunarity] Generate heights; --generate-heights 7 uses the default scale, octaves, persistence and lacunarity.
--terrain-colors pct,r,g,b,pct,r,g,b... The Height colors: 4 numbers per stop (at least 2 stops): the position in % of the height range, then red, green and blue 0..1, e.g. 0,0,0,1,100,1,0,0 for blue at the bottom and red at the top.
--create-terrain-material Create texture & material.
Areas and spawns
--add-area id,priority,x0,z0,x1,z1 A rectangle area.
--add-polygon id,priority,x,z,x,z,x,z... A polygon area (at least 3 points).
--area-parent id,parent The area's parent area.
--area-portal id,map,x,y,z,heading Make the area a portal to map id map, arriving at (x, y, z) facing heading.
--move-area-vertex id,i,x,z, --delete-area id Move vertex i of the area; delete the area.
--add-spawn id,npc,x,z[,heading[,respawnSec]] A spawn of NPC npc (respawn seconds, default 60; -1 = never).
--move-spawn id,x,z, --delete-spawn id Move (across tiles too) or delete a spawn.
--add-path spawnId,wait,loop,x,z,x,z... A patrol path <spawnId>_path for the spawn: wait seconds at each point, loop 1 (loop) or 0 (walk back).
Objects
--add-object type,prefab,x,z[,yaw[,scale[,box,hx,hy,hz|cylinder,r,h]]] A zone object: visual, obstacle or interactable, a project-relative prefab, a shape.
--set-interactable id,range,event[,name[,data]] Interactable id's fields; data is a JSON object, the rest of the value, commas and all (--set-interactable 1,3,shrine.activated,Meadow Shrine,{"message":"Hi"}).
--move-object tx,tz,i,x,z, --delete-object tx,tz,i Move or delete the object at index i of tile tx, tz's objects file (--move-object 0,0,2,300,40).
--scatter x,z,radius,count,seed,scaleMin,scaleMax,prefab[+prefab...] One Scatter stroke of one dab, with a fresh seed (random yaw).
--erase-visuals x,z,radius Remove every visual in the circle.
Undo, checks and saving
--undo, --redo Undo / redo one step of the map's history (exit 1 if there is none); logs Undo <step> / Redo <step>.
--validate Check the zone as a save does; any problem fails the run. Writes nothing.
--save-zone Save the zone (any problem blocks it: nothing written, exit 1).
--expect-save-fail Save the zone and fail the run if the save succeeds (tests of blocked saves).
Run
--headless Run the zone edits (and --bake, waiting for it) and exit without opening a window.
--no-recycle Zone saves delete files for good instead of sending them to the Recycle Bin (the tests use it).
--focus x,z,distance Point the Scene camera at (x, z) on the zone's ground from that distance.
--prompt-remove-tile tx,tz Open the Zone tab's remove-tile confirmation for that tile after 12 frames, for screenshots. Removes nothing by itself.
--sculpt-loop A brush circling the map's centre raises and lowers it every frame, outside undo (with --log-fps and --no-vsync: the sculpting benchmark).

The Zone UI flags --focus-panel Zone, --zone-section, --zone-tool, --zone-select, --bake, --mapbake and --file-save are in the table above.

Invalid arguments exit with code 2; init failures (SDL, window, bgfx) log the reason, show a message box, and exit 1.
