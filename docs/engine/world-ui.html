World-space UI

A WorldUI component floats a game GUI (an .rml document, styled and scripted as in Game GUI) at its entity: nameplates, health bars, signs. Each WorldUI entity gets its own document instance, even when several entities use the same .rml, and Lua addresses one by its entity. Like UI Documents, they are drawn in Play only: in kast_player and in the editor's Game view while playing or paused, never while Stopped. Code: engine/world_ui.h (kast::WorldGui, owned by kast::SceneGui).

This page covers Overlay mode. World mode (documents drawn as textured quads in the 3D scene, with Facing and Pixels Per Meter), mouse input on panels and floating text come in later phases: until then a World-mode WorldUI draws nothing and Interactive does nothing.

The WorldUI component

World UI in the Inspector (Editor controls). Every field is saved; a scene file may leave out any field but path and visible (it then has its default), and scenes from before WorldUI load unchanged.

Field (JSON)DefaultMeaning
path""Project-relative .rml (saved as an asset reference). Empty: nothing is drawn.
visibletrueOff: the panel is hidden (its document stays loaded, keeping what Lua wrote).
mode"overlay""overlay" or "world" (not drawn yet).
facing"billboard"World mode only: "billboard", "yawOnly" or "fixed".
offset[0, 2, 0]The anchor, in meters in the entity's local space (its world matrix applies, scale included).

pixelsPerMeter256World mode only (at least 1).

"WorldUI": { "path": { "id": "...", "path": "ui/nameplate.rml" }, "visible": true, "offset": [0, 1.4, 0], "width": 96, "height": 32 }

Overlay mode

Every frame the anchor is projected through the camera the game renders from (the first Camera entity): the document is drawn screen-space at a constant pixel size, centered horizontally on the anchor with its bottom edge on it. It is hidden when the anchor is behind the camera or off the view, beyond maxDistance, or occluded. Panels are drawn far to near, so a nearer panel covers a farther one where they overlap, and all of them are drawn under the screen GUIs (UI Documents), so a HUD stays on top of nameplates. The document's <body> is given display: block, position: absolute and the component's size; style its content as usual (RmlUi has no default styles: blocks need display: block).

<rml>
<head>
    <style>
        body { font-family: Roboto; font-size: 18px; color: #000000; }
        .plate { display: block; width: 100%; height: 100%; background-color: #ff00ff; text-align: center; }
    </style>
</head>
<body><div id="plate" class="plate"><p id="name">Name</p></div></body>
</rml>

GUI prefabs, rich text (<p class="rich">), the default widget style, effects and project fonts work as in UI Documents. Data models (data-model), clicks and hot reload of the files are not supported on WorldUI documents yet.

Occlusion

With occlude on, a ray is cast through the physics world from the camera to the anchor; the panel is hidden if it hits a body before the anchor. Bodies of the entity itself, its ancestors and its descendants (e.g. a character's own capsule) and trigger colliders are skipped. Why physics and not the depth buffer: the answer is for the frame being drawn (a depth read-back lags a frame or more) and it costs one ray per panel otherwise shown. The catch: only colliders occlude. A wall with a Mesh Renderer but no Collider does not hide a panel behind it; give walls that should hide nameplates a (static) Collider. Without a physics session (none outside Play) nothing occludes.

Lua

The kast.gui functions that act on one document's element take an entity id first to act on that entity's WorldUI document only:

Screen GUIs (UI Documents)One entity's WorldUI
kast.gui.setText(id, text)kast.gui.setText(entity, id, text)
kast.gui.setRichText(id, text)kast.gui.setRichText(entity, id, text)
kast.gui.setVisible(id, visible)kast.gui.setVisible(entity, id, visible)
kast.gui.setAttribute(id, name, value)kast.gui.setAttribute(entity, id, name, value)
kast.gui.setValue(id, value)kast.gui.setValue(entity, id, value)
kast.gui.value(id)kast.gui.value(entity, id)

The entity form is used when the call has one argument more than the plain form and the first is a number (an entity id, as kast.query returns); every other call is the plain form, with its errors as before (kast.gui.setText(5, "x") still raises id must be a string). An id that names no entity raises invalid entity id. The plain forms never touch WorldUI documents. Writes are kept per entity like setText's: made in init, before the document has loaded, they apply when it does; they are forgotten when the next scene's systems start.

for e in kast.query("WorldUI") do
    kast.gui.setText(e, "name", "Guard")             -- this entity's panel only
end
kast.gui.setAttribute(boss, "plate", "class", "plate elite")
kast.gui.setVisible(boss, "hp", false)

Errors

A missing .rml (or one with RmlUi errors) logs World UI document 'ui/x.rml' not found (or has errors) once per path, however many entities use it, and those entities draw nothing; every other panel still draws and Play goes on. The Inspector shows a path that is not in the project as (missing) with a warning.
