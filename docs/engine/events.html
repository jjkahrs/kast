Events

Lua systems and engine C++ code exchange named events with plain-data payloads through one event bus per Play session (engine/event_bus.h, built on entt::dispatcher; owned by LuaSystems, so editor Play and kast_player both have it). Publishing only queues an event; the queue is delivered once per frame at a fixed point.

local handle
return {
    init = function()
        handle = kast.subscribe("health.empty", function(event)  -- event: a fresh copy of the payload
            kast.log("empty: " .. event.id)
        end)
    end,
    update = function(dt)
        kast.publish("heartbeat", {time = dt, tags = {"a", "b"}})
        if kast.input.keyDown("U") then kast.unsubscribe(handle) end
    end,
}
Function Returns Notes
kast.publish(name [, payload]) — Queues an event. name: a non-empty string. payload: plain data (below); omitted or nil is JSON null. The payload is deep-copied now: later changes to the table don't affect the event.
kast.subscribe(name, fn [, options]) handle fn(payload) is called for every later event named exactly name (no wildcards). name: a non-empty string, fn: a function, options: a table or nil. {replay = true}: also call fn at once (inside kast.subscribe) with the world connection's last world.* / server.* event of that name, if one came since world.connected (none after world.disconnected, or without Online Services). For a scene loaded after a one-time event its scripts still need, such as a server.* event sent on entering the world (Online Services, scene switches). An error in that call raises at the kast.subscribe line.
kast.unsubscribe(handle) — Stops deliveries at once, including the rest of the current drain. A handle already unsubscribed, or one owned by another system, is a no-op; any value that isn't a handle raises.

A wrong argument raises a Lua error at the calling line, and nothing is queued or subscribed.

Payloads are plain data: nil, booleans, finite numbers, strings, and tables of these. A table whose keys are exactly 1..n becomes a JSON array; one with only string keys becomes an object; an empty table is {}. Mixed or other keys ({1, x = 2}, {1, nil, 3}, {[0] = 1}, {[true] = 1}), functions, userdata, threads, cycles, NaN or infinity, and tables nested more than 32 deep raise at the publish call (payload.a.b: ... names the bad value). Integral numbers travel as JSON integers. Each subscriber gets its own fresh copy: mutating it affects no one else. JSON arrays arrive as 1-based sequences, objects as string-keyed tables; a null inside a payload arrives as nil (in an array that leaves a hole).

Delivery: the queue drains once per frame in LuaSystems::tick, after every Lua system's update and before a kast.loadScene switch is applied, so an event published in update reaches subscribers in the same frame. Events are delivered in publish order; each event goes to its subscribers in subscription order, C++ and Lua subscribers in one shared order. Events published while the queue drains (by Lua or C++ subscribers) are delivered next frame, so a subscriber that re-publishes can't loop within a frame. A subscription added during a drain takes effect from the next event.

Ownership: a Lua subscription belongs to the system whose code called kast.subscribe (from init, update, a subscriber or the file body). It is removed when that system is disabled (by any error), when it is hot-reloaded (the old instance's subscriptions go before the new file runs), and when the Lua state goes on Stop or a scene switch. The publisher recorded for a Lua event is the system's path as listed in the scene (scripts/health_events.lua).

Errors, Pause, Stop, scene switch:

  • A Lua subscriber that raises is logged with file:line and its system is disabled exactly like an update error (which also removes all its subscriptions until a successful hot reload). The event's other subscribers still run, and Play continues.
  • A C++ subscriber that throws is caught and logged (Event 'x': C++ subscriber failed: ...); delivery continues.
  • Paused: nothing is delivered; the queue is held until Play resumes.
  • Stop: queued events are discarded (including any published by shutdown). Play start resets the bus: queue, every subscription (C++ ones too), the history and the frame count.
  • kast.loadScene switch: undelivered events (published during that frame's drain or by the old shutdowns) are dropped and the old scene's Lua subscriptions go with its Lua state. C++ subscriptions and the history carry over.

C++ API (kast::EventBus, from LuaSystems::bus(); no Lua or ImGui dependency):

kast::EventBus& bus = lua.bus();
kast::EventBus::Subscription sub = bus.subscribe("health.empty", [](const nlohmann::json& payload) { /* ... */ });
bus.publish("door.opened", {{"id", 7}});   // publisher "C++"; delivered at the next drain
sub.unsubscribe();                          // or let the handle go out of scope (RAII, move-only)

drain() delivers (LuaSystems::tick calls it), dropQueued() discards the queue, reset() clears everything, and history() returns the last 500 delivered events (frame = drains since Play start, name, compact one-line JSON payload, publisher). A Subscription must not outlive its bus; after reset() it is a harmless no-op. Physics publishes the collision and trigger events.

Events panel (editor, tabbed with Console): the last 500 delivered events, oldest first, following new ones while scrolled to the bottom. Columns: frame, event name, compact payload, publisher (script path or C++). Clear empties it; the filter shows events whose name contains the text (case-sensitive). Play start clears it; it stays after Stop. --focus-panel Events brings it to the front for screenshots.

Sample: tests/project/events.scene runs scripts/health_events.lua (a heartbeat every 20 frames and, on frame 30, health.empty with {id, title} for every entity with Health; it changes nothing itself) and scripts/on_health_empty.lua (greys out the named entity's material with kast.setMaterialProperty).
