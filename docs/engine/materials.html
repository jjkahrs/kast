Materials

Meshes render with PBR metallic-roughness materials (glTF semantics) defined in .mat files: JSON, any folder of the project, referenced by MeshRenderer.material (project-relative). Every field but version is optional (default in brackets); unknown keys and invalid values make the file invalid.

{
  "version": 3,
  "baseColor": [0.8, 0.8, 0.8, 1],
  "baseColorTexture": "textures/checker.png",
  "metallic": 0,
  "roughness": 0.5,
  "metallicRoughnessTexture": "",
  "normalTexture": "textures/normal_bumps.png",
  "normalScale": 1,
  "occlusionTexture": "",
  "occlusionStrength": 1,
  "emissiveEnabled": false,
  "emissive": [0, 0, 0],
  "emissiveIntensity": 1,
  "emissiveTexture": "",
  "uvScale": [1, 1],
  "uvOffset": [0, 0],
  "alphaMode": "opaque",
  "alphaCutoff": 0.5,
  "cullMode": "back",
  "unlit": false,
  "shader": "",
  "params": {}
}

Versions: files are version 3. Version 1 (no fields after alphaCutoff) and version 2 (no shader / params) files still load, with the defaults below for every newer field; saving any material (the Inspector, Create > Material) writes version 3 with every field, in the order above. Other versions are invalid ("version" must be 1, 2 or 3).

  • baseColor linear RGBA 0–1 [0.8 grey, alpha 1], times baseColorTexture (sRGB; project-relative, empty = none).
  • metallic, roughness 0–1 [0, 0.5], times metallicRoughnessTexture (linear, glTF packing: G = roughness, B = metallic).
  • normalTexture [none] (linear, tangent space, glTF / OpenGL convention: +X right, +Y green = up in the image; DirectX-style maps need their green channel inverted first) bends the shading normal; normalScale (any finite number [1]) scales the sampled normal's X and Y, as glTF's normalTexture.scale. Without one (or if it fails to load) the normal is flat: the mesh shades exactly as without normal mapping. Tangents come from the mesh (see Shaders).
  • occlusionTexture [none] (linear, R channel) with occlusionStrength 0–1 [1]: ao = 1 + strength * (R - 1) multiplies the ambient light only (both ambient terms); direct light from the directional and point lights is unchanged. The same file can also be the metallicRoughnessTexture (a packed ORM texture: R = occlusion, G = roughness, B = metallic).
  • emissiveEnabled [false]: when on, emissive (linear RGB 0–1 [black]) times emissiveIntensity (≥ 0 [1]) is added after lighting (shows without lights); an intensity that lifts it above the bloom threshold glows. Older files with only emissive load with emission on if it is non-black, and channels above 1 move into the intensity. emissiveTexture [none = white] (sRGB) multiplies the emissive color and intensity (glTF semantics); it does nothing while emissiveEnabled is off.
  • uvScale (2 finite numbers [1, 1]) and uvOffset ([0, 0]): every texture of the material (base color, metallic-roughness, normal, occlusion, emissive, and the alpha-mask cutout in the shadow maps) samples uv * uvScale + uvOffset; textures repeat, so [4, 4] tiles them 4 times. One transform for all textures (no rotation, no per-texture transform).
  • alphaMode [opaque]: mask discards pixels whose alpha is below alphaCutoff [0.5]; blend draws after every opaque mesh, far to near by the mesh's world-space center (no per-triangle sorting), alpha-blended, depth-tested but not depth-written. additive draws in the same far-to-near pass (sorted together with blended meshes and particle emitters) and adds color * alpha to what is behind it (it can only brighten), depth-tested, not depth-written; fog fades it toward black rather than toward the fog color, as additive particles do. Blended and additive meshes never cast shadows.
  • cullMode [back]: which triangle faces are not drawn: back, front or none (both sides drawn). Front faces wind counter-clockwise (as glTF and the built-in primitives); a mirroring transform (negative scale) swaps the winding, and the renderer swaps the culled side with it. Shadow maps always draw both faces, so shadows look the same in every mode.
  • unlit [false]: the output is baseColor * baseColorTexture + emissive (emissive with its texture, when enabled): no directional or point lights, no shadows received, no ambient. Mask, blend and additive still apply, fog still applies, and the mesh still casts shadows when its renderer's castShadows is on.
  • Back-face culling (new in version 2): version 1 rendered every mesh double-sided. Now every material culls back faces by default: .mat files without cullMode (all version 1 files), the default material of a MeshRenderer with no material, and model materials (except glTF doubleSided ones). Open meshes meant to be seen from both sides (planes seen from below, foliage cards, single-sided walls) need "cullMode": "none". A closed translucent (blend) mesh now shows only its front surface, not its inside, and terrain seen from underground is invisible. In this repository samples/starter-mmo/materials/grass_material.mat (the grass blade model) was migrated to none.
  • shader [empty = the built-in shader] (new in version 3): a project-relative .kshader file (or a .kshadergraph, a node graph that generates one), a user shader whose fragment() (and optional vertex() and light()) run inside the mesh shader. Every field above still applies to such a material: its values are what fragment() starts from, and alpha mode, cull mode, unlit and the textures work as without a shader (render modes live here, not in the shader, so one shader serves opaque, mask and blend materials). A shader that samples SCREEN_TEXTURE or DEPTH_TEXTURE needs alphaMode blend or additive (why). A missing .kshader, or one that doesn't parse or compile, renders the material magenta, with one error in the log naming the file and line. In the editor, pick it in the Inspector's Shader section (Shaders in the editor).
  • params [{}] (new in version 3): values for the shader's declared params, by name. A number for a float, an array of 2, 3 or 4 numbers for a vec2, vec3 or vec4 (3 or 4 for a color), a project-relative texture path for a texture2D (empty: its declared default). Params the material doesn't list use the shader's defaults. A value of the wrong type for its param renders the material magenta (logged once); a value for a param the shader doesn't declare (the shader may have changed since the .mat was saved) is ignored with a warning. In the file, the object must hold only numbers, arrays of 2 to 4 numbers or strings. The Inspector shows one widget per param and saves edits here; Lua's kast.setMaterialProperty sets them per entity in Play.
  • Shading: Cook-Torrance (GGX distribution, Smith / Schlick-GGX geometry, Schlick Fresnel, F0 = mix(0.04, baseColor, metallic)) for the first DirectionalLight and up to 8 PointLights per mesh; ambient adds a diffuse term and a flat specular term (roughness-aware Fresnel), so metals are not black with ambient light only. Direct light is scaled by the shadow maps (the directional term by its cascade, each shadowed point light by its cube) unless the mesh's receiveShadows is off. No image-based lighting. The shader outputs linear HDR color (formulas in engine/shaders/fs_mesh.sc); the post chain tonemaps and encodes it to sRGB.
  • Textures: PNG and JPG (stb_image), mipmapped at load (sRGB-correct filtering for base color and emissive), shared by path.
  • Fallbacks (the scene always loads): a missing or invalid .mat renders unlit magenta; a missing or undecodable texture renders as white, except a normal texture, which renders flat. Each is logged once per path, with the reason.
  • glTF import (models): normalTexture and its scale, occlusionTexture and its strength, emissiveTexture, doubleSided (true: cullMode none; false or absent: back) and KHR_materials_unlit (unlit) map onto these fields, besides base color, metallic-roughness, emissive and alpha mode. A model's material without these gets the defaults.
  • Editor: Assets > Create > Material writes new_material.mat (default material) into the folder and starts a rename. Selecting a .mat in Assets shows it in the Inspector (until an entity is selected): color pickers, sliders (clamped), drags for the normal scale and UV scale / offset, the alpha mode (with Additive) and cull mode combos, the Unlit checkbox and texture combos for base color, metallic-roughness, normal, AO and emissive (the project's .png / .jpg); every edit saves the file and the views show it the same frame. The MeshRenderer Inspector picks a material from the project's .mat files or None (default). Renaming or moving a .mat or texture (or a folder holding them) in Assets rewrites the open scene's MeshRenderer.material paths and the texture paths inside every valid .mat; deleting one leaves the references to fall back. .mat and texture files changed on disk (e.g. in an external editor; double-click opens a .mat there) reload within a frame: the renderer checks each loaded file's modification time every frame (not in the built game).
  • Lua (Play): kast.set(e, "MeshRenderer", {material = "materials/red.mat"}) swaps the material. kast.setMaterialProperty(id, name, value) changes one field for that entity only: the first call copies its material into a per-entity instance (Unity's renderer.material); other entities using the same .mat are unaffected. kast.getMaterialProperty(id, name) reads the instance, else the .mat. Values are checked like .mat fields (invalid raises); colors are {r, g, b[, a]} or {x =, y =, z =[, w =]} and come back as arrays, as do uvScale / uvOffset ({x, y}); cullMode and alphaMode are strings, unlit a boolean. Every field above works, e.g. kast.setMaterialProperty(e, "uvOffset", {0.5, 0}). Instances are never saved: Stop discards them, and kast.set to another material drops the entity's instance.
  • Built game: .mat and texture files ship in game.pak like every other project file; the player renders them the same way.
