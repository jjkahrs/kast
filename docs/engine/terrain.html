Terrain

Heightmap ground for maps (engine/terrain.h, services/world/map/heights.h), streamed in Play (editor and kast_player; not in edit mode).

Heightmaps: a map folder maps/<folder>/ holds map.json (its heightRange [min, max], material, terrainUv and nav.maxSlopeDeg are used here) and one file per tile, heights/<tx>_<tz>.r16 (exactly 257 x 257 little-endian uint16, 132098 bytes) or .png (257 x 257 16-bit grayscale). A tile is 256 m with a sample every 1 m, row-major with rows along +z; column 256 of tile tx is column 0 of tile tx+1 (and likewise for rows), so neighbours share their edge. Sample s is at y = min + s / 65535 * (max - min). A tile with no file is flat at min; a file that doesn't decode (wrong size, 8-bit, colour) logs the reason and the tile is flat. Each 1 m quad is two triangles split along its (u, v)-(u+1, v+1) diagonal, the same triangles Jolt's height field uses, so what you see is what you stand on (and what the server and navmesh will use).

Terrain component (on one scene entity): map (the map.json id) and radius (0-4 tiles). Each frame the tiles of that map within radius tiles of the centre tile (a square: radius 1 is 3 x 3) are kept as TerrainTile children of the entity, clipped to the tiles map.json declares; tiles that leave the square are destroyed. The centre is the NetworkLocalPlayer, else the active camera. Online, world.entered and world.mapChanged set map to the server's map, so a portal swaps every tile for the new map's. TerrainTile (map, tx, tz) is runtime only: it is not in Add Component, and its Transform is ignored (tiles sit at their map position).

  • Rendering: each tile is one 257 x 257 vertex mesh drawn with the map's material (empty: the default material), lit, casting and receiving shadows like any mesh. No LOD. Its UVs follow map.json "terrainUv": "tiled" (the default) is world x/z / 8, a texture repeating every 8 m; "map" stretches one texture over the bounding box of the declared tiles (UV 0, 0 at its min x, min z corner, 1, 1 at its max), the same on both sides of a tile edge. Any other value fails the manifest (the editor, player, zone builder and world server refuse the map).
  • Physics: each tile is a static Jolt height field (under 2 cm from the rendered ground), so characters and bodies collide with it and raycasts hit it (the hit entity is the TerrainTile). While tiles exist, characters use the map's nav.maxSlopeDeg instead of their own maxSlopeDegrees.
  • Areas: when the centre moves into another area of the map's areas.json (or onto another map), the bus gets area.left then area.entered, each {map, id, name} (publisher kast.terrain).
  • Loading is synchronous, on the frame a tile appears: crossing into a new tile can hitch.

Generated texture: the Zone Builder can color a map by height. It keeps the gradient in map.json as "terrainColors": stops [pos, [r, g, b]], pos 0..1 of the height range (0 = min, 1 = max), colors 0..1, at least 2, e.g. [[0, [0.76, 0.7, 0.5]], [0.3, [0.33, 0.52, 0.21]], [1, [0.95, 0.95, 0.97]]]. On save it bakes them into textures/<folder>_terrain.png (1 px per metre of the bounding box, at most 4096 px on a side, row 0 at min z) with materials/<folder>_terrain.mat, and the map uses that material with "terrainUv": "map". The engine and the world server ignore terrainColors; the texture is an ordinary material texture.

Sample: tests/project/maps/hills (map 3, 2 x 2 tiles of PNG16 hills, materials/terrain_grass.mat) and tests/project/terrain.scene (a Terrain on map 3, a CharacterController dropped above the hills). The start map's hills_gate area ([1060, 1020]-[1070, 1030]) is a portal to it. scripts/terrain_map_switch.lua switches a Terrain from its map to map 3 offline, as world.mapChanged does online.
