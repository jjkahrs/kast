Screen-space reflections

SSR reflects what is on screen in smooth surfaces (wet floors, polished stone, metal), marched every frame through the depth buffer. Where a ray hits, it replaces the reflection probe / IBL specular already in the pixel; where it misses (off screen, behind something, too rough) the probe specular stays, so nothing is counted twice and a miss fades back to the probe instead of popping (engine/post_process.h, engine/shaders/post/fs_ssr_*.sc). The Scene view (with its toolbar's Post box), the Game view and the built game apply it alike.

It is a per-scene setting ("postProcessing" > "ssr"), off by default: a scene without it renders exactly as before. Edit it in Window > Post Processing > SSR (live, undoable, marks the scene dirty) or from Lua. Place a reflection probe or use a sky so misses have something to fall back to.

Settings

FieldDefaultRangeMeaning
enabledfalseSSR on
maxDistance500.5 to 1000meters a ray travels in the view; it fades over its last 30%
thickness0.30.01 to 5meters behind the depth buffer a ray still counts as hitting a surface
maxRoughness0.60 to 1surfaces rougher than this keep the probe specular (fading over the last 25%)
intensity10 to 1how much of the probe specular the hits replace (0: no change, byte for byte; neither pass runs)
steps32integer 8 to 128linear march steps per ray (quality and cost)
"postProcessing": {
  "ssr": { "enabled": true, "maxDistance": 50, "thickness": 0.3, "maxRoughness": 0.6, "intensity": 1, "steps": 32 }
}

Every field is optional (missing ones take the default). An unknown field, a wrong type or a value out of range fails the scene's load with an error naming it, e.g. postProcessing.ssr: "steps" must be an integer between 8 and 128, and the open scene is left untouched.

How it works

  1. G-data (shared with SSAO): normal and roughness, the pixel's indirect specular (RG11B10F: what the probes / IBL / VoxelGI / SDFGI added) and, for SSR only, its specular weight f0 * envBRDF.x + envBRDF.y (RGBA8, times material AO and the distance fog's remaining fraction). About 32 MiB at 1920 x 1080 with SSR on.
  2. Trace, half resolution (RGBA16F): a reflection ray about a GGX-sampled normal (roughness spreads the rays; a 4 x 4 Bayer pattern spreads the samples) is marched linearly in screen space with perspective-correct depth over steps steps up to maxDistance; the first step behind the depth buffer is refined by 5 binary steps and is a hit when less than thickness behind it. It reads the opaque HDR scene color after SSAO (before blended draws and post). Confidence 0..1 fades over the screen's edges, the ray's last 30%, the thickness, back faces and roughness.
  3. Composite, full resolution: a bilateral 4 x 4 gather over the trace (its spacing grows with roughness, so rough surfaces reflect blurrier; taps weighed by depth, normal and 1 / (1 + luma)), added to the color: 
    color = color + intensity * confidence * (specularWeight * reflection - indirectSpecular)
    Confidence 0 adds exactly 0 (kast::ssrComposite is the CPU mirror checked by engine_self_check).

Limits: rough reflections show a faint dither pattern (no temporal filter); the occlusion culling's Hi-Z is last frame's, so SSR doesn't use it. A Hi-Z march and temporal resolve are the upgrade path.

Cost

Debug build, RTX 4070 Ti SUPER, built player at 1920 x 1080 (--gpu-stats, mean of 3 runs of 590 frames), on tests/project/ssr.scene: 2.86 ms GPU frame with SSR vs 1.94 ms off, about +0.9 ms for the G-data and both passes. Memory: the G-data (32 MiB) plus one half-res RGBA16F target (4 MiB).

Lua

kast.ssr.get() returns the settings as a table; kast.ssr.set{...} changes any of its fields at run time, all-or-nothing and checked as on load (kast.ssr.set: postProcessing.ssr: ... on a bad field).

kast.ssr.set({maxRoughness = 0.3, steps = 64})   -- only mirror-like surfaces, finer march
print(kast.ssr.get().enabled)

See tests/project/ssr.scene (a smooth and a rough floor, colored cubes and spheres, a pillar) and scripts/ssr_set.lua.
