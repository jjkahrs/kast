Asset references

Project files name assets by project-relative path (/ separators, compared ignoring case). Since stable asset ids, a reference also carries the asset's id from its .meta file (Assets and asset ids), so the editor finds the asset after a rename or move. The engine itself only ever uses the path.

Format

In JSON project files a reference is an object of exactly a string id and a string path (the path hint):

"MeshRenderer": { "primitive": "cube", "material": { "id": "86f80bd4-a7a4-403a-9829-7dfed3edaf9e", "path": "materials/red_plastic_r01.mat" } }

The editor writes one wherever a string value exactly names an asset of the project. The files that hold references:

FileReferences
.scene, .prefabComponent fields: ModelRenderer.model and .materials, MeshRenderer.material, AudioSource.clip, ParticleEmitter.texture, baked data paths (bakedPath); prefab instances ("prefab"); systems; skybox faces.
.matTexture slots, texture2D param values, the shader (.kshader / .kshadergraph).
project.kaststartScene (and any other value naming an asset).
maps/<map>/map.json, maps/<map>/objects/*.jsonThe terrain material; each object's prefab.
.rml, .guiprefabGUI prefab instances (data-prefab) and style sheet links (<link type="text/rcss" href="...">), each with a data-kast-id attribute beside the path attribute: <div id="a" data-prefab="ui/prefab_button.guiprefab" data-kast-id="d7d5e664-..."/>. RmlUi ignores the attribute and loads the path.

Not references: Animator.clip (a clip name), StateMachine.machine (a machine name), shader graph files (no asset paths), areas.json, the .server/ files and generated terrain materials (plain paths, as before).

Legacy plain strings

A plain path string is still a valid reference everywhere: files written before asset ids load unchanged, in the editor and in the built game. The editor upgrades them to {id, path} on the next save of each file. tests/legacy_project is a small project kept in that legacy form (no .meta files) to test it.

Runtime: still by path

  • Every engine loader (scenes, prefabs, materials, project.kast, maps, terrain) replaces each {id, path} by its path right after parsing (kast::readAssetRefs, engine/asset_ref.h); ids are never looked up. The editor plugs its id registry in through kast::setAssetRefHooks; the engine does not depend on it.
  • The player, game.pak and Lua load by path. game.pak has no id table and no .meta files; Build writes the current paths into the shipped copies.
  • Lua paths (kast.loadScene("scenes/x.scene") and the like) are plain strings, not tracked by ids.
  • The world server (kast_world) reads the maps' map.json and objects/*.json in both forms, and kast_mapbake ignores .meta files. Rebuild both (cmake --build services/world/build/release --target kast_world kast_mapbake) before using maps saved by this editor: older builds don't read {id, path}.
