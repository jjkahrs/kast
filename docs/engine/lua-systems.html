Lua systems

Game logic can be written as global ECS systems in Lua (LuaJIT, bound with sol2; engine/lua_systems.h). A scene lists its system files in "systems"; Play runs each once per frame, after the C++ systems and in listed order. They don't run while stopped or paused.

File shape: one .lua file is one system and returns a table:

local speed = 2 -- file-level locals and globals are private to this system

return {
    init = function() kast.log("ready") end,           -- optional: once when Play starts (or after a hot reload)
    update = function(dt)                                -- required: every Play frame, dt in seconds
        for e in kast.query("Transform", "MeshRenderer") do
            local p = kast.get(e, "Transform").position
            p.y = p.y + speed * dt
            kast.set(e, "Transform", {position = p})
        end
    end,
    shutdown = function() kast.log("bye") end,          -- optional: on Stop (or before a hot reload)
}

A file that doesn't return a table with an update function, or whose init/shutdown isn't a function, is an error for that system.

Paths: "systems": ["scripts/spin.lua", "shared/ai.lua"] are relative to the active project's root (/ separators), wherever the scene file is. The Systems panel stores paths that way; Save As does not rewrite them. With no active project, or for a path outside the project, that system is disabled with the reason.

kast API (one read-only table per system; assigning to kast, kast.input or kast.fsm is an error). Entities are persistent ids (EntityId integers, the scene file's id). An invalid or destroyed id, an unknown component name or a wrong argument type raises a Lua error at the calling line.

Function Returns Notes
kast.query(name, ...) iterator of ids Entities that have every listed component, in hierarchy order: for e in kast.query("Transform", "Rotator") do. No names = every entity. The matches are captured when query is called: entities destroyed later in the loop are skipped, entities created in the loop are not visited.
kast.get(id, name) table A copy of every field. Raises if the entity doesn't have the component.
kast.set(id, name, fields) — Partial: only the listed fields change. All-or-nothing: an unknown field, a wrong type or a value the component rejects (e.g. Camera ranges, a zero quaternion) raises and leaves the component unchanged.
kast.getMaterialProperty(id, name), kast.setMaterialProperty(id, name, value) value, — The entity's material, per entity: see Materials; also the params of its .kshader. Raises without a MeshRenderer, for an unknown property or (set) an invalid value.
kast.has(id, name) boolean
kast.add(id, name) — Default-constructed; no-op if already present.
kast.remove(id, name) — No-op if absent. Transform can't be removed (raises).
kast.create(name [, parentId]) id New entity with a Transform, at the root or as the last child of parentId.
kast.destroy(id) — Destroys the entity and its children immediately.
kast.instantiate(path [, parentId [, position]]) id or nil A new linked instance of the prefab path (project-relative .prefab), at the root or as the last child of parentId, with every entity of the prefab (nested prefabs included) usable by id right away. position ({x =, y =, z =}) sets the root's local position; without it the root keeps the prefab root's transform. Returns the root's id. A path that doesn't resolve inside the project, a missing file or one that doesn't parse returns nil and logs a warning saying why; a bad parentId or position type raises like the other functions. Each prefab file is read once per Play session. Works in editor Play and in built players (.prefab files ship in game.pak).
kast.nearestInteractable(position, maxDistance) table or nil The interactable zone object of the streamed terrain tiles nearest to position ({x =, y =, z =}), by the horizontal distance to its shape's edge, if within maxDistance m: {id =, name =, pos = {x, y, z}, distance =}.
kast.interact(id) boolean Activates interactable id (1 to 4294967295): sends Interact to the world server and returns true while in the world, else false. The server's Lua answers if it wants to (Terrain, Zone objects).
kast.items table The project's item definitions (items/**/*.lua, one item per file) by id: {[id] = {id, name, icon, quality, maxStack, sellPrice, description}}, read-only all the way down. Loaded when Play starts, with the World Server's rules and messages (World Server, Items), so a folder shared with the server gives both the same items. A rejected file is a Console error, Item rejected: items/x.lua: ..., and is left out.
kast.log(msg), kast.warn(msg), kast.error(msg) — To the Console, prefixed with the system's path: [info] scripts/spin.lua: msg.
kast.input.keyDown(name) boolean SDL scancode names (SDL_GetScancodeFromName): "W", "Space", "Left Shift", "Up"... An unknown name raises.
kast.input.mouseDelta() dx, dy Pixels moved this frame (also while the cursor is locked).
kast.input.mouseDown(button) boolean "left", "middle", "right", "x1" or "x2" held down. Any other value raises.
kast.input.wheelDelta() number Wheel notches this frame; + = away from the user (up), whatever the OS scroll direction.
kast.input.mouseRay() origin, direction The ray from the scene's active Camera through the cursor, as {x, y, z} tables (direction normalized), e.g. for kast.physics.raycast to pick what was clicked. nil, nil before the cursor position is known or without a Camera. The cursor is tracked within the game view: the whole window in the player, the Game panel's image in the editor.
kast.input.setCursorLocked(locked) — true hides the cursor and locks it in the window (relative mode; mouseDelta keeps reporting motion); false shows it where the lock began. Released automatically when the game loses input (see the Game panel above). A non-boolean raises.
kast.loadScene(path) — Switches the running scene. path is project-relative. Checked at call time, reading the file from disk (unsaved editor edits are not seen): no active project, a path outside the project, a missing file or a scene that fails to load (including an old version) raises at the calling line, and nothing is queued. On success the switch is applied at the end of the frame, after every system's update; the last call in a frame wins. Applying it calls the old scene's enabled systems' shutdown, discards the Lua state, replaces the scene, and starts a new session for the new scene's own systems (each init runs). Nothing persists across the switch. Calls from a shutdown are ignored; a call from an init is applied at the end of the next ticked frame.
kast.publish(name [, payload]), kast.subscribe(name, fn), kast.unsubscribe(handle) —, handle, — Events between systems and C++: see Events.
kast.currentScene() string or nil The running scene's project-relative path ("levels/b.scene"), or nil with no active project or for an Untitled scene.
kast.fsm.state(target), kast.fsm.change(target, state), kast.fsm.canChange(target, state), kast.fsm.states(target) string, boolean, boolean, table Game and entity state machines: see State machines. kast.fsm is read-only too.

Input is only live while the Game panel is focused and playing; otherwise every key is up and the delta is 0.

These work the same on Lua components (kast.get(e, "Health"), ...), whose array fields are 1-based Lua sequences ({"gold", "potion"}); kast.set replaces an array field as a whole.

Field values: float/int are Lua numbers (an int field needs an integral number; numbers must be finite), bool is a boolean, std::string a string, bx::Vec3 a table {x=, y=, z=}, bx::Quaternion {x=, y=, z=, w=} (all keys required when setting), and enums their scene-file names ("cube", "plane", "sphere"). Component and field names are the scene file's ("MeshRenderer", "degreesPerSecond").

Sandbox: one LuaJIT state per Play session; each file runs in its own environment with its own copies of the globals and of the table, string and math libraries, so two systems can use the same global names. Only the base, table, string and math libraries are loaded, and dofile, loadfile, load, loadstring, require, module, getfenv and setfenv are removed: io, os, ffi, debug, jit, bit and package are not reachable. Files are loaded as text only (no precompiled bytecode).

Errors: a syntax error, a missing file, a bad returned table or an error in init, update or shutdown (Lua or raised by kast.*) is logged to the Console with the file and line (Lua system disabled: scripts/spin.lua:12: ..., plus a traceback for runtime errors) and disables that system until the next Play or a successful hot reload. Play and the other systems keep running. Disabled systems' shutdown is not called. With no active project, every listed system is disabled with no project (open a scene inside a project to run Lua systems).

Hot reload: while playing, each listed file's modification time is checked every frame. When it changes, the old instance's shutdown runs (if it was enabled), the file is reloaded into a fresh environment and its init runs. A successful reload clears the error; the scene and entities are not reset, but the system's Lua locals start over.
