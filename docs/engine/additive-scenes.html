Additive scenes

Several .scene files can be loaded at once, as with Unity's additive scene loading: a town, its interiors and a UI scene, say, each its own file, loaded and unloaded while the game runs. Lua does it with kast.loadScene(path, {additive = true}) and kast.unloadScene(path) (in the editor's Play mode and in the built player); the editor opens several scenes together (Multi-scene editing). The scene file format does not change: an additively loaded scene saves exactly as it does when loaded alone.

One registry, several loaded scenes

  • Every loaded scene shares the one kast::Scene (one EnTT registry). The renderer, physics and Lua see all their entities together; there is no list of scenes to pass around.
  • Each loaded scene file is a LoadedScene (Scene::loadedScenes(), in load order): a slot, the path it was loaded from and its scene-level settings. Every entity carries a SceneMember component naming its slot, and a subtree never spans two scenes. The roots are kept grouped by scene, in load order.
  • Entity ids (PersistentId) are unique per file, so two files may both use id 1. In memory an entity's id is its file id with its scene's slot in the high 32 bits (scopedId(slot, fileId)); the first loaded scene is slot 0, so a scene loaded alone keeps its file's ids. Every lookup by id (selection, undo, prefab instances, Lua, the state machines, Play's selection restore) is therefore scoped by scene, and saving writes the file id back (fileEntityId). Scene files may use ids up to 4294967295.
  • Slots are never reused while the scene runs, so an id of an unloaded scene never names an entity of a later one.
  • A path can be loaded only once at a time; loading it again is an error. The same scene twice (instancing) is not supported.
  • Cross-scene references are not supported: moving an entity into another scene (reparenting it under one of that scene's entities, or Scene::moveToScene) moves its whole subtree. Each moved entity keeps its file id unless the target scene already uses it, in which case it gets a fresh one.

The active scene

One loaded scene is active. Its settings are the Scene's own (systems, lighting with the lightmap and SDFGI settings, sky, postProcessing, physics, editorData), so they are the ones that render (sky, ambient, post-processing, fog) and simulate (gravity). The other scenes' settings wait in their LoadedScene untouched, so each one saves back unchanged. Scene::setActiveScene swaps them; Scene::settingsOf(slot) reads any scene's.

  • New entities created without a parent (kast.create, kast.instantiate, the editor's GameObject menu) go into the active scene; with a parent, into the parent's scene.
  • The first scene loaded is active. Unloading the active scene makes the first remaining one (in load order) active.
  • Lightmap and VoxelGI bakes are made and applied as before additive scenes, for the active scene's file; baking while several scenes are open is not supported (their entities are not told apart in a bake).

From Lua

All of these are queued and applied at the end of the frame, after every system's update, in call order; each is checked at the call (raising at the calling line). Paths are project-relative. See the Lua systems API table for the full list.

FunctionWhat it does
kast.loadScene(path, {additive = true})Reads and checks path now (a missing or broken file raises), then adds it to the loaded scenes at the end of the frame: its entities appear, its systems not already running start (init), its playOnStart audio sources play and its state machines enter their initial states. Raises if path is already loaded (or queued to be).
kast.loadScene(path)As before additive scenes: unloads every loaded scene and loads path as the only, active one (the old systems' shutdown run, a fresh Lua session starts). It drops the requests queued before it in the frame; the last such call wins.
kast.unloadScene(path)Shuts down the systems only that scene lists (one another loaded scene also runs keeps running), destroys exactly its entities and drops it. Raises if path isn't loaded, or is the only loaded scene (use kast.loadScene to replace it).
kast.setActiveScene(path)Makes a loaded scene the active one. Raises if it isn't loaded.
kast.activeScene(), kast.currentScene()The active scene's path (nil if untitled or no project).
kast.loadedScenes()The loaded scenes' paths, in load order ("" for an untitled one).

A system runs once however many loaded scenes list it, and only shuts down when the last of them unloads. Lua entity ids are opaque numbers: ids of an additively loaded scene's entities carry its slot (e.g. 4294967297 for its entity 1), so look entities up with kast.query rather than hard-coding file ids.

-- town.lua: load the interior when the player walks in, drop it on the way out
return {
    update = function(dt)
        if enteredInn() then kast.loadScene("interiors/inn.scene", {additive = true}) end
        if leftInn() then kast.unloadScene("interiors/inn.scene") end
    end,
}

The game's other per-scene parts follow additive loads and unloads: physics creates and removes the bodies (gravity is the active scene's), the game GUIs load and unload their UIDocuments and WorldUIs, the unloaded entities' audio stops. A switch still resets everything as before. Replication keeps working on the combined entities.

Tile scenes use this same path: in Play the engine loads and unloads a map's per-tile scenes (maps/<folder>/scenes/<tx>_<tz>.scene) around the player as terrain tiles stream, one load a frame, each listed by kast.loadedScenes() (Terrain, tile scenes). A tile scene Lua already loaded is not loaded twice; one out of range is unloaded even if Lua loaded it.

From C++

  • kast::loadSceneAdditive(path, scene, slot, error) loads a file as one more scene; appendScene(into, std::move(from), path) moves an already-loaded Scene in.
  • kast::saveScene(scene, slot, path, error) and sceneToJson(scene, slot) write one loaded scene: its entities with their file ids and its own settings, byte-identical to the file it came from if unchanged. Without a slot they write the active scene.
  • kast::scenesToJson / scenesFromJson hold every loaded scene with its slot and path and the active one (the editor's Play snapshot).
  • Scene::removeScene(slot) destroys a scene's entities and drops it; Scene::roots(slot) lists its roots.
  • LuaSystems::tick still returns true only for a switch; LuaSystems::sceneChanges() counts every applied change, for hosts that hold entity handles (the editor's panels).
