Lightmaps and baked global illumination

Light bounces: a red wall tints the floor beside it, a ceiling shades the corner under it, a box darkens the floor at its foot. Kast bakes that global illumination (GI) on the CPU in the editor: lightmaps for the meshes that never move (Static) and a grid of light probes for the ones that do (Dynamic). At run time they replace the mesh's diffuse ambient light; specular reflections still come from the reflection probes or the sky (or a VoxelGI volume). The Scene view, the Game view and the built game render them alike (engine/lightmap.h, engine/lightmap_bake.h, engine/shaders/fs_mesh.sc).

Nothing changes until you opt in: every mesh is Off by default, and a scene without a bake renders pixel for pixel as before.

Quick start

  1. Select the meshes that never move (walls, floors, rocks, buildings) and set GI Mode to Static in their Mesh Renderer or Model Renderer.
  2. Set the moving ones (characters, props the player pushes) to Dynamic.
  3. Save the scene in a project, open Window > Lighting and press Bake Lightmaps. The bake runs in the background with a progress bar and Cancel; the editor keeps working. When it is done the scene lights with it and is marked dirty: save it.
  4. Move a Static mesh, change a baked light or the sky, and the status says Out of date: bake again.

A skinned model can't be Static (its pose changes): the Inspector greys Static out, and a scene file that says so anyway loads, warns once ('Hero': a skinned model can't be Static; lit as Dynamic) and lights it as Dynamic. All fields are optional in the scene file (missing = the default) and are undoable Inspector edits like any other.

"MeshRenderer": { "primitive": "cube", "material": "materials/wall.mat", "giMode": "static", "lightmapScale": 2 }
"PointLight": { "color": [1, 0.75, 0.45], "intensity": 3, "range": 8, "bakeMode": "full" }

Light bake mode

bakeModeDirect light and shadowsBounces
"realtime"realtime, on everythingnone (the light is left out of the bake)
"indirect" (default)realtime, on everythingbaked
"full"baked into Static meshes' lightmaps (soft area-light shadows included); realtime on Dynamic and Off meshesbaked

A Full light costs nothing at run time on lightmapped meshes: it isn't among their light slots (or, for the sun, its color is zero for them). The baker shines lights exactly as the renderer does (pointLightFalloff, spotConeFalloff, the area light's form factor and range window; color times intensity is radiance times pi), so a Full light's baked look matches its realtime one, give or take its specular highlight (diffuse only is baked) and the sharpness of its shadow. Dynamic meshes' realtime shadows don't fall on Static meshes from Full lights (their light is in the lightmap); use Indirect where that matters.

Scene settings (Window > Lighting)

Saved in the scene file under "lighting" > "lightmaps" (only when not all default, so older scenes save byte-identically). The first four take effect at the next bake, the next three at once (also from Lua):

The defaults bake tests/project/lightmap_room.scene (ten Static meshes, three lights, 27 000 texels, 405 probes) in under a second on a 16-core desktop (Release); the target is under a minute. Raise samplesPerTexel first if lightmaps look noisy (the bake has no denoiser), texelsPerMeter or a mesh's lightmapScale if they look blurry. The panel also shows the bake's status: Not baked, Baked, Out of date (highlighted) or why its files can't be used (red), and logs it when it changes.

How the bake works

  1. Gather (main thread): every Static mesh (primitives and non-skinned models in their bind pose), the lights that aren't Realtime, the sky and lightmapped terrain become plain data, so the bake runs while you keep editing. Surfaces bounce their material's base color times its base color texture's average color times (1 - metallic), and emissive materials emit their emission (times the emissive texture's average).
  2. Unwrap: each mesh gets a second UV set with xatlas, non-overlapping charts padded against bilinear bleeding, at its texel density, in its own rect. Meshes of the same source at the same scale and density share one unwrap (and can still be instanced). A glTF mesh with a second UV set (TEXCOORD_1) keeps its own instead. The rects are packed into atlas pages of up to 1024 x 1024 texels.
  3. Trace: a BVH (engine/bvh.h) over all Static triangles and terrain, then for every texel samplesPerTexel cosine-weighted paths (stratified, each texel its own random stream from a fixed seed: the bake is deterministic and its files are identical on every run) on every CPU core. Escaped rays see the sky times the ambient color and intensity (the flat ambient with the sky off), as the renderer lights with it; every bounce is lit by the baked lights with shadow rays. A texel whose rays mostly hit the back of one-sided geometry is inside it (e.g. under a wall) and is filled from its neighbors; every chart is then dilated 8 texels against seams.
  4. Probe grid: probes at probeSpacing over the Static meshes' bounds (at most 8192: the spacing grows if it would be more), each projecting its incoming light (sky, bounces, emission: not the lights' direct light, which Dynamic meshes get in real time) into order-2 spherical harmonics. A probe buried in geometry is marked invalid.
  5. Write (main thread, when done): each file atomically, the json last, so a cancelled, failed or interrupted bake leaves the previous one intact.

Entities are matched by their persistent scene id. The hash covers what the bake depends on: every Static mesh (mesh, material, world matrix, lightmap scale), every light that isn't Realtime, the ambient and sky, the bake settings and lightmapped terrain; when the scene's differs the status says Out of date (and the old bake still renders). Each file's FNV-1a hash is in the json too, so a mix of two bakes is caught. Build ships all of them in game.pak as they are; the player loads them like the editor.

Shading

The diffuse ambient of a draw comes from one selection point (selectDiffuseGi in lightmap.h, kastGiDiffuse in fs_mesh.sc), in this order:

  1. Lightmap: a Static mesh the bake covers.
  2. VoxelGI: any mesh (Off, Static without a lightmap, Dynamic) whose bounds center is in an enabled, baked VoxelGI volume's box: cone-traced from the volume, relit every frame. (SDFGI, a later part of Kast's GI, slots in after it.)
  3. Probe grid: a Dynamic mesh, or a Static one the bake can't light (not in the bake, a model changed since).
  4. The environment as before GI: a reflection probe's or the sky's spherical harmonics, or the flat ambient.
diffuse  = (1 - F) * (1 - metallic) * albedo * GI(n) * intensity
GI(n)    = lightmap(uv2) * (dot(n, d.xyz) * 0.5 + 0.5) / d.w     // directional: d = the direction texel
         | VoxelGI(n): the volume's diffuse cones (voxelgi.html), fading to the next line at its box's faces
         | SH(grid sampled at the mesh's bounds center, n)
specular = the environment's, unchanged; inside a VoxelGI volume its reflection cone instead (lightmapped meshes too)

The directional term: at the baked surface's own normal the factor is exactly 1; a normal map tilting toward where the light came from gets more, away less, so bumps show under baked light too. The probe grid is sampled trilinearly from the eight probes around the point (clamped into the grid); invalid probes are left out and the rest reweighted, so a probe inside a wall never darkens a mesh beside it; with no valid probe around, the mesh falls back to the environment.

Second UV set: primitive and terrain vertices carry a TEXCOORD1; a lightmapped draw uses its unwrapped vertex buffer and its rect in the atlas page (u_lightmapST, or per instance in i_data4 for an instanced batch). Static meshes sharing an unwrap and an atlas page still draw as one instanced submit; each probe-grid draw samples its own harmonics, so Dynamic meshes draw one by one.

Texture stages: the lightmap and its direction take stages 12 and 13, which a .kshader's third and fourth texture2D params also use. A shader with at most two keeps its lightmaps; a material whose shader has three or four lights its Static meshes with the probe grid instead (the stages are then the shader's).

Terrain

A Terrain with Bake Lightmap on ("lightmap": true) bakes every declared tile of its map: one 257 x 257 lightmap per tile, one texel per height sample (the heightmap grid is its UV set: no unwrap), into the map's folder (maps/<name>/lightmaps/), so each lightmap streams in and out with its tile. Terrain also occludes and bounces light for the scene's Static meshes. Only client data: nothing goes under .server/. The map's lightmaps are the last scene's that baked it. A tile whose files are missing or don't match its map's lightmaps.json warns once (Terrain tile 0_1: lightmap: not baked …; lit as unbaked) and keeps the sky or flat ambient. On the 2 x 2 tile test map a bake takes about 10 to 20 seconds.

When a bake can't be used

A missing lightmaps.json, a corrupt or truncated file, a file that doesn't match its hash, another version, or malformed json: the engine warns once (Lightmaps 'room_lightmaps/lightmaps.json': lightmaps.json is version 2, expected 1 (bake again); the scene renders unbaked), the Lighting panel shows the reason, and every mesh lights as if there were no bake. A model that changed since the bake (a different vertex count) warns and its meshes fall back to the probe grid. Never a crash, never black.

Lua

kast.lightmaps.get() returns the scene's settings as a table; kast.lightmaps.set{...} changes the ones that apply at once: enabled, intensity, directional (the rest need a bake and raise; anything the scene file would reject raises and changes nothing, as kast.sky.set):

kast.lightmaps.set({intensity = 0.5, directional = false})  -- dusk: half the bounced light
kast.lightmaps.set({enabled = false})                       -- the realtime lights alone

There is no Lua bake. giMode and bakeMode are regular component fields (kast.set), but changing them at run time only changes how the existing bake is applied.

Limits

  • CPU only, no denoiser: noise is traded against samplesPerTexel. Diffuse only: no baked specular; transparent and cut-out materials bake as opaque; material files are named, not read, by the out-of-date hash (editing a .mat's color doesn't mark the bake out of date).
  • Static means static: a moved Static mesh keeps its old light until the next bake. Skinned meshes are never Static; a non-skinned model is baked in its bind pose.
  • One bake per scene (and one per terrain map); no lightmap streaming beyond terrain tiles; atlases are RGBA16F and uncompressed.
  • The probe grid is a box over the Static meshes: Dynamic meshes outside it are clamped to its nearest probes.
