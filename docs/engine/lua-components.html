Lua components

Game developers can define data-only ECS component types in Lua, inside their project (engine/lua_components.h). Once defined, a Lua component behaves like a built-in one: saved in scenes, edited in the Inspector, listed by Add Component, copied on Duplicate, snapshot/restored by Play and reachable from Lua systems through kast.*.

Files: every .lua file under <project>/components/, scanned recursively, is one definition. They are loaded when a project becomes active (opening a scene or project, New Project, --project / --scene at startup). No project = no Lua components. Each file returns exactly one table:

-- components/health.lua
return {
  name = "Health",          -- type name and scene-file key; required, unique
  displayName = "Health",   -- optional: Inspector header / Add Component label, defaults to name
  fields = {                -- required list (may be empty), in save and Inspector order
    { name = "current", type = "float",  default = 100, min = 0 },
    { name = "lives",   type = "int",    default = 3, min = 0, max = 9 },
    { name = "regen",   type = "bool",   default = true },
    { name = "title",   type = "string", default = "Hero" },
    { name = "tint",    type = "vec3",   color = true, default = {x = 1, y = 0, z = 0} },
    { name = "facing",  type = "quat" },                                     -- identity
    { name = "faction", type = "enum",   values = {"neutral", "ally", "enemy"}, default = "neutral" },
    { name = "drops",   type = "array",  of = "string", default = {} },
  },
}
type Value (Lua / JSON) Options
float number (stored as a 32-bit float) min, max
int integral number (32-bit) min, max (integers)
bool boolean
string string
vec3 {x=, y=, z=} / [x, y, z] color = true: color picker in the Inspector
quat {x=, y=, z=, w=} / [x, y, z, w], nonzero
enum one of values, as a string values: non-empty list of unique non-empty strings (required)
array Lua sequence / JSON array of of of: any type above except array (no nesting); an enum array also takes values; min/max on a float/int array apply to each element; color on a vec3 array
  • Names (name of the type and of each field) are letters, digits and _, not starting with a digit. Field names are unique within the type.
  • default is optional. Without it a field gets its type's zero value moved into min/max: 0, false, "", {0,0,0}, the identity quaternion, the first enum value, an empty array. A given default that violates the field's type, range or values is a definition error.
  • Unknown keys (at the top level or in a field) are errors, so typos don't pass silently.

  • Two optional top-level keys belong to the world server, so a game project's components/ can be shared with it (World Server, Lua components and systems):

    • persist = true|false (default false): the server saves the component per character.
    • replicate = "none"|"owner"|"aoi" (default "none"): who the server sends it to.

    The engine checks them (a non-boolean persist or another replicate value is a definition error) and otherwise ignores them: it applies whatever the server replicates (see Replication).

Sandbox: one Lua state per scan, separate from Play's, each file in its own environment with the same rules as Lua systems: only base, table, string and math; io, os, ffi, debug, jit, package, require, dofile, loadfile, load and loadstring are not reachable; text only.

Errors: a file that isn't valid Lua, raises, doesn't return exactly one table, or breaks any rule above is rejected. The message starts with the project-relative path (and the line for Lua errors, e.g. components/health.lua:3: ...), is logged as Lua component rejected: ... and shown in the Components panel. Valid files in the same project still load.

Name clashes: a name equal to a built-in component (Transform, MeshRenderer, DirectionalLight, Camera, Rotator, StateMachine) or a structural one (PersistentId, Name, Hierarchy, PreservedComponents) is rejected. If two files declare the same name, both are rejected, each error naming the other file, so the result never depends on scan order.

Scene files: same shape as built-ins, after them, sorted by type name: "Health": { "current": 100.0, "lives": 3, ..., "tint": [1.0, 0.0, 0.0], "faction": "neutral", "drops": ["gold"] } (vec3/quat as arrays, enums by name, arrays as arrays, floats rounded to 32-bit). Output is deterministic; re-saving gives identical bytes. Scene files stay version 4.

Inspector: one collapsible section per Lua component with generated widgets, removable with its x: drag fields clamped to min/max, a checkbox, a text box, a color picker for color vec3s, Euler degrees for quats (as for Transform), a combo for enums. Arrays show name [count] with one row per element (value, move up, move down, remove x) and Add Element (appends the zero value moved into min/max). Edits are checked like kast.set. Add Component lists Lua types the entity doesn't have; adding one gives the declared defaults.

Lua systems: kast.query/get/set/has/add/remove take Lua component names like built-in ones. kast.set stays partial and all-or-nothing: an unknown field, a wrong type, an enum name not in values, a value outside min/max (including one array element) or a non-sequence table for an array raises at the calling line and leaves the component unchanged.

Schema drift (lenient, unlike built-ins): when stored data doesn't match the current definition, on scene load and on definition hot reload, missing fields get their default, unknown fields are dropped, and mistyped or out-of-range values (including a bad array element or an unknown enum name; a bad element resets the whole array) are reset to the field default. Each change is a Console warning naming the entity, component and field, e.g. Entity 'Hero' (id 3): Health: "lives" 12 must be <= 9; reset to default 3. The scene still loads. The document is marked dirty only if some instance's data was changed this way.

Missing definitions: a component name that is neither built-in nor a valid Lua definition (never defined, file deleted, or now broken) doesn't stop the scene from loading: a Console warning is logged, and its JSON is kept verbatim on the entity (PreservedComponents), written back unchanged on Save (after the known components) and carried through Duplicate and Play/Stop. The Inspector shows it read-only as Missing: <name> with its raw JSON, removable with x. Lua systems can't reach it (kast.* raises unknown component "<name>"). When a valid definition for that name appears (hot reload, or opening the scene in a project that has it), the preserved data is converted with the drift rules.

Hot reload: while stopped, the editor checks the components/ folder every 0.5 s for added, removed and modified .lua files (modification time) and reloads the definitions: existing instances migrate with the drift rules, and a removed or now-broken definition turns its instances into preserved Missing data (nothing is lost; restoring the file converts them back). During Play definitions are frozen; changes made meanwhile apply after Stop, to the restored scene.
