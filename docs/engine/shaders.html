Shaders

Shaders (editor/shaders/*.sc for ImGui, engine/shaders/*.sc for meshes and grid lines, engine/shaders/gui/*.sc for game GUIs, engine/shaders/post/*.sc for the post-processing passes; each directory has its own varying.def.sc) are compiled at build time to Direct3D 11 bytecode headers (-p s_5_0) with shaderc from vcpkg's bgfx[tools] (a host dependency in vcpkg.json). Sources stay editable and always match the installed bgfx version.

Meshes and shadow casters have three vertex shader variants each: vs_mesh / vs_shadow (one draw, model matrix from u_model), vs_mesh_skinned / vs_shadow_skinned (plus bone matrices) and vs_mesh_instanced / vs_shadow_instanced (model matrix per instance in i_data0..3, see Instancing and culling). The single and instanced variants transform the same way (model, then u_viewProj), so a mesh covers the same pixels either way.

Mesh vertices and tangents

Every mesh vertex layout (primitives and terrain: position, normal, tangent, UV0; models: the same plus joint indices and weights) has a vec4 tangent (a_tangent, TANGENT): xyz points along increasing texture u, and w (±1) is the handedness, so the bitangent cross(normal, tangent.xyz) * w points toward the image's top (decreasing v, the normal map's +Y). Sources: the built-in cube, plane and sphere compute them exactly; terrain uses world +X made perpendicular to each vertex normal (w = 1); models get Assimp's tangents (aiProcess_CalcTangentSpace) made perpendicular to the normal, with w from the triangles' UVs; vertices without UVs get any unit vector perpendicular to the normal. vs_mesh and vs_mesh_instanced carry the tangent by the model matrix (not the normal matrix) and vs_mesh_skinned skins it like the normal first; a mirroring model matrix flips w. fs_mesh makes the interpolated tangent perpendicular to the normal again (Gram-Schmidt) before applying the normal map. The shadow shaders read only the position and UV of the same buffers, so their output is unchanged.

Every layout also has a vertex color (a_color0, COLOR0, RGBA8 normalized, linear): a model's glTF COLOR_0 (8 bits per channel; RGB colors get alpha 1), else white, as for the primitives and terrain. The vertex shaders pass it on as v_color0; the built-in material ignores it, a .kshader reads it as COLOR.

Mesh material inputs

fs_mesh samplers: s_baseColor (stage 0), s_metallicRoughness (1), the shadow maps (2–6), s_normal (7), s_occlusion (8), s_emissive (9). Uniforms besides the lights: u_baseColor, u_emissive, u_material (metallic, roughness, alpha cutoff, output mode 0 opaque / 1 blend / 2 additive), u_materialExt (normal scale, occlusion strength, normal map bound, unlit), u_uvTransform (UV scale xy, offset zw; also read by fs_shadow for mask cutouts).

u_time (vec4, x = seconds) is set for every mesh draw. In the editor it advances by each frame's delta in edit mode and in Play (by exactly --fixed-dt per frame when that option is given) and holds while Play is paused; the player advances it every frame. It wraps to 0 every 3600 seconds (kShaderTimePeriod in engine/shader_clock.h) so it keeps sub-millisecond float precision. The built-in material doesn't read it; a .kshader reads it as TIME.

User shaders (.kshader)

A .kshader file holds a fragment() function, optionally a vertex() function, in the bgfx .sc GLSL dialect, plus declared params. A material uses it through its "shader" field (see Materials). Kast injects the file into its mesh shader templates, engine/shaders/fs_mesh.sc and vs_mesh.sc / vs_mesh_skinned.sc / vs_mesh_instanced.sc (with mesh.sh, the uniforms and built-ins they share), at their //@user line: the built-in mesh shaders are those templates compiled as is (with empty default fragment() and vertex()), so built-in and user shaders share all of the transform, skinning, instancing, lighting, shadow, fog and alpha code. main() first fills every built-in with what the built-in material computes (base color times its texture, metallic / roughness times theirs, emissive, the normal map, AO), calls fragment(), then discards below the alpha cutoff (mask), lights the result (Cook-Torrance, shadows, ambient), adds EMISSION and fogs. A fragment() that writes nothing renders exactly as the material without a shader.

// shaders/stripes.kshader
param color tint = color(1.0, 0.6, 0.3);
param float stripes = 6.0 range(1, 20);
param float speed = 0.5 range(0, 4);
param texture2D pattern = white srgb;

void fragment()
{
    float band = step(0.5, fract(UV.x * stripes + TIME * speed));
    ALBEDO *= tint.rgb * COLOR.rgb * mix(0.35, 1.0, band) * texture2D(pattern, UV).rgb;
    EMISSION += vec3(0.0, 0.3, 1.0) * band;
}

Params

One declaration per line, starting with param: param <type> <name> [= <default>] [range(<min>, <max>)] [srgb]; (a trailing // comment is fine).

TypeDefault syntaxWithout a defaultIn the code
float= 1.5; optional range(0, 10) (the Inspector slider's bounds; not enforced)0float
vec2, vec3, vec4= vec3(1, 0.5, 0), or one number for all: vec3(0.5)zerosthat vector
color= color(r, g, b[, a]), linear (a = 1 if left out)whitevec4
texture2D= white, black (opaque) or normal (flat, 0.5, 0.5, 1); flag srgb for color datawhite, lineara sampler: texture2D(name, UV)

Numeric params become slots of one uniform array (u_kastParams[16], one vec4 each), so a shader can declare at most 16 float / vector / color params. Names must be identifiers, unique, not a built-in below, not a keyword or type name, and not start with u_, s_, v_, a_, i_, gl_, bgfx or kast. Param lines are taken out of the code before it compiles (line numbers stay), so param can't start a code line.

Texture limit: a draw has 16 sampler stages (D3D11's per-stage slot count, bgfx's maxTextureSamplers; the renderer logs an error at start if a GPU reports fewer). The mesh shader uses stages 0–9 (material textures and shadow maps) and keeps 14 and 15 for SCREEN_TEXTURE / DEPTH_TEXTURE, so texture2D params take stages 10–13: at most 4 per shader. A 5th is a parse error: line 5: too many texture2D params: at most 4 (sampler stages 10..13; ...).

vertex()

Optional. It runs per vertex before the template transforms the vertex to the world, so it moves the mesh in object space; skinned meshes run it after skinning (in the model's space), instanced ones get each instance's model matrix. main() fills the built-ins with the mesh's vertex, so a vertex() that writes nothing changes nothing. The shadow passes run the same vertex shaders, so shadows follow the displacement.

// shaders/sway.kshader (tests/project/shader_vertex.scene)
param float sway = 0.4 range(0, 1);
param float speed = 1.5 range(0, 8);

void vertex()
{
    vec3 origin = mul(MODEL_MATRIX, vec4(0.0, 0.0, 0.0, 1.0)).xyz; // the object's world position
    float h = saturate(VERTEX.y + 0.5);
    VERTEX.x += sway * h * h * sin(TIME * speed + origin.x * 1.7 + float(INSTANCE_ID));
}

void fragment() {}
NameTypeIn / outMeaning
VERTEXvec3in / outobject-space position (skinned: after skinning)
NORMALvec3in / outobject-space normal, as the mesh stores it (the template normalizes it per fragment)
UVvec2in / outUV0 as the mesh stores it; fragment()'s UV is this times uvScale plus uvOffset
COLORvec4in / outvertex color, white if the mesh has none; fragment() reads what this writes

World space: read world positions with mul(MODEL_MATRIX, vec4(VERTEX, 1.0)) (wind phases, noise lookups); write offsets in object space. For an unscaled, unrotated mesh the two are the same.

Stages: a .kshader compiles into fs_mesh (main pass), its shadow variant (fs_mesh with KAST_SHADOW: it runs fragment(), discards below the cutoff and stops, so ALPHA cutouts and discard written in fragment() also cut the shadow, on mask materials as in the main pass) and, if it has a vertex(), the three vertex templates. The shadow passes reuse the main pass's vertex shaders, so 2 or 5 compiles make 6 programs (main and shadow for single, skinned and instanced draws). Without vertex() the built-in vertex shaders are used. Each stage compiles only its own function: the other one is blanked (line numbers kept). Code outside both functions (helpers, #defines) is compiled into every stage, so it may only use built-ins every stage has (TIME, CAMERA_POSITION, VIEW_MATRIX, PROJECTION_MATRIX, MATERIAL_*, PI, params).

Culling: draws are culled by the mesh's undisplaced bounds; a vertex() that moves geometry far outside them can pop out at the edge of the view or a shadow cascade.

Compiling and errors

The editor compiles a .kshader the first time a rendered material uses it, and again when the file changes, with the same shaderc and flags as the build (CMake copies shaderc.exe next to kast_editor.exe, with kshader/include/ (bgfx's bgfx_shader.sh, bgfx_compute.sh) and kshader/mesh/ (the templates, mesh.sh and varying.def.sc) beside it). Each compile is logged (Compiled shader 'shaders/stripes.kshader'); both editor views share it. For now it compiles on the render thread, pausing the editor for the compile (about 0.1 s per stage). The player does not compile shaders.

Errors render every material using the shader magenta (the errorMaterial) and log one error per load, with the line in the .kshader: Kast puts a #pragma kast_line <n> marker before each of its lines, and maps the line of shaderc's error back to the nearest marker. Examples:

[error] Shader 'shaders/broken.kshader': line 7: error X3004: undeclared identifier 'undeclaredThing'; rendering it magenta
[error] Shader 'shaders/bad_param.kshader': line 4: unknown param type 'vec5': float, vec2, vec3, vec4, color or texture2D; rendering it magenta
[error] Shader 'shaders/none.kshader': cannot read the file; rendering it magenta
[warn] Shader 'shaders/showcase.kshader': param 'stripes' is a float: its value must be a number; rendering the material magenta
[warn] Shader 'shaders/showcase.kshader' declares no param 'removed_param'; ignoring the material's value

A missing ; is reported on the line where the compiler sees the next token, as in any C compiler. Only errors within shaderc's listing (the lines around its first error) map to .kshader lines; others say generated line <n>. Preprocessor errors (an unterminated #if) are logged as shaderc prints them.

Samples: tests/project/shader_showcase.scene (shaders/showcase.kshader: params, a texture param, TIME, vertex colors on models/vertex_colors.gltf) and tests/project/shader_errors.scene (a GLSL error, a bad param line, a missing shader, a wrong-typed value), tests/project/shader_vertex.scene (shaders/sway.kshader: vertex() on a cutout cube, an instanced batch and a skinned model) and tests/project/shader_vertex_offset.scene (must match shader_vertex_offset_reference.scene exactly: lifted meshes and their shadows, and a fragment() cutout with no shadow).
