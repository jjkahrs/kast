Shaders

Every mesh in Kast (primitives, models, terrain) is drawn by one built-in physically based shader: base color, metallic and roughness, normal, occlusion and emissive maps, a directional light and up to 8 point, spot and area lights with shadows, ambient light and fog. A material (.mat) only sets that shader's inputs.

To change how a surface looks beyond those inputs, write a user shader: a .kshader file with a fragment() function (per pixel), and optionally vertex() (per vertex) and light() (per light), plus the params it exposes to materials. It works like Godot's spatial shaders: you write only the part that is different, and Kast keeps doing the rest (transforms, skinning, instancing, shadows, lighting, fog). This page is the reference; Shaders in the editor shows the workflow (creating, assigning, editing and debugging a shader).

Quick start

  1. In the Assets panel, Create > Shader. Kast writes new_shader.kshader, a commented starter that compiles.
  2. Select a .mat and pick the file in the Inspector's Shader section (or set "shader": "shaders/new_shader.kshader" in the .mat). Every mesh using that material now runs it.
  3. Double-click the .kshader to open it in your external editor. Each save recompiles it and the views update in well under a second. Errors show in the Inspector and the log at your file's line.
  4. Set the params per material in the Inspector, or from Lua with kast.setMaterialProperty.
// shaders/stripes.kshader
param color tint = color(1.0, 0.6, 0.3);
param float stripes = 6.0 range(1, 20);
param float speed = 0.5 range(0, 4);
param texture2D pattern = white srgb;

void fragment()
{
    float band = step(0.5, fract(UV.x * stripes + TIME * speed));
    ALBEDO *= tint.rgb * COLOR.rgb * mix(0.35, 1.0, band) * texture2D(pattern, UV).rgb;
    EMISSION += vec3(0.0, 0.3, 1.0) * band;
}

A .mat using it (the material's own fields still apply: fragment() starts from them):

{
  "version": 3,
  "baseColor": [0.8, 0.8, 0.8, 1],
  "shader": "shaders/stripes.kshader",
  "params": { "stripes": 10, "tint": [0.2, 0.6, 1, 1], "pattern": "textures/checker.png" }
}

How Kast runs your shader

Kast's mesh shaders are templates (engine/shaders/fs_mesh.sc, vs_mesh.sc, vs_mesh_skinned.sc, vs_mesh_instanced.sc, with mesh.sh holding the uniforms and built-ins they share). Each has a //@user line where Kast pastes your .kshader, and an empty default for each function you leave out. The built-in shader is the template compiled with nothing pasted in, so built-in and user shaders share every line of transform, skinning, instancing, lighting, shadow, fog and alpha code and cannot drift apart. The fragment template runs, per pixel:

  1. Fills every built-in with what the built-in material computes: ALBEDO = base color times its texture, METALLIC / ROUGHNESS times their texture, EMISSION, NORMAL_MAP, AO and so on.
  2. Calls your fragment(), which may read and change them.
  3. Discards the pixel if ALPHA is below the cutoff (alphaMode mask).
  4. Unlit materials stop here and output ALBEDO + EMISSION.
  5. Applies the normal map to NORMAL.
  6. Lights it: the built-in Cook-Torrance, or your light() once per light. Shadows are included either way.
  7. Adds ambient light times AO, then EMISSION, then fog. The ambient is the flat ambient color with the sky off, or image-based lighting (the sky's, or a baked reflection probe's: diffuse from its spherical harmonics, specular from its prefiltered cube at ROUGHNESS) with the sky on or inside a probe's box, for every .kshader as for the built-in material, whether or not it has a light().

So a fragment() that writes nothing renders exactly like the material without a shader (a test checks this pixel for pixel). Your vertex() runs per vertex before the template moves the vertex to the world, in every pass that draws the mesh, shadow passes included.

The .kshader file

A .kshader is a text file in the bgfx .sc dialect: GLSL-style names (vec3, mix, fract, texture2D) compiled to Direct3D 11 HLSL. It contains, in any order:

  • param lines (below), one per line, each starting with param;
  • void fragment() (required), void vertex() and void light() (optional), each written with no parameters, as here;
  • optionally your own helper functions, constants and #defines (see Helpers and stages).

Differences from Godot's and plain GLSL that trip people up:

  • A one-number vector is vec3_splat(0.5), not vec3(0.5) (an HLSL error).
  • A matrix times a vector is mul(M, v), not M * v (which multiplies component by component).
  • saturate(x) clamps to 0–1; texture2DLod(t, uv, 0.0) samples without derivatives (needed in vertex()).
  • HLSL keywords can't be names, even where GLSL allows them: line, point, triangle, sample, linear, ... (float line = ... fails with syntax error: unexpected token 'line').

Params

Params are the values a material (or Lua) sets for your shader; in the code they read like constants. One declaration per line:

vertex()

Optional. Runs per vertex, before the template moves the vertex to the world, so it changes the mesh in object space (the space the mesh's vertices are stored in). Skinned meshes run it after skinning (in the model's space), instanced copies each get their own MODEL_MATRIX. Every built-in starts as the mesh's own value, so a vertex() that writes nothing changes nothing. The shadow passes run the same vertex shader, so shadows follow the displacement.

param float sway = 0.4 range(0, 1);
param float speed = 1.5 range(0, 8);

void vertex()
{
    vec3 origin = mul(MODEL_MATRIX, vec4(0.0, 0.0, 0.0, 1.0)).xyz; // the object's world position
    float h = saturate(VERTEX.y + 0.5);                              // 0 at a primitive cube's bottom, 1 at its top
    VERTEX.x += sway * h * h * sin(TIME * speed + origin.x * 1.7 + float(INSTANCE_ID));
}

void fragment() {}

  • World space: read world positions with mul(MODEL_MATRIX, vec4(VERTEX, 1.0)).xyz (for wind phases, noise lookups), but write offsets in object space. For a mesh that is scaled, divide a world offset by the scale, e.g. length(mul(MODEL_MATRIX, vec4(1.0, 0.0, 0.0, 0.0)).xyz) for X (the wind sample does this). There is no inverse matrix built-in.
  • Culling uses the mesh's undisplaced bounds: a vertex() that moves geometry far outside them can pop out at the edge of the view or a shadow cascade. Keep displacements small relative to the mesh.
  • vertex() can't change the tangent.

light()

Optional. With a light(), the template calls it instead of its own Cook-Torrance lighting: once for the scene's directional light (if there is one) and once for each point, spot and area light reaching the mesh (up to 8 of them together, see Coordinates and scenes). Each call adds its share to DIFFUSE_LIGHT and SPECULAR_LIGHT, which start black; their sum is the direct light. Ambient light (times AO), EMISSION and fog are then added as without a light(). Kast does not multiply DIFFUSE_LIGHT by ALBEDO afterwards: do it yourself. Unlit materials never call light().

param float bands = 3.0 range(1, 8);

void fragment() {}

void light()
{
    float lit = saturate(dot(NORMAL, LIGHT_DIRECTION)) * ATTENUATION;
    DIFFUSE_LIGHT += ALBEDO * LIGHT_COLOR * (ceil(lit * bands) / bands);
    vec3 halfway = normalize(LIGHT_DIRECTION + VIEW);
    SPECULAR_LIGHT += LIGHT_COLOR * step(0.97, dot(NORMAL, halfway)) * step(0.01, lit);
}
NameTypeIn / outSpaceMeaning
LIGHT_DIRECTIONvec3inworld, unitfrom the surface toward the light; an area light: toward its closest point on the rect
LIGHT_COLORvec3inlinearthe light's color times its intensity
ATTENUATIONfloatin0–1point lights: distance falloff times shadow; spot lights: distance falloff times cone falloff times shadow; area lights: see below; the directional light: its shadow. Shadow factors are 1 when the mesh doesn't receive shadows
NORMALvec3inworld, unitafter fragment() and the normal map
VIEWvec3inworld, unitfrom the surface toward the camera
ALBEDO, METALLIC, ROUGHNESSvec3, floatinwhat fragment() left; metallic clamped to 0–1, roughness to 0.04–1
DIFFUSE_LIGHT, SPECULAR_LIGHTvec3in / outlinear HDRthe sums so far: add this light's part with +=
TIME, CAMERA_POSITION, MATERIAL_*, PI, paramsinas in fragment()

The other fragment() built-ins (UV, COLOR, WORLD_POSITION, ...) don't exist in light(): using one is a compile error at its line. To reproduce the built-in lighting (and then change it), call the template's own function: DIFFUSE_LIGHT += shade(NORMAL, VIEW, LIGHT_DIRECTION, LIGHT_COLOR * ATTENUATION, ALBEDO, mix(vec3_splat(0.04), ALBEDO, METALLIC), METALLIC, ROUGHNESS); renders exactly as the material without a shader under the directional and point lights (spot lights: the same, up to float rounding).

Area lights (an approximation): the built-in shader integrates the whole rect (Linearly Transformed Cosines), but light() gets one direction per light, so for an AreaLight LIGHT_DIRECTION points at the rect's point closest to the surface and ATTENUATION is the rect's diffuse form factor (what fraction of the surface's cosine-weighted view it fills) divided by dot(NORMAL, LIGHT_DIRECTION) there (capped at 1), times its range fade and shadow. A Lambert light() (LIGHT_COLOR * ATTENUATION * N·L) then gets about the built-in diffuse; a specular term computed from LIGHT_DIRECTION highlights that one point, not the rect's reflection. No new built-in names: spot and area lights use the same ones.

SCREEN_TEXTURE and DEPTH_TEXTURE

For refraction, heat haze, soft intersections and shorelines a transparent surface needs to see what is behind it. SCREEN_TEXTURE is the scene's color as the opaque and mask meshes and the sky left it (linear HDR, fogged, before post-processing); DEPTH_TEXTURE is their depth (0–1, 1 = the far plane). Sample both at SCREEN_UV (plus an offset for refraction). linearDepth(d) turns a depth value into meters in front of the camera, comparable with -VIEW_POSITION.z, the surface's own:

// for an alphaMode blend, unlit material
param float strength = 0.015;
param float foam_depth = 0.3;

void fragment()
{
    vec2 wave = vec2(sin(UV.y * 60.0 + TIME * 3.0), cos(UV.x * 60.0 + TIME * 3.0)) * strength;
    float behind = linearDepth(texture2D(DEPTH_TEXTURE, SCREEN_UV).r) + VIEW_POSITION.z; // meters past the surface
    ALBEDO = texture2D(SCREEN_TEXTURE, SCREEN_UV + wave).rgb;                         // refraction
    ALBEDO = mix(ALBEDO, vec3_splat(1.0), 1.0 - saturate(behind / foam_depth));       // foam near geometry
    ALPHA = 1.0;
}
  • Blend and additive materials only. They are copies of the opaque scene, made after it is drawn and before the transparent surfaces, so an opaque or mask material (which is part of that scene) can't sample them. Such a material renders magenta with a warning, the Inspector shows the reason in red, and the Build fails on a shipped one: SCREEN_TEXTURE is only for blend and additive materials (drawn after the opaque scene it copies); this material's alphaMode is opaque.
  • Only when used. The copies (color and depth separately) are made once per frame, and only on frames where a transparent surface in view samples them, so they cost nothing otherwise.
  • Other transparent surfaces (glass, particles, other water) are not in the copy, so they don't show through each other.
  • Shadow passes never sample them: transparent materials don't cast shadows.
  • Use them inside fragment() only (helper functions also compile into the vertex stages, which don't have them).

Texture slots

A Direct3D 11 draw can bind 16 textures (sampler stages 0–15; bgfx's maxTextureSamplers, and the renderer logs an error at start if a GPU reports fewer). The mesh shader uses:

StagesUsed for
0, 1base color, metallic-roughness texture
2–6shadow maps (the atlas of directional cascades and spot / area light tiles, point light cubes)
7, 8, 9normal texture, environment cube (image-based lighting; the occlusion texture shares stage 1, packed as glTF's ORM), emissive texture
10–13your texture2D params, in declaration order
14, 15SCREEN_TEXTURE, DEPTH_TEXTURE

So a shader can declare at most 4 texture2D params. A 5th is a parse error: line 5: too many texture2D params: at most 4 (sampler stages 10..13; ...). The material's own textures (stages 0, 1, 7–9) are still free to use through ALBEDO, the sample*() helpers and so on, so pack extra data into them or into the channels of one texture if you need more.

Helpers and stages

One .kshader is compiled into several GPU programs: the main pixel shader, a shadow pixel shader (your fragment() run only for its ALPHA cut and discard, so cutouts appear in shadows), and, if it has a vertex(), one vertex shader each for single, skinned and instanced meshes (shadow passes reuse them). Without a vertex() the built-in vertex shaders are used. Each stage compiles only its own function; the others are blanked (line numbers kept).

Code outside the stage functions (helper functions, constants, #defines) is compiled into every stage, so it may use only what every stage has: TIME, CAMERA_POSITION, VIEW_MATRIX, PROJECTION_MATRIX, MATERIAL_*, PI and your params. Pass anything else (UV, WORLD_POSITION, ...) in as an argument. The water sample's waves(xz) helper is shared this way by vertex() (to move the surface) and fragment() (for its normal).

Compiling, hot reload and the cache

The editor compiles a .kshader the first time a rendered material uses it, with bgfx's shaderc (CMake copies shaderc.exe next to kast_editor.exe, with kshader/include/ (bgfx's shader headers) and kshader/mesh/ (the templates)). Each compile is logged: Compiled shader 'shaders/stripes.kshader' in 0.15 s.

  • Never blocks a frame. shaderc runs on a worker thread. Until a shader's first compile finishes, the meshes using it are not drawn (no magenta flash). Editor runs with --screenshot (tests) compile when first drawn instead, so screenshots repeat exactly.
  • Hot reload. Saving the file recompiles it (Recompiled shader '...'); the previous version keeps rendering until the new one is ready, typically about a quarter of a second after the save. A broken save keeps the last good version rendering and shows the error.
  • Cache. Each stage's bytecode is kept in <project>/.kast/shader_cache/<key>.bin, the key a hash of the file's text, the stage and the template version (the files under kshader/ and shaderc.exe). An unchanged shader is not recompiled on the next editor start (Compiled shader '...' (cache hit)); a Kast update that changes the templates recompiles everything once. The folder never ships and is never pruned: delete it to clear it.
  • Built games don't compile: the editor's Build compiles every shipped .kshader into game.pak, failing on any error, and the player only loads that bytecode (Loaded shader '...' (precompiled)). shaderc never ships.

Errors

A shader that fails to parse or compile renders every material using it magenta (or, if it compiled before, keeps the last good version) and logs one error naming the file and the line in your .kshader. The same text is in the Inspector for the .kshader and for every .mat using it.

[error] Shader 'shaders/broken.kshader': line 7: error X3004: undeclared identifier 'undeclaredThing'; rendering it magenta
[error] Shader 'shaders/bad_param.kshader': line 4: unknown param type 'vec5': float, vec2, vec3, vec4, color or texture2D; rendering it magenta
[error] Shader 'shaders/none.kshader': cannot read the file; rendering it magenta
[error] Shader 'shaders/x.kshader': no fragment() function: a .kshader needs one, as void fragment() { ... }; rendering it magenta
[error] Shader 'shaders/x.kshader': line 3: param 'ALBEDO' has the name of a built-in; rendering it magenta
[error] Shader 'shaders/x.kshader': line 3: error X3004: undeclared identifier 'missingName'; the last good version keeps rendering
[warn] Shader 'shaders/showcase.kshader': param 'stripes' is a float: its value must be a number; rendering the material magenta
[warn] Shader 'shaders/showcase.kshader' declares no param 'removed_param'; ignoring the material's value
[warn] Shader 'shaders/water.kshader': SCREEN_TEXTURE is only for blend and additive materials (...); rendering the material magenta
  • The first word after the line number (error X3004) is the HLSL compiler's error code; the message is about the HLSL it compiled, so names like float3 may appear where you wrote vec3.
  • A missing ; is reported on the line of the next token, as in any C compiler.
  • Kast maps lines through #pragma kast_line markers in the generated code. Only errors within shaderc's listing (the lines around its first error) can be mapped; others say generated line <n>. Fix the first error first. Preprocessor errors (an unterminated #if) are logged as shaderc prints them.
  • The two [warn] kinds about values are per material: the shader is fine, the .mat (or Lua) gave a value that doesn't fit it. A value for a param the shader no longer declares is ignored, so renaming a param never breaks old materials.

In the editor and Lua

The editor workflow (Assets > Create > Shader, the Inspector's status and param widgets, undo, renames) is on Shaders in the editor. From Lua, kast.getMaterialProperty(id, name) and kast.setMaterialProperty(id, name, value) take a shader's params as well as the material's fields: a number, an array or {x =, y =[, z =, w =]} table, or a texture path for a texture2D. Setting one gives the entity its own copy of the material (other entities keep theirs), and Stop discards it. Reading a param the material doesn't set returns its default. A material field with the same name wins.

-- scripts/dissolve_driver.lua (custom_shaders.scene): dissolve and re-form every 6 seconds
local elapsed = 0
return {
    update = function(dt)
        elapsed = elapsed + dt
        local threshold = 0.5 - 0.5 * math.cos(2 * math.pi * elapsed / 6)
        for e in kast.query("MeshRenderer") do
            if kast.get(e, "MeshRenderer").material == "materials/shader_dissolve.mat" then
                kast.setMaterialProperty(e, "threshold", threshold)
            end
        end
    end,
}

Coming from Godot

The model is Godot 4's spatial shaders, and most built-in names are the same. The language is not: a .kshader is bgfx's GLSL-like .sc dialect (compiled to HLSL), not Godot's shading language, so translate by hand. Built-in shaders (engine internals)

Engine developers only: you don't need this section to write .kshader files. Kast's own shaders (editor/shaders/*.sc for ImGui, engine/shaders/*.sc for meshes and grid lines, engine/shaders/gui/*.sc for game GUIs, engine/shaders/post/*.sc for the post-processing passes; each directory has its own varying.def.sc) are compiled at build time to Direct3D 11 bytecode headers (-p s_5_0) with shaderc from vcpkg's bgfx[tools] (a host dependency in vcpkg.json). Sources stay editable and always match the installed bgfx version. User shaders use the same shaderc and flags at run time.

Meshes and shadow casters have three vertex shader variants each: vs_mesh / vs_shadow (one draw, model matrix from u_model), vs_mesh_skinned / vs_shadow_skinned (plus bone matrices) and vs_mesh_instanced / vs_shadow_instanced (model matrix per instance in i_data0..3, see Instancing and culling). The single and instanced variants transform the same way (model, then u_viewProj), so a mesh covers the same pixels either way. Materials with a .kshader use the vs_mesh* variants in the shadow passes too.

Mesh vertices and tangents

Every mesh vertex layout (primitives and terrain: position, normal, tangent, UV0; models: the same plus joint indices and weights) has a vec4 tangent (a_tangent, TANGENT): xyz points along increasing texture u, and w (±1) is the handedness, so the bitangent cross(normal, tangent.xyz) * w points toward the image's top (decreasing v, the normal map's +Y). Sources: the built-in cube, plane and sphere compute them exactly; terrain uses world +X made perpendicular to each vertex normal (w = 1); models get Assimp's tangents (aiProcess_CalcTangentSpace) made perpendicular to the normal, with w from the triangles' UVs; vertices without UVs get any unit vector perpendicular to the normal. vs_mesh and vs_mesh_instanced carry the tangent by the model matrix (not the normal matrix) and vs_mesh_skinned skins it like the normal first; a mirroring model matrix flips w. fs_mesh makes the interpolated tangent perpendicular to the normal again (Gram-Schmidt) before applying the normal map. The shadow shaders read only the position and UV of the same buffers, so their output is unchanged.

Every layout also has a vertex color (a_color0, COLOR0, RGBA8 normalized, linear): a model's glTF COLOR_0 (8 bits per channel; RGB colors get alpha 1), else white, as for the primitives and terrain. The vertex shaders pass it on as v_color0; the built-in material ignores it, a .kshader reads it as COLOR.

Mesh material inputs

fs_mesh samplers: s_baseColor (stage 0), s_metallicRoughness (1), the shadow maps (2–6), s_normal (7), s_env (8, the environment cube), s_emissive (9), .kshader texture params (10–13), s_kastScreen / s_kastDepth (14, 15). Uniforms besides the lights: u_baseColor, u_emissive, u_material (metallic, roughness, alpha cutoff, output mode 0 opaque / 1 blend / 2 additive), u_materialExt (normal scale, occlusion strength, normal map bound, unlit), u_materialOrm (whether s_metallicRoughness holds the metallic-roughness texture, x, and the occlusion, y), u_envSh[9], u_envSpecular, u_envBox[2] (the environment: spherical harmonics, specular tint and roughness 1 mip, probe box), u_uvTransform (UV scale xy, offset zw; also read by fs_shadow for mask cutouts), u_kastParams[16] (.kshader numeric params).

u_time (vec4, x = seconds) is set for every mesh draw. In the editor it advances by each frame's delta in edit mode and in Play (by exactly --fixed-dt per frame when that option is given) and holds while Play is paused; the player advances it every frame. It wraps to 0 every 3600 seconds (kShaderTimePeriod in engine/shader_clock.h) so it keeps sub-millisecond float precision. The built-in material doesn't read it; a .kshader reads it as TIME.

Opaque meshes and the sky draw in the scene's bgfx view; blended meshes and particles in the view after it (same target), at whose start the SCREEN_TEXTURE / DEPTH_TEXTURE copies (an RGBA16F and a D24S8 blit) happen when needed. A renderer drawing without a target (Renderer::setTarget not called) samples black and the far plane instead. Adding a built-in: define it in mesh.sh (every stage) or fs_mesh.sc and add its name to shaderBuiltinNames() in engine/shader.cpp (a self-check fails otherwise).
