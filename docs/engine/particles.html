Particles

A ParticleEmitter component turns an entity into a GPU particle system: fire, smoke, sparks, magic. Particles are spawned, moved and killed by a compute shader (engine/shaders/cs_particle_sim.sc) and drawn as camera-facing, unlit, fogged billboards (vs_particle.sc / fs_particle.sc). The CPU only keeps each emitter's clock and decides how many particles to spawn (engine/particles.h). The Scene view previews emitters in edit mode, and the Game view, Play and the built game all draw them. The editor side (the shape gizmo, the Inspector's Restart / Pause / count and GameObject > Particle System) is in Editor controls.

Particle state (the clock, live particles) is runtime only: it is never saved, never copied by Duplicate or a prefab, and Play's Stop throws it away with the rest of the Play scene, so the edit-mode preview starts over.

Fields

Defaults are what Add Component, GameObject > Particle System and kast.add start with. Ranges are min/max pairs: each particle picks uniformly between them, in either order. Colors are linear RGB.

Scene file

The campfire flame in samples/starter-mmo/scenes/meadow.scene:

"ParticleEmitter": {
  "playOnStart": true,
  "looping": true,
  "duration": 5,
  "rate": 45,
  "burstCount": 0,
  "maxParticles": 64,
  "shape": "cone",
  "coneAngle": 10,
  "radius": 0.3,
  "boxSize": [1, 1, 1],
  "emitFromSurface": false,
  "lifetimeMin": 0.6,
  "lifetimeMax": 1.0,
  "speedMin": 0.9,
  "speedMax": 1.6,
  "startSizeMin": 0.5,
  "startSizeMax": 0.75,
  "endSize": 0.3,
  "startColor": [4, 1.5, 0.35],
  "endColor": [1.2, 0.2, 0.02],
  "startAlpha": 1,
  "endAlpha": 0,
  "gravity": [0, 0, 0],
  "space": "world",
  "texture": "textures/particles/fire.png",
  "blend": "additive"
}

Like every built-in component, all fields must be present (the editor always saves all of them): a missing field ("ParticleEmitter": missing field "playOnStart"), a wrong type, an unknown enum value or a value out of range fails the scene load with a message naming the field ("maxParticles" must be between 1 and 65536) and leaves the open scene as it was. Texture paths are not checked at load.

Shapes

Shapes live in the entity's local space, so its Transform positions, turns and scales them. Kast is Y-up (Coordinates and scenes): an unrotated emitter sprays upward.

  • cone: from a disc of radius in the local XZ plane, each particle heading within coneAngle of local +Y (uniform over that cap of directions). coneAngle 0 is a beam, 90 a hemisphere, 180 every direction.
  • sphere: from inside a ball of radius (uniform by volume), each particle heading straight out from the center.
  • box: from inside boxSize centered on the entity, every particle heading along local +Y (a curtain or rain sheet; turn the entity upside down for rain).

With emitFromSurface the cone spawns on its disc's rim, the sphere on its shell and the box on a random face. Each particle's spawn time is spread over the frame, so a fast stream doesn't come out in clumps.

Space

  • world [default]: particles are spawned at the entity's current transform and then stay in the world; a moving emitter leaves a trail (a torch carried by a running character). Gravity is world space.
  • local: particles live in the entity's space and move, turn and scale with it (an aura around a moving character). Gravity is still given in world space and turned into the entity's space each frame.

Blend

  • alpha [default]: ordinary transparency (src * alpha + dst * (1 - alpha)): smoke, dust, leaves.
  • additive: src * alpha + dst, light that only brightens: fire, sparks, magic. Order doesn't matter, so overlaps never look wrong.

Particles are drawn after the opaque meshes and the sky, depth tested against them but not writing depth. Each emitter is one draw, sorted back to front with the other blended draws (transparent meshes, other emitters) by its position; the particles inside one emitter are not sorted, which is invisible for additive particles and usually fine for soft alpha ones.

Fog: particles are fogged like meshes (Post-processing and fog). Alpha particles fade toward the fog color; additive ones fade toward black (adding fog color would brighten them).

Texture

A PNG or JPG in the project, read as sRGB like a material's base color. Its RGB multiplies the particle's color and its alpha the particle's alpha, so a white image with the shape in alpha is tinted by startColor / endColor. The image covers the whole billboard, its top-left at the quad's top-left. An empty texture draws a soft round falloff. A missing or unreadable file logs one warning (Texture 'textures/missing_particle.png': cannot read the file) and draws the soft circle. samples/starter-mmo/textures/particles/ has 64x64 fire.png, smoke.png and spark.png.

Culling bound

With culling on, an emitter is simulated and drawn only while a box around its world position intersects the camera's view (Instancing and culling). The box's half size is the farthest a particle can get:

shape reach x scale    (radius, or half the box diagonal; times the entity's largest scale)
+ max(|speedMin|, |speedMax|) x max lifetime    (times that scale in local space)
+ 1/2 |gravity| x max lifetime^2
+ 1/2 max start size x max(1, endSize)

Known gap: a world space emitter that moves leaves particles behind it, outside that box, so a long trail can be culled a little early once the emitter itself is out of view. Culling saves only the draw: off-screen emitters are still simulated every frame, so they look right the moment they come back into view.

Time

Emitters tick in Play (and the built game) with the frame's time, and in the editor's edit mode for the preview. A frame longer than 0.1 s (a hitch, a load) simulates only 0.1 s, so particles never jump or flood. Pausing Play holds them. --fixed-dt S (command line) steps every frame by exactly S for repeatable captures. Each emitter's random stream is seeded from its entity, so two identical emitters don't look identical.

No compute shaders

The simulation needs compute shaders (Direct3D 11/12, Vulkan or OpenGL 4.3). On a GPU or renderer without them (BGFX_CAPS_COMPUTE missing, also the Noop renderer of headless runs), Kast logs one warning, Particles: the GPU has no compute shader support; ParticleEmitters are not drawn, and skips every emitter. Nothing else changes: the scene loads, the CPU clocks still tick and the Lua API still works. There is no CPU fallback.

Lua

Fields are ordinary component fields: kast.get(e, "ParticleEmitter"), kast.set(e, "ParticleEmitter", {rate = 50}) (partial; colors, box size and gravity as {x =, y =, z =} tables, enums as strings) and kast.add / kast.remove. A change takes effect on the next frame; changing maxParticles empties the emitter (its GPU buffer is remade). kast.particles controls an emitter at runtime; none of it is saved. Every function takes an entity id like the rest of the API; an invalid id raises (invalid entity id X) and an entity without an emitter raises kast.particles.<fn>: entity X has no ParticleEmitter.

FunctionReturnsNotes
kast.particles.play(e)—Starts emitting, or resumes a paused emitter. A stopped emitter starts its cycle over (with its burst).
kast.particles.stop(e, clear)—Stops emitting. clear = true also kills the live particles; otherwise (false or nil) they finish their life.
kast.particles.burst(e, n)integerSpawns n particles (a whole number >= 0) at once, even while stopped or not started; clamped to maxParticles. Returns how many.
kast.particles.alive(e)integerThe live particle count, estimated (see Alive count).
 
-- A one-shot burst of sparks that cleans up after itself (samples/starter-mmo/scripts/combat.lua does this per hit).
local spark = kast.create("Sparks")
kast.set(spark, "Transform", {position = {x = 10, y = 1.2, z = 4}})
kast.add(spark, "ParticleEmitter")
kast.set(spark, "ParticleEmitter", {playOnStart = false, looping = false, rate = 0, maxParticles = 24,
                                    shape = "sphere", lifetimeMin = 0.25, lifetimeMax = 0.5, speedMin = 3,
                                    speedMax = 6, gravity = {x = 0, y = -9.8, z = 0}, blend = "additive",
                                    texture = "textures/particles/spark.png"})
kast.particles.burst(spark, 24)
-- later, in update:
if kast.particles.alive(spark) == 0 then kast.destroy(spark) end

kast.particles also exists in the world server's Lua, CPU only (nothing is drawn there); the server never reads emitters from scenes and nothing about particles is sent over the network. Effects are client side.

Alive count

The count is a CPU estimate, not a GPU readback: the particles spawned within the last max(lifetimeMin, lifetimeMax) seconds of the emitter's simulated time, capped at maxParticles. No particle lives longer than that, so with fixed settings it never under-counts: 0 means every particle is dead, which is what cleanup code needs. It over-counts particles that drew a shorter lifetime and ones replaced early in a full ring. Shortening lifetimeMax while particles are flying can under-count them. The Inspector shows the same estimate.

Limits

  • 65,536 particles per emitter. Each emitter keeps a ring of maxParticles slots on the GPU (48 bytes each) and draws every slot, dead ones collapsing to nothing, so the draw cost follows maxParticles, not the live count: size it to about rate x lifetimeMax + burstCount. tests/scenes/particles_stress.scene (8 emitters, 100,000 live particles) is the benchmark: run it with --play --log-fps --no-vsync.
  • Unlit, no shadows, no collision (physics, terrain or depth), no soft particles (they cut sharply into geometry).
  • Only linear start-to-end color, alpha and size; no curves, flipbooks, trails, sub-emitters or mesh emission.
  • No per-particle sorting (see Blend).
  • No CPU fallback (see No compute shaders) and no network replication.
