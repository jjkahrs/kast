Physics

3D physics on Jolt (engine/physics.h). One Jolt world per Play session, built from the scene at Play start (and on a kast.loadScene switch) and dropped at Stop; the editor's Stop then restores the pre-Play scene as usual. Nothing simulates in Edit mode or while paused. Editor Play and kast_player both run it.

Components (Add Component, Inspector, scene file; values outside the ranges are rejected):

Component Fields [default]
Collider shape box / sphere / capsule / cylinder [box]; size box full extents [1, 1, 1] (> 0); radius sphere / capsule / cylinder [0.5] (> 0); height capsule total height along local Y, both hemispheres included [2] (>= 2 * radius), or an upright cylinder's height (any > 0, flat or tall); center local offset [0, 0, 0]; isTrigger [false]; friction [0.5] (>= 0); restitution [0] (0..1)
Rigidbody motionType static / dynamic / kinematic [dynamic]; mass kg [1] (> 0); gravityScale [1]; linearDamping [0.05] (>= 0); angularDamping [0.05] (>= 0)
CharacterController radius [0.4]; height total [1.8] (>= 2 * radius); maxSlopeDegrees [45] (0..90); stepHeight [0.3] (>= 0)
  • A Collider without a Rigidbody is a static body. A Rigidbody without a Collider is ignored, with one warning naming the entity. CharacterController plus Collider or Rigidbody is an error: logged once naming the entity, shown in red in the Inspector, and the entity gets no physics.
  • Bodies use the entity's world transform at any hierarchy depth. World scale applies: a box per axis, a sphere, capsule or cylinder by the largest axis; center is scaled too. After each step dynamic and kinematic bodies and characters write their pose back into the entity's local Transform (relative to its parent; scale untouched).
  • Kinematic bodies follow their Transform (moved over one step, so they push dynamic bodies) and move by a velocity set with kast.physics.setVelocity.
  • Runtime changes apply before the next step: adding / removing Collider / Rigidbody / CharacterController (kast.add / kast.remove, the Inspector) creates or removes the body; changing their fields rebuilds it; destroying the entity removes it. A Transform changed by anything (kast.set, Rotator, the gizmo in Play, a moved parent) teleports a static or dynamic body (a dynamic one keeps its velocity), moves a kinematic one and sets a character's position.

Gravity: per scene, "physics": {"gravity": [x, y, z]} in the scene file [0, -9.81, 0] (each axis -1000..1000; missing = default, so older scenes load unchanged), edited in Window > Physics (hidden by default; changes apply at once, also in Play, and Stop reverts them). --focus-panel Physics opens it.

Timestep: a fixed 60 Hz step (kPhysicsStep) with an accumulator, independent of the frame rate; at most 4 steps per frame (kMaxPhysicsSteps), time beyond that is dropped (the game slows down instead of spiralling). Each Play frame: C++ systems, then the physics steps (contact events queued), then the Lua updates, then the event drain; so contact events reach subscribers in the same frame, and what Lua changes applies at the next frame's step. Rendering shows the last step's pose (no interpolation).

Events (on the session's event bus, publisher C++; ids are the entity ids kast.* uses; no "stay" events):

Event Payload
collisionEnter {a, b, point = {x, y, z}, normal = {x, y, z}}: the first contact point; normal points from a toward b
collisionExit {a, b}
triggerEnter / triggerExit {a, b}, when either collider isTrigger (triggers block nothing)

Each fires once per pair when it starts / stops touching (a bouncing ball sends enter, exit, enter...; a body falling asleep on the floor does not end its contact). Destroying an entity or removing its body sends the exits of its contacts at once. Characters send these like any body.

Lua: kast.physics (vectors {x =, y =, z =} or {x, y, z}; rotations {x, y, z, w}; bad arguments and the wrong kind of body raise at the calling line):

Function
raycast(origin, direction, maxDistance) nil or {entity, point, normal, distance}, the closest hit; direction need not be normalized
overlapSphere(center, radius), overlapBox(center, halfExtents[, rotation]) list of entity ids touching the shape
getVelocity(id) / setVelocity(id, v) dynamic or kinematic body, or character
getAngularVelocity(id) / setAngularVelocity(id, v) dynamic or kinematic body (radians / s)
addForce(id, f) / addImpulse(id, i) dynamic body; a force acts over the next step, an impulse at once (dv = i / mass)
moveCharacter(id, v) character: walk at v's horizontal part from now on (call again to change or stop; gravity is added)
isGrounded(id) character: standing on walkable ground
getGround(id) character: nil or {entity, normal} of what it stands on

Queries see triggers and characters too. A raycast from inside a character hits that character.

local hero
return {
    init = function()
        hero = kast.query("CharacterController")()
        kast.subscribe("triggerEnter", function(e) kast.log("trigger " .. e.a .. " " .. e.b) end)
    end,
    update = function(dt)
        local x = (kast.input.keyDown("D") and 3 or 0) - (kast.input.keyDown("A") and 3 or 0)
        kast.physics.moveCharacter(hero, {x, 0, 0})
        if kast.input.keyDown("Space") and kast.physics.isGrounded(hero) then
            local v = kast.physics.getVelocity(hero)
            kast.physics.setVelocity(hero, {v.x, 5, v.z})  -- jump
        end
    end,
}

Character controller (Jolt CharacterVirtual): an upright capsule whose bottom is the entity's position (feet, like imported characters' pivot); physics never changes its rotation. It is blocked by static and kinematic bodies, pushes dynamic ones, walks up steps up to stepHeight and slopes up to maxSlopeDegrees, sticks to the floor going down steps, and falls with the scene gravity (characters are Y-up: only gravity's Y part pulls them). setVelocity sets walk and vertical speed together (a jump). It also has an inner body, so bodies, queries and triggers see it.

Editor: the selected entity's collider (or character capsule) draws as a green wireframe in the Scene view, as physics builds it (world position, rotation, scale, center).

Limits: box, sphere, capsule and cylinder colliders only (no mesh or convex hull), one collider per entity, no joints, no collision layers (everything collides with everything), no stay events, no interpolation, client-side only (not networked). Resting bodies sink up to 2 cm into each other (Jolt's penetration slop). Capacity: 65536 bodies.

C++: kast::Physics (from LuaSystems::physics()) has the same queries and controls (std::invalid_argument for the wrong body) and update(dt) returning the steps taken. kast_self_check --bench-physics times 500 dynamic boxes.

Sample: tests/project/physics.scene (ground with a scaled box collider, two falling cubes, a bouncy sphere, a trigger zone the first cube falls through, a character) runs scripts/physics_log.lua, which logs the four events and a raycast at init.
