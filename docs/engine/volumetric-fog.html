Volumetric fog

Volumetric fog fills the air with a lit, shadowed medium: sun shafts through gaps in a roof, cones under spot lights, glowing spheres around lamps, with dense local banks placed by FogVolume components. A camera-aligned 3D grid of froxels is filled, lit with the scene's lights and their shadow maps, and integrated toward the eye every frame on compute (engine/volumetric_fog.h, engine/shaders/cs_volfog_*.sc, volumetric_fog.sh, post/fs_volfog_composite.sc). Opaque meshes get it in a post pass by their depth; blended meshes and particles sample the same grid themselves, so glass and smoke are fogged consistently with what is behind them. The Scene view (with its toolbar's Post box), the Game view and the built game apply it alike.

It is a per-scene setting ("postProcessing" > "volumetricFog"), off by default: a scene without it renders exactly as before. It is separate from the exp² distance fog: either, both or neither can be on, and the distance fog is unchanged. Edit it in Window > Post Processing > Volumetric Fog (live, undoable, marks the scene dirty) or from Lua.

density0.02>= 0extinction per meter at baseHeight

"postProcessing": {
  "volumetricFog": { "enabled": true, "density": 0.06, "albedo": [0.9, 0.9, 0.9], "anisotropy": 0.6, "heightFalloff": 0.05,
                     "baseHeight": 0, "maxDistance": 60, "temporalBlend": 0.9, "lightIntensity": 1, "ambientIntensity": 1 }
}

Every field is optional (missing ones take the default). An unknown field, a wrong type or a value out of range fails the scene's load with an error naming it, e.g. postProcessing.volumetricFog: "anisotropy" must be a number between -0.9 and 0.9, and the open scene is left untouched. With density 0 and no FogVolume of density above 0 nothing runs.

How it works

The grid is 160 x 90 cells across the view by 64 depth slices, spaced exponentially from 0.5 m to maxDistance: slice s (0..64) is at view depth 0.5 * (maxDistance / 0.5)^(s / 64), so near froxels are small and far ones large (kast::froxelSliceDepth / froxelSlice).

  1. Inject (one thread per froxel): the height fog density * exp(-heightFalloff * max(y - baseHeight, 0)) with albedo, plus every FogVolume (below), as scattering albedo * extinction and extinction.
  2. In-scatter: each light's radiance times the Henyey-Greenstein phase (1 - g^2) / (4 pi (1 + g^2 - 2 g cos theta)^1.5) (kast::henyeyGreenstein), times lightIntensity: the DirectionalLight through its shadow cascades, point lights through their cube shadow maps and spot lights through their atlas tile when they cast shadows (unshadowed otherwise), up to 16 local lights; area lights are left out. Plus the scene's flat ambient times ambientIntensity (isotropic). Then blended with the last frame's result at the same world point (reprojected by the camera's last view-projection) by temporalBlend; each froxel is jittered inside itself every frame so the blend smooths the grid's steps. At temporalBlend 0 each froxel is lit at 4 points instead. The history restarts when the fog is turned on or maxDistance changes.
  3. Integrate, front to back per froxel column, each slice energy-conserving over its thickness (Hillaire 2015: S * (1 - e^(-sigma t)) / sigma) times the transmittance in front of it, into a 2D atlas: what the eye sees up to each slice, in-scattered light and transmittance T.
  4. Apply: opaque pixels (and the sky, the whole grid) by their depth, color = color * T + inScattered, before the blended draws; blended meshes (fs_mesh.sc, after the distance fog) and particles (fs_particle.sc) do the same lookup at their own depth. Lookups are dithered by up to half a froxel and the composite by 1/255, so neither the grid nor 8-bit banding shows.

Formats: RGBA16F throughout: density, scattering and its history 3D textures (160 x 90 x 64, 7 MiB each) and the atlas (10240 x 90, 7 MiB): about 28 MiB per view rendering it (the Scene and Game views each own one), made on first use and freed any frame the fog doesn't run.

Limits: reprojection follows the camera only, so moving lights and objects can leave a short trail at a high temporalBlend; the ambient is the flat ambient color, not the sky; at most 8 FogVolumes (the nearest to the eye) and 16 local lights; a .kshader that reads SCREEN_TEXTURE isn't volumetric-fogged on its own surface.

FogVolume

A FogVolume component adds density to a local region: a unit box or sphere (-0.5..0.5) sized, placed and rotated by its entity's world transform. It contributes only while the scene's volumetric fog is on (even at density 0).

FieldDefaultRangeMeaning
shape"box""box", "sphere"the region's shape
density0.1>= 0extinction per meter inside, added to the height fog
albedo[0.9, 0.9, 0.9]0 to 1 eachlinear RGB scattering tint
edgeFalloff0.250 to 1the outer fraction (center to surface) over which it fades to 0; 0 is a hard edge
heightFalloff0>= 0, optionalper meter: thins with height above the volume's lowest point
"FogVolume": { "shape": "sphere", "density": 0.6, "albedo": [0.8, 1, 0.85], "edgeFalloff": 0.6, "heightFalloff": 0.3 }

Its density at a point, with d 0 at the center and 1 on the surface (the box's largest axis, the sphere's radius): density * saturate((1 - d) / edgeFalloff) * exp(-heightFalloff * (y - bottom)), 0 outside (kast::fogVolumeDensity).

In the editor: Add Component > Fog Volume, an Inspector section with these fields (undoable), and a yellow outline of the box or sphere while the entity is selected. It saves in scenes and prefabs like other components; from Lua, kast.get(id, "FogVolume") / kast.set(id, "FogVolume", {...}).

Cost

Debug build, RTX 4070 Ti SUPER, built player at 1920 x 1080 (--gpu-stats, 590 frames each), on tests/project/volumetric_fog.scene: 3.36 ms GPU frame with volumetric fog vs 3.58 ms off (mean of 4 runs each, spread about 0.3 ms): the difference is within the run-to-run noise (an earlier measurement during development gave +0.5 ms). The three compute passes work on the fixed 160 x 90 x 64 grid whatever the resolution; only the composite is per pixel.

Lua

kast.volumetricFog.get() returns the settings as a table; kast.volumetricFog.set{...} changes any of its fields at run time, all-or-nothing and checked as on load (kast.volumetricFog.set: postProcessing.volumetricFog: ... on a bad field).

kast.volumetricFog.set({density = 0.1, anisotropy = 0.7})   -- thicker morning haze, strong sun glow
print(kast.volumetricFog.get().density)

See tests/project/volumetric_fog.scene (the sun through a roof's gaps between pillars, a shadowed point and spot light behind occluders, a glass pane, smoke particles, a box and a sphere FogVolume) and scripts/volfog_set.lua.
