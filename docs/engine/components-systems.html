Components and systems

Components are registered once with entt::meta in engine/components.cpp (registerComponent<T>, a stable type name, then each field with a display name and an optional color hint). ComponentInfo::validate optionally checks values beyond their types (e.g. Camera ranges); loading rejects and the Inspector reverts what it refuses. Field types: float, int, bool, std::string, std::vector<std::string> (a JSON array of strings), bx::Vec3, bx::Quaternion and registered enums. Registration alone gives a component scene-file save/load, copy on Duplicate, Inspector widgets and Add/Remove Component. PersistentId, Name and Hierarchy are structural and not registered.

The uniform layer at the end of engine/components.h (ComponentType, FieldDesc, allComponentTypes, findAnyComponentType, hasComponent/addComponent/removeComponent/componentToJson/setComponentJson) covers built-in and Lua components alike, with JSON as the common value form; scene IO, the Inspector, Add/Remove Component, Duplicate, Play snapshots and kast.* use it. The entt::meta functions above stay for C++ code working with built-ins.

Systems (engine/systems.h) are plain functions void(Scene&, float dt), listed in update order in engine/systems.cpp. Only Play mode runs them, once per frame with the real frame time, never while paused or editing (except that the editor also runs animatorSystem in Edit mode, for the animation preview).
