Tests

  • Self-check (tests/self_check.cpp + tests/lua_checks.cpp, ctest world_self_check): assert-style checks of the pure logic with an injected clock, so nothing sleeps (except the send fan-out check: net::send_many to five sessions on unconnected sockets encodes the message once and leaves exactly proto::encode of it in each one's send buffer, also through the lag simulator, whose timers it waits a few ms for). The Lua checks write their scripts to a temp folder and drive a World with captured sends, saves and log lines. A batching check moves 3 players and a script NPC in view of 2 still players and asserts each of the 5 gets exactly one EntityMoves with every other mover's move and never its own, and that a lone player gets none (it fails if replication goes back to a message per mover). The codec checks round-trip EntityMoves empty, with two entries and full (kMaxEntries, which must fit one frame), and reject a cut entry, a count past the payload, bytes past the count and a NaN position. They cover the event bus (the engine's cases), kast.publish/subscribe/unsubscribe and the client sends: audiences, order, rejections and timing. They also cover state machines, from definitions to C++ / Lua parity, and Lua logging (kast.debug, fields tables, their errors, LOG_LEVEL). Log lines are written by a background thread, so the checks call log::flush() before reading what they captured.
  • AOI differential check (self_check.cpp, checkAoiDifferential): seeded random worlds (20 seeds × 400 ticks; players and NPCs on 3 maps, moves within a cell and across cells, logins and logouts, NPC create / destroy, transfers before and after the aoi pass, Lua-style moves after it, idle ticks) run through the old full recompute (kept in the test) and through aoi_system, which skips players with no touched cell near. After every tick each session's messages (encoded, in order), every Visible.ids / Visible.entered and every NPC's Viewers must be identical; it prints how often each event kind ran and fails if any ran 100 times or fewer. Leaving out any touch (for example the one for a move within a cell) fails it.
  • AOI cost (ctest aoi_bench, world_self_check --aoi-bench): ns per aoi_system call with 500 and 2000 players (plus a fifth as many NPCs) on a 2 km map, all idle, 10% and 100% moving a short step each tick. Printed, not checked.
  • Tile activation (checkTileActivation in lua_checks.cpp, the sample lua/ plus a probe system logging what kast.query("Npc") returns): no spawn-file NPC however long a world runs with no player; a login spawns its tile's and the neighbours' NPCs at once and no farther; a transfer away puts them to sleep without despawning them (absent from kast.query, the Guard's position and patrol state frozen) and loads the destination; a destroyed sleeping NPC respawns exactly respawnSec later, asleep; coming back wakes the same Guard, which walks on to the point it was heading for; nothing spawns twice; kast.create NPCs sleep, and wake when moved onto a near tile; a logout puts the tiles to sleep; ACTIVATION_TILES 2 loads tiles two off. checkConfig refuses ACTIVATION_TILES 0, -1, abc, 1.5 and 33. Checks written for always-on spawns put a watcher player on every spawn spot first (watch_spawns).
  • Map contexts (lua_checks.cpp; Map contexts): checkMapContexts on three maps: the realm's and START_MAP's contexts start with the scripts and the others on first use, each with a map context started debug line; the game machine enters once (in the realm) however many map contexts load fsms/; each map runs its own copy of a system; each map's NPCs are in its own registry; 1,000 NPCs created and destroyed in each of the three contexts, twice, have 3,000 different ids, each valid in exactly one context; the Spawns a player gets carry them, each once; an NPC moved to another map keeps its id. checkWorldPost: kast.world.post to a map id, "realm" and "all" is delivered on the next tick only, in post order per bus, as {from = 1, data} (a C++ subscriber on the realm's bus, a Lua one on each map's); a game machine's callback posting from the realm gives from = "realm"; a bad target (9, 1.5, a string, nil), a bad event name and bad data (infinity, a cycle) raise. checkStarterMmoMapCrossing (the starter-mmo sample plus a probe system): a Warrior with a bag, an active quest and Shield Wall up walks Meadow → Cavern → Meadow through the gates; on each crossing onMapLeave runs once on the map left and onMapEnter once on the map entered, with what onMapLeave returned; every Lua component is the same; MapChange comes before the Despawns and Spawns, all in the portal tick; the watchers on both maps see the same wire id; Shield Wall is still cooling down on both maps and its buff fades in the Cavern; a Bat killed there counts for the quest. The checks that read an entity on another map use that map's registry (World::registry(map), registry_of(e)) and bus; game machines are driven through World::realm_fsm().
  • Activation cost (ctest activation_bench, world_self_check --activation-bench): the median World::tick over 200 ticks (after 50 to warm up) on the injected clock, the sample lua/ running, 100 idle players on one tile of a 32×32 tile map, (a) alone and (b) with 10,000 patrolling spawn-file Guards on 100 tiles 9 or more tiles away. Before (b) a scout logs in on each Guard tile and out again, so the 10,000 exist and sleep. Fails if (b) is more than 110% of (a). Before tile activation (b) was about 270 times (a) (26 ms against 0.1 ms, Release).
  • Logging (ctest log_bench and log_flush): log_bench (world_self_check --log-bench, stdout to the null device) prints the caller-side ns per line of log::info and of the old synchronous write (printed only: one timing sample is too noisy to fail a build on), and checks that 4 threads × 100,000 lines all reach the sink. log_flush checks that the line logged right before a SIGSEGV on the main thread or another thread, an abort(), and a SIGKILL while the writer is busy (a warn line; world_self_check --log-crash segv|segv-thread|abort|kill) and before kast_world's fatal startup error (a missing MAP_ROOT) is on stdout, and that the logger leaves SIGTERM to the app's own handler (--log-crash sigterm).

  • Load (tests/load.sh):
    • Setup: restarts world so its totals cover only the test. It then runs COUNT bots in one process (8 io threads, 50 new connections per second) for DURATION s.
    • Pass criteria:
      • Bot summary PASS: every bot entered the world, with no errors, no unexpected disconnects and no Correction for honest movers. A wanderer that walks into the sample portal stops on the other map (map_changes_recv); the corrections for its moves still in flight are not counted.
      • Every 10 s window's tick p99 is under 25 ms, and so is the run total.
      • Zero failed save attempts.
