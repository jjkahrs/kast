Operations

  • Logs: JSON lines on stdout: ts (UTC, 2026-10-15T12:34:56.789Z), level, msg, then the fields. LOG_LEVEL (debug, info, warn, error) drops lower levels before anything is queued.
    • Asynchronous: the caller (the tick, the DB worker, Lua) only builds the line and queues it; a background thread (Quill) writes stdout. ts is the time of the call, not of the write.
    • Never dropped: each thread's queue grows to 64 MiB; past that the caller blocks until the writer catches up.
    • Flushed on exit: everything queued is written when the process exits normally: after shutdown complete, after SIGINT/SIGTERM (the graceful shutdown, then the normal exit), and after a fatal startup error (exit 1). The logger never handles SIGINT/SIGTERM itself; one that arrives before the server is up kills the process with the default action, and lines still queued are lost.
    • warn and error flushed at once: the writer flushes stdout after each warn or error line, so one already written survives a SIGKILL (a docker stop timeout, the OOM killer). debug/info lines are flushed when the writer is idle.
    • Crashes: SIGSEGV, SIGABRT (abort()), SIGFPE and SIGILL (on Windows abort() and any unhandled SEH exception, such as an access violation, on any thread) write the queued lines, then Received signal/Received exception and Program terminated unexpectedly lines, before the process dies.
  • Tick stats: every TICK_STATS_INTERVAL_SECONDS, the server logs a tick stats line, and a tick stats total line on shutdown. They contain:
    • p50_ms, p99_ms and max_ms: systems time per tick (the whole tick, workers and serial points included).
    • lag_p99_ms and lag_max_ms: how late the tick timer fired.
    • map_threads: MAP_THREADS. contexts: the map contexts updated in the last tick.
    • ctx_p50_ms, ctx_p99_ms and ctx_max_ms: one map context's update time in one tick (its two update steps), over every context and tick of the window (Threading). With MAP_THREADS > 1 a tick takes at least its slowest context, plus the serial points; with 1, about the sum of them.
    • population and connections.
    • saves_ok, saves_failed_attempts and saves_pending.
  • Net stats: with every tick stats line the server logs a net stats line, and a net stats total line on shutdown (since the start). net_threads is NET_THREADS; busy_pct has one number per net thread: its CPU time (TLS, framing, socket calls) over the wall time of the window, in %. A thread near 100 is the network limit: raise NET_THREADS if cores are free. Connections are spread round-robin when they connect, so the numbers can drift apart; nothing rebalances them. Example: {"msg":"net stats","net_threads":4,"busy_pct":[12.5,11.9,13.1,12.2]}.
  • Choosing MAP_THREADS: keep 1 while p99_ms is well under the tick period (50 ms at TICK_HZ 20) or nearly every player is on one map: a single map never splits across threads. Raise it when players spread over several maps and p99_ms climbs: with contexts busy maps, about min(contexts, cores - 2) (the net threads, the DB workers and the log writer need cores too). More threads than busy maps only wait. If ctx_max_ms is close to p99_ms, one map is the bottleneck and more threads will not help; give that map a layerCap instead.
  • Layers (Maps, Layers):
    • layer created (info) {map, name, instance, key: null}: every live layer of the map was full, so an extra layer opened.
    • layer destroyed (info) {map, instance, key: null, npcs}: an extra layer was empty for the map's emptyTimeoutSec.
    • no new layer: overfilling the fullest (warn) {map, instance, players, cap, reason}: every layer was full and no new one could be made (reason: instance ids exhausted or entity ids low); the player joined the fullest layer anyway.
    • saved layer not joinable; placing as a new arrival (info) {char, map, instance, reason}: a login saved in a layer that is full (layer full) or gone (layer gone: closed, or a previous run's).
    • transfer refused: layer full or gone (info) {entity, map, layer}: a kast.transfer with layer =.
    The number of live layers per map is in the admin port's instance list, or layer created minus layer destroyed (tests/load.sh prints the peak).
