Instances

An instance map (a dungeon, a raid, a scenario) runs as many separate copies as groups enter it, each copy its own map context updated in the MAP_THREADS pool like a world map's. This is AzerothCore's MapInstanced / InstanceMap model, simplified: a Lua hook picks a copy by an instance key, copies live in memory only, and there are no binds, resets, difficulties, groups or lockouts.

{ "version": 1, "id": 6, "name": "Crypt", "tiles": [[0, 0, 0, 0]],
  "spawn": {"pos": [128, 0, 128]},
  "type": "instance",
  "maxPlayers": 2,
  "emptyTimeoutSec": 5,
  "exit": {"map": 1, "pos": [1030, 0, 1060], "heading": 3.14} }

map.json fields

Field Value Meaning
type "world" (default) or "instance" A world map has exactly one context (instanceId 0), started as before. An instance map has none at startup; copies are made on entry
maxPlayers integer ≥ 1; absent: no limit Players per copy (NPCs do not count). A transfer into a full copy is refused (below)
emptyTimeoutSec integer 0-31536000, default 300 How long a copy lives once its last player left. 0: destroyed at the next serial point
exit {map, pos, heading}, required Where a character goes when it logs in saved in a copy that is gone (or full). map must be a loaded world map and pos on its tiles, not inside one of its portal areas

The fields are parsed by kast_map (map::parse_manifest), so the server, kast_mapbake and the editor's Zone Builder refuse the same things with the same messages, each naming the file and the field: maps/crypt/map.json: "maxPlayers" must be an integer >= 1 (leave it out for no limit), maps/cave/map.json: "emptyTimeoutSec" is only for instance maps ("type": "instance"). The exit is checked against the other maps once all are loaded (map::exit_error, like a portal destination): maps/crypt/map.json: "exit": position is not on a tile of map 1. Any of these refuses the start. START_MAP must be a world map. A copy shares its map's immutable data (ground, navmesh, areas, objects, the parsed spawn files); its tile activation is its own, so each copy spawns its own NPCs.

Choosing the copy

  • The key: on a transfer into an instance map (a portal or kast.transfer), the source context asks its systems' instanceKey(e, map) in system order; the first non-empty string (at most 255 bytes) is the key. nil from all, or no hook: no key. Returning anything else disables that system, like any callback error. kast.transfer(e, {map =, position =, heading =, instance = "key"}) passes the key directly and the hooks are not asked.
  • The copy: a live copy of that map with that key is used; a key with no live copy makes a new copy registered under it; no key always makes a new keyless copy. Keys are per map. A new copy gets a process-unique uint32 instanceId ≥ 1 (counting up from one above the highest characters.instance_id of the realm, read at startup before players are accepted, so an id saved in an earlier run names no copy of this one; once UINT32_MAX is used no more copies are made, and the transfer is refused like a full copy: transfer refused: no new instance copy {reason: "instance ids exhausted"} logged, instance.full published). The same refusal, with reason: "entity ids low", comes when fewer than 65536 entity indices are unused (kept for world maps and live copies, entity ids); a copy takes its ids in blocks of 256, so about 1800 copies live at once fit. A new copy loads npcs/ and systems/ and runs their init; it is logged as instance created {map, name, instance, key}.
  • Within a copy: kast.transfer onto the copy's own map without instance (or with its own key) teleports within the copy; with another key it moves to that copy. Copies of one map share the map id, so the client gets MapChange with the same map id (see protocol).
  • When: creation and destruction happen only at the serial points, never during the parallel step, so MAP_THREADS=4 makes the same copies with the same ids as MAP_THREADS=1 (the parallel differential check covers it).

A full copy

A player's transfer into a copy that has maxPlayers players is refused: the player stays where it was, gets no MapChange, and instance.full {entity, map, key} is published on the source context's bus (logged transfer refused: instance full). The request checks the copy's player count as of the last serial point plus the players its own context queued for that copy, so kast.transfer returns false; one that filled up since (by another context's transfers or a login) is refused when the transfer is done, with the same event, after kast.transfer returned true. A portal that refuses leaves the player standing in it; it walks out and back in to try again. A new copy is never full.

The empty timer

At every serial point each copy with no player starts its timer (if not running) and each with a player stops it. A copy whose timer passed its map's emptyTimeoutSec is destroyed there: every system's shutdown runs, its NPCs are removed (a spawn NPC that came from another map's spawn file respawns there), its key is free again, and its entity ids go back to the process-wide pool. Logged as instance destroyed. Time is the tick time (an injected clock in the self-checks). A player who enters first cancels the timer.

Relog and restart

characters.instance_id (migration 005) is saved with the position: the copy's instanceId, 0 on a world map. On entering, a character saved on an instance map rejoins its copy at the saved position if that copy is live and has room. Otherwise (the copy was destroyed, the server restarted, the copy is full, or an old row with 0) it enters at the map's exit, logged as saved instance not joinable; entering at the map's exit with the reason (instance gone, instance full, position off the map).

Lua

  • kast.map.instance(): {id, key, map} of the copy this context runs (key nil for a keyless copy), or nil on a world map.
  • Each copy's systems run init when it is made and shutdown when it is destroyed: the per-instance hooks. Module tables are per copy.
  • kast.world.post targets a world map's id, "realm" or "all" (every running context, copies included). An instance map's id raises: it has no single context.
  • kast.create with map = an instance map raises, except from inside a copy of that map (the NPC is made in that copy).

The sample services/world/lua/systems/test_hooks.lua keys copies by what a client sent in a client.test.instance_key event, for the bot scenarios; a game would use its party or raid id.

Admin

The world admin port's AdminInstancesReq lists every live context: map id and name, instanceId (0 for a world map), key, players, NPCs, when it was made and, for an empty copy, when its timer started. The admin app shows it on its Instances page. A layered world map's extra layers are listed the same way (no key).

Layers

A layered world map ("layerCap") reuses this machinery for its extra layers, which are copies of the world map rather than of an instance map. What is the same: each is its own context, made with a fresh instanceId from the same counter, only at serial points, with its own Lua state, tile activation and NPC spawns; it is destroyed after the map's emptyTimeoutSec (default 300) with no players, as an empty copy is; characters.instance_id names it for a relog; when no copy can be made (ids exhausted, entity ids low) the same checks apply. What differs: no keys and no instanceKey (the layerFor hook and the fill-the-fullest placement pick the layer); the base layer (instanceId 0) always exists; a full layer opens a new one instead of refusing, and with no new copy possible the player overfills a layer, so a login or a transfer onto a world map is never refused because of layers; a gone or full saved layer means placement on the same map, not an exit. Only kast.transfer's explicit layer = is refused like a full copy (instance.full {entity, map, layer}).
