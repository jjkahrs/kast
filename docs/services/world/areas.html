Areas

A map can name its regions (zones, subzones, towns) in an optional areas.json next to its map.json. The server always knows which area every player is in. It publishes enter/leave events on the event bus, answers area lookups from Lua, and treats an area with a portal as a zone line to another map.

{ "version": 1, "areas": [
  {"id": "eastvale", "name": "Eastvale", "priority": 0, "rect": [0, 0, 2048, 2048],
   "flags": {"pvp": false, "noMount": false}, "music": "sounds/eastvale.ogg"},
  {"id": "goldshire", "name": "Goldshire", "parent": "eastvale", "priority": 10,
   "polygon": [[1000, 980], [1035, 980], [1035, 1030], [1000, 1030]], "y": [-50, 200], "flags": {"pvp": true}},
  {"id": "cave_mouth", "name": "Cave Entrance", "parent": "eastvale", "priority": 20, "rect": [1040, 990, 1050, 1000],
   "portal": {"map": 2, "pos": [256, 0, 240], "heading": 3.14}}
]}
  • Shape: exactly one of rect [x0, z0, x1, z1] (x0 < x1, z0 < z1) or polygon (at least 3 [x, z] points, any simple polygon, convex or not), on the x/z plane. An optional y [min, max] limits it in height (bounds included). A point exactly on an edge may count as either side.
  • Which area: a point is in the highest-priority area that contains it (default priority 0), or in none. kast_map's area_at does the lookup with a per-tile index built at load. It is pure, so the client can reuse it.
  • Fields: id (unique, required). name defaults to id. music is a project path (not inherited). flags is any JSON object: an area's flags are its parent's (resolved the same way), with its own on top. The server only passes flags on. Game Lua decides what pvp, noMount and the rest mean.
  • Load errors refuse the start, naming the file and area: a bad shape or field, a duplicate id, an unknown parent or a parent cycle, two areas with equal priority that overlap (sharing an edge is fine, and so are disjoint y ranges), a portal to an unknown map, a portal destination that is not on that map's tiles, or one inside a portal area there (so a portal never sends a player straight into another).
  • Events: after movement each tick, each player that moved is looked up again. On a change the bus gets area.leave for the old area, then area.enter for the new one. The payload is {entity, map, area, name, flags}, where area is the area id and flags are the resolved flags. Leaving into no area publishes only area.leave. On login (and after any transfer) the player's area is set the same way, so login publishes area.enter alone; logout publishes nothing (onLeave covers it). NPCs get no area events.
  • Portals: a player who moves into a portal area is sent to portal.map at portal.pos / portal.heading through World::transfer, before the tick's interest pass. The client gets MapChange, then Despawn for its old neighbours, then Spawn for its new ones, all in that tick. The bus gets area.enter for the portal area, then area.leave for it and area.enter for the destination's area. The player is not in a portal on arrival, so it must walk out and back in to return.
Lua
kast.map.area(e) {id, name, flags, music} of the area player or NPC e is in, or nil
kast.map.areaAt(map, x, y, z) The same for a point on loaded map map, or nil. Raises on an unloaded map
