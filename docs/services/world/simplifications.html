Deliberate simplifications

Each is marked // ponytail: in the code with its limit and upgrade path:

  • One database writer per realm: character limits are checked with count-then-insert on the single DB thread. Several world processes per realm would need SELECT … FOR UPDATE.
  • Migration splitter: splits on ; at the end of a line.
  • Component replication diff: only components marked dirty by a writer (kast.add, kast.set, kast.remove, NPC creation, login restore) are compared with the last sent value, and each change is serialized once for all its recipients. A change is still sent as the component's full JSON; delta or binary encoding if bandwidth matters.
  • kast.set through JSON: reuses the definition checks; convert Lua values directly if it shows in profiles.
  • No TLS close_notify on disconnect: peers see EOF.
  • Map bounds by rectangle scan: each bounds check walks a map's tile rectangles. Fine for a handful per map; use a tile set if maps grow many.
  • Area overlap check: an exact test, except that two non-convex polygons with exactly coincident edges and outside centroids can slip through. It compares every pair of areas at load (O(n^2)), which is fine for hundreds per map.
  • Load bots park after a portal: they stop moving on the destination map instead of wandering its bounds.
  • No jump or flying allowance: MOVE_MAX_AIR is one limit for everyone, and NPCs are always on the ground. A jump arc or flying mounts need a per-entity allowance, and flying NPCs a flag.
  • Off the navmesh is corrected at once: a player cannot fall off a cliff face. A grace period (or an allowance while falling) if drops are wanted.
  • Navmesh cell height: fixed at cellSize / 2; a manifest field if maps need finer vertical steps.
  • Zone objects block by navmesh only: the server has no shape collision; an obstacle's whole column under its footprint is cut from the bake, whatever its height. Bridges, overhangs or objects that stop blocking (doors) need the shapes' own y range in the bake and dynamic obstacles (Detour tile cache).
  • No interactable state: the server keeps no cooldown, enabled flag or per-object state, and sends nothing for a rejected Interact; the game's Lua does both if it needs them.
  • 32-bit poly refs: about 4096 polygons per tile at 1024 tiles a map; DT_POLYREF64 past that.
  • One process owns every tile: Maps::owns is always true for a loaded tile. Several processes need a refused transfer to save and send Redirect{host, port, ticket} to the owner.
