Deliberate simplifications

Each is marked // ponytail: in the code with its limit and upgrade path:

  • One database writer per realm: character limits are checked with count-then-insert on the single DB thread. Several world processes per realm would need SELECT … FOR UPDATE.
  • AOI touched cells: the re-bucket after Lua touches the cells of that tick's player movers again, so their neighbours recompute once more on the next tick (with the same result). A separate Lua-moved tag if that shows in a profile.
  • Tiles never unload: a tile that has loaded its spawns keeps them for the life of the process, as in AzerothCore master; sleeping NPCs cost memory, not ticks. Despawn idle tiles on a timer if memory ever matters.
  • A map context starts inside a tick: its Lua state loads (about 30 ms with the sample lua/) at the serial point of its first use, so that tick is late. Start every map's context with the scripts if that hitch matters.
  • One map, one thread: with MAP_THREADS > 1 the map contexts update at once (Threading), but a map never splits across threads, so one crowded map is as slow as with 1.
  • Held sends are copies: during a parallel step each message a context sends is copied into the context and encoded on the tick thread after the barrier. Encode on the worker if the tick stats show the serial part growing.
  • MAX_NPCS in even shares: before each update step what is left under the limit is split evenly among the map contexts, so with several maps a map can be refused an NPC while another's share is unused (until the next step's split). Weight the shares by use if that ever bites.
  • Id blocks: each map context holds a spare block of entity ids (4096; 256 on an instance copy); a context that makes more than that in one update step takes another block mid-step, which keeps ids unique but no longer the same as with 1 thread. Each context's unused ids stay with it.
  • One lock per navmesh: a path search takes its map's lock (Detour's query keeps its search state); only a kast.map.path for another map can wait on it. A query object per context if that shows.
  • Finding an entity's context is a scan: World asks each map context in turn (one per world map in use and one per instance copy) which holds an id, for a session's messages and C++ calls: a hash lookup each. An id-to-context index if thousands of copies live at once.
  • Instances live in memory only: no binds, saved instance state, scheduled resets, difficulties, groups or lockouts (AzerothCore's). A copy is found by its Lua instance key while it lives; a restart (or its empty timeout) loses it, and its players enter at the map's exit. Save the copies' state if a game needs raids that outlive a restart.
  • A full copy is checked twice: kast.transfer can return false only for a copy that was full at the last serial point (counting the context's own queued players); one filled since by another context or a login is refused when the transfer is done, after kast.transfer returned true (instance.full both times). Reserve the place at the request if a game needs the return value exact.
  • Instance ids never wrap: each run's copies count up from one above the highest saved characters.instance_id, so a saved id names no copy of this run. After 232 − 1 copies ever made in a realm no more are made (transfers into a new copy are refused like a full one); reset characters.instance_id to 0 (those players enter at the exits) if a realm ever gets there.
  • Map contexts never stop: a world map's context, once started, stays for the life of the process, like its tiles. An instance copy is destroyed once empty for its map's emptyTimeoutSec; its entity ids go back to the pool.
  • Every context keeps every spawn record: each map context has the full list of spawn file entries (a pointer and a timer each), so a spawn index means the same in all of them; it only spawns its own map's.
  • Sleeping patrols are swept slowly: the sample systems/npcs.lua checks 8 patrol entries a tick for NPCs that are gone (a sleeping one is just missing from kast.query), so a destroyed patrol's few bytes linger for a while. A destroy event if that ever matters.
  • Migration splitter: splits on ; at the end of a line.
  • Component replication diff: only components marked dirty by a writer (kast.add, kast.set, kast.remove, NPC creation, login restore) are compared with the last sent value, and each change is serialized once for all its recipients. A change is still sent as the component's full JSON; delta or binary encoding if bandwidth matters.
  • Move bytes: each player gets one EntityMoves a tick, but at 20 bytes per move the payload is still O(movers × viewers). Quantized or delta-encoded entries, or a lower update rate for far viewers, if bandwidth matters.
  • kast.set through JSON: reuses the definition checks; convert Lua values directly if it shows in profiles.
  • No TLS close_notify on disconnect: peers see EOF.
  • Map bounds by rectangle scan: each bounds check walks a map's tile rectangles. Fine for a handful per map; use a tile set if maps grow many.
  • Area overlap check: an exact test, except that two non-convex polygons with exactly coincident edges and outside centroids can slip through. It compares every pair of areas at load (O(n^2)), which is fine for hundreds per map.
  • Load bots park after a portal: without MAPS they stop moving on the destination map instead of wandering its bounds. With MAPS they walk a straight line to each portal, so the maps must have no obstacle or navmesh edge on the way, and the gates must be clear of the other portals.
  • No jump or flying allowance: MOVE_MAX_AIR is one limit for everyone, and NPCs are always on the ground. A jump arc or flying mounts need a per-entity allowance, and flying NPCs a flag.
  • Off the navmesh is corrected at once: a player cannot fall off a cliff face. A grace period (or an allowance while falling) if drops are wanted.
  • Navmesh cell height: fixed at cellSize / 2; a manifest field if maps need finer vertical steps.
  • Zone objects block by navmesh only: the server has no shape collision; an obstacle's whole column under its footprint is cut from the bake, whatever its height. Bridges, overhangs or objects that stop blocking (doors) need the shapes' own y range in the bake and dynamic obstacles (Detour tile cache).
  • No interactable state: the server keeps no cooldown, enabled flag or per-object state, and sends nothing for a rejected Interact; the game's Lua does both if it needs them.
  • 32-bit poly refs: about 4096 polygons per tile at 1024 tiles a map; DT_POLYREF64 past that.
  • One process owns every tile: Maps::owns is always true for a loaded tile. Several processes need a refused transfer to save and send Redirect{host, port, ticket} to the owner.
