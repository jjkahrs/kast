Chat service protocol

The chat service speaks the world server's protocol (version 8, services/world/protocol/messages.h): the same frames (u16 payload length, u16 opcode, little-endian payload), strings, handshake and heartbeat; see the world protocol for those. Every message below is in its message table too.

Game client connection (CHAT_PORT, 7778)

client                                   chat service
  |---- TLS --------------------------------->|
  |---- Hello{8}, Auth{accessToken} ---------->|  JWKS verify; held until the account's character
  |                                            |  is online (CHAT_BIND_TIMEOUT_MS), else no_character
  |<--- AuthOk{accountId, role} ----------------|
  |<--- ChatChannel{1, General, joined} --------|
  |---- ChatSend / ChatJoin / ChatLeave / ------>|
  |     ChatIgnore / ChatMute                  |
  |<--- ChatLine / ChatChannel / ChatNotice -----|
OpcodeNameDirPayload
0x0001 Hello C u16 protocolVersion (8)
0x0002 Auth C str accessToken, the same as for the world server
0x0102 AuthOk S u64 accountId, u8 role: bound to the account's online character
0x0103 Disconnect S u16 reason (codes; no_character 26 is the chat service's)
0x0003 / 0x0004 Ping / Pong C/S u32 nonce
0x0030 ChatSend C u8 target (0 whisper, 1 channel, 2 zone), str to (a character name, a channel name, empty for zone), str text
0x0031 ChatJoin C str channel (a CHAT_CHANNELS name, any case)
0x0032 ChatLeave C str channel
0x0033 ChatIgnore C str name, u8 on (1 ignore, 0 unignore)
0x0034 ChatMute C str name, u32 minutes (0: unmute). GM / admin only
0x0130 ChatLine S u8 target (0 whisper, 1 channel, 2 zone, 3 whisper_sent), str channel (channel lines), str name (the sender; the recipient for whisper_sent), str text
0x0131 ChatChannel S u8 number, str channel, u8 joined: membership changed (number = place in CHAT_CHANNELS, from 1)
0x0132 ChatNotice S u8 code, str name, u32 minutes: see Notices
0x012A ChatServer S (world) str host, u16 port: the world server says where this service is, right after EnterWorldOk
0x0124 ChatMsg S (world) u8 kind, str fromName, str text: proximity chat (say, yell, emote) stays on the world server

Rules

  • Whisper: to a character name, any case, on any map of any linked world. The sender gets ChatLine{whisper_sent, "", recipient, text} first, the recipient ChatLine{whisper, "", sender, text}. No chat connection: not_online.
  • Channels: the CHAT_CHANNELS list only, numbered from 1 in config order (/1 /2 /3 = General, Trade, LFG by default). Every connect puts the client in the first again; the others are the client's to rejoin. A channel line goes to every member, the sender included.
  • Zone: every connected character on the sender's map (as the world server last reported it), the sender included.
  • Ignore: a recipient that ignores the sender gets none of its whispers, channel or zone lines; the sender is not told.
  • Order of checks for a ChatSend: rate limit, then text (sanitize_chat), then mute, then the target.
  • Unexpected: any other message after AuthOk, or a chat message before it, is Disconnect{unexpected_message}.

Notices

ChatNotice.code. "error" ones are a request refused or a message dropped (the engine's chat.error), "notice" ones confirmations (chat.notice).

ValueNameKindMeaning
1 not_online error Whisper: no character of that name has a chat connection (name)
2 muted error You are muted: the message was dropped (minutes left). The world server sends it too, for a say, yell or emote
3 not_allowed error Mute / unmute: GM or admin only
4 no_channel error No such channel (name)
5 not_in_channel error Send to / leave a channel you are not in (name)
6 rate_limited error Over CHAT_RATE_COUNT per CHAT_RATE_WINDOW_MS: dropped
7 rejected error Empty, over CHAT_MAX_BYTES, or not valid UTF-8: dropped
8 bad_name error Not a character name (3-16 letters) (name)
9 ignored notice Ignore done (name)
10 unignored notice Unignore done (name)
11 mute_set notice To the GM: name muted for minutes
12 mute_cleared notice To the GM: name unmuted
13 you_muted notice To the muted character: for minutes
14 you_unmuted notice To the unmuted character

Internal link (CHAT_LINK_PORT, 7779)

Each world server connects (TLS, it verifies the chat service's certificate) and keeps the link up with backoff. Several world servers may link at once.

OpcodeNameDirPayload
0x0200 LinkHello world → chat u16 protocolVersion, str secret (CHAT_LINK_SECRET); first
0x0201 LinkOk chat → world (empty); then a MuteState per running mute
0x0202 CharOnline world → chat u64 accountId, u64 charId, str name, u16 map: entered the world; after LinkOk, one per character already in it
0x0203 MapChanged world → chat u64 charId, u16 map
0x0204 CharOffline world → chat u64 charId: left the world (logout, disconnect, duplicate login)
0x0205 MuteState chat → world str name, u64 untilMs (Unix ms, wall clock; 0: not muted)
  • Re-sync: on every (re)connect the chat service sends every running mute, and the world server every character it has in the world. The world server clears its mutes on LinkOk first.
  • Link lost: the chat service takes that world's characters offline and closes their chat connections (no_character); their clients reconnect once the world has linked again.
