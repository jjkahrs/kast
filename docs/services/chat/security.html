Security behaviour

Game clients

  • TLS 1.2+ only, as the world server; with the dev setup both present the same certificate.
  • Access tokens: the world server's verifier, shared (token verification): RS256 by kid from the auth service's JWKS, iss, aud, exp. A bad token gets Disconnect{invalid_token}, an expired one token_expired. The role (player, gm, admin) comes from the token, never from the client.
  • Bound to a character: a connection speaks only as its account's online character, as the world server reported it. No character within CHAT_BIND_TIMEOUT_MS: Disconnect{no_character}. A second connection for the same character replaces the first (logged_in_elsewhere); the character leaving the world closes it (no_character).
  • Text: exactly the world server's rules and code (sanitize_chat): valid UTF-8, at most CHAT_MAX_BYTES, C0/DEL/C1 control characters stripped; an invalid or oversized message gets ChatNotice{rejected}. The rate limit (CHAT_RATE_COUNT per CHAT_RATE_WINDOW_MS, per sender) answers rate_limited; rejected messages count. Neither disconnects.
  • Frames: the world server's session limits (frame size, handshake deadline, idle timeout, message rate with disconnect on sustained excess, send-buffer cap).
  • Logging: tokens and chat text are never logged at info or above; at debug level only a message's byte length is.

World links

  • Separate port (CHAT_LINK_PORT), meant for the private network; TLS like the client port.
  • Shared secret: the first message must be LinkHello{version, secret}, compared in constant time with CHAT_LINK_SECRET. Wrong secret: Disconnect{invalid_token} and a world link refused: wrong secret warning; wrong version: protocol_mismatch; anything else first: unexpected_message.
  • Trust: a linked world server is trusted with who is online where. Its characters go offline when the link drops.

Mutes

  • Who: only a gm or admin token may mute or unmute; a player gets ChatNotice{not_allowed} (logged as mute refused: not a GM).
  • What: by character name (case-insensitive), online or not, for 1 to CHAT_MUTE_MAX_MINUTES minutes. The muted character gets you_muted; its whispers, channel and zone lines are dropped with ChatNotice{muted, minutes left}, and every linked world server drops its say, yell and emote the same way.
  • Stored: table chat_mutes in kast_chat (name, end time, the GM's account), loaded at startup and sent to each world server when its link connects; expired rows are deleted at startup and every minute. A database write that fails is logged (mute store write failed); the mute still applies until the next restart.
  • Audit: muted / unmuted log lines with the name, minutes and GM account.

Ignore

Per character, in memory, until it logs out (or the chat service restarts). Ignored senders aren't told.
