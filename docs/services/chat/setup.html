Setup and commands

With the world stack (docker compose)

The chat service is part of the services/world compose stack. In services/world/.env (from .env.example) set CHAT_LINK_SECRET (16+ characters) and CHAT_DB_PASSWORD, then:

cd services/world
docker compose up -d --build        # world, chat, auth, mysql, mailpit
docker compose logs chat            # "migrations done", "mutes loaded", "listening", then "world link up"
docker compose restart chat         # mutes survive it (MySQL)
  • Image: kast-chat:dev, built from services/ with chat/Dockerfile (it compiles services/world/protocol and the shared server code). Its dependency layer is the world image's, so Docker reuses it.
  • Database: the one-shot service chat-db-init creates kast_chat and its user on every start (fresh or existing MySQL volume); the chat service runs its own migrations.
  • Ports: 7778 for game clients (published as CHAT_HOST_PORT); 7779, the internal link, stays inside the compose network.
  • TLS: the chat service uses the world server's dev certificate (the world-certs volume, read-only), whose names include chat, so a client trusts one CA file for both. It starts after the world server is healthy (which makes the certificate). A dev certificate from before it named chat is made again by the world server: copy it to clients again (the starter-mmo's setup_realm.cmake does).
  • World server settings: the compose file sets the world's CHAT_PUBLIC_HOST (default 127.0.0.1, the host's view), CHAT_PUBLIC_PORT, CHAT_LINK_HOST=chat and the secret.

Build and test on Windows

cd services/chat
cmake --preset debug && cmake --build --preset debug
ctest --preset debug                # chat_self_check

Same toolchain as the world server (VS 2022, VCPKG_ROOT, presets debug / release; linux-release in the image).

Run outside docker

cd services/chat
cp .env.example .env                # set CHAT_LINK_SECRET and the database; every variable: Configuration
build/debug/kast_chat.exe           # reads the environment (load .env yourself)

Point a world server at it with CHAT_LINK_HOST / CHAT_LINK_PORT / CHAT_LINK_SECRET and tell clients where it is with CHAT_PUBLIC_HOST / CHAT_PUBLIC_PORT (world configuration).

Logs

JSON lines on stdout, like the world server's: listening, world link up / world link down, chat client bound, auth rejected, no character online for the account, muted / unmuted {name, minutes, by}, mute refused: not a GM, mutes expired. Chat text never appears at info level or above.
