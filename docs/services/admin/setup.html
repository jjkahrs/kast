Setup

The admin app runs in the world compose stack (services/world/docker-compose.yml) next to auth, world, chat, MySQL and Mailpit.

cd services/world
cp .env.example .env        # first time; otherwise add the admin variables from .env.example to your .env
# set ADMIN_DB_PASSWORD, ADMIN_WORLD_DB_PASSWORD, WORLD_ADMIN_SECRET, SEED_ADMIN_EMAIL, SEED_ADMIN_PASSWORD
docker compose up -d --build
curl -s localhost:3200/health   # {"status":"ok","db":"ok"}

Open http://localhost:3200 and sign in with SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD (auth creates that admin, pre-verified, on start). Create GM accounts on the Accounts page.

ServicePortNotes
admin127.0.0.1:${ADMIN_HOST_PORT:-3200}API + SPA. Runs its migrations (kast_admin) on start. Published on the host loopback only. COOKIE_SECURE=false because the stack is plain http
admin-db-init-Runs on every up, after world and auth are healthy (docker/admin-db-init.sh, idempotent): creates kast_admin and its user, the kast_world_admin user with SELECT, UPDATE on kast_world.characters only, and seeds realm REALM_ID in auth with admin_host=world, admin_port=7780 (kept if already set)
world7780 (compose network only)The admin port; on when WORLD_ADMIN_SECRET is set

The admin service reads the world's dev certificate from the world-certs volume (read-only) as the CA for the admin port.

GMs need one admin sign-in first

GMs cannot read realms from auth (realm admin endpoints are admin-only), so the admin service keeps a copy of each realm's admin host/port in kast_admin.realm_endpoints. It is refreshed whenever an admin signs in, opens the Realms or Online page, or edits a realm. Until an admin has done that once after a realm was added or its admin endpoint changed, GMs get 503 realm_unreachable for that realm's online list, kicks and character writes.

Running on the host

For development, run the API and the Vite dev server on the host against the compose stack's MySQL and auth:

cd services/admin
npm ci
cp .env.example .env     # DB_PORT=3307 (compose MySQL), AUTH_URL=http://127.0.0.1:3100,
                         # WORLD_ADMIN_CA_FILE = a copy of the world's server.crt
npm run dev:api          # API on :3200 (tsx, reads .env)
npm run dev              # SPA on http://localhost:5173, /api proxied to :3200 (ADMIN_API_URL overrides)

The world admin port is not published by compose, so from the host online/kick only work against a world server running on the host.

Tests

npm test uses TEST_MYSQL_ROOT_PASSWORD to create TEST_ADMIN_DB_NAME / TEST_WORLD_DB_NAME and the two least-privilege users on first run, and starts auth in-process with ../auth/.env on auth's test database. The MySQL of the auth compose stack (port 3306) works.
