Kast Admin App

Web app for admins and game masters: accounts, roles, bans, characters, realms and who is online, across every realm, with an audit log of every change. It lives in services/admin: a React single-page app (web/, Vite + React Router + TanStack Query, plain CSS in the Kast palette) served by a Node 24 / TypeScript / Express 5 backend-for-frontend on one port (3200).

How it fits together

browser (SPA, cookies only) --HTTP--> admin service :3200
                                       |-- auth /v1/admin/*               accounts, bans, roles, realms (caller's token)
                                       |-- MySQL kast_world.characters    SELECT/UPDATE only
                                       |-- MySQL kast_admin               audit log, realm endpoint copy
                                       '-- world admin port :7780 per realm (TLS + secret): online list, kick
  • Auth owns accounts. Account and realm changes are proxied to the auth admin endpoints with the signed-in user's own access token, so auth re-checks every permission. The admin service never connects to kast_auth.
  • Characters are read and written directly in kast_world.characters. Before a write, the realm's world server is asked whether the account is online (online guard).
  • Online / kick use each world server's admin port. A kick disconnects the client the same way a duplicate login does, so the character is saved.
  • Audit: every mutating request writes one row to kast_admin.admin_audit, on success and on failure. Admins read it on the Audit page.

Pages in the app

PageWhoWhat
Loginadmin, gmPlayers are refused (403)
Accountsadmin, gmSearch by email or id; filter by role, banned, verified, locked; paginated. Admins also get Create account
Account detailadmin, gmInfo, ban history, characters. Ban (with a confirmation) and unban; admins also set the role, verify the email, send a password reset, unlock, revoke sessions and delete (with a confirmation)
Charactersadmin, gmSearch by name prefix, realm, account; include deleted
Character detailadmin, gmRename, move, edit components/options JSON, delete (with a confirmation) and restore. An online character shows a Kick button; a write while it is online opens a dialog that offers Kick. Admins get a Force checkbox when the realm is unreachable
Onlineadmin, gmSessions per realm (lobby sessions show as lobby); Kick with a reason and a confirmation
RealmsadminCreate, edit and delete realms, including the admin host/port; reachability of each admin port
AuditadminFilter by actor, action, target and date range; before/after JSON per entry

API errors are shown with a readable label and their code, for example Character is online character_online. Screenshots of every page for both roles are in services/admin/screenshots/ (made by npm run screenshots).
