Zone Builder

kast_zone_builder (tools/zone-builder/, built with everything else: build\<preset>\kast_zone_builder.exe) creates and edits a project's zone maps (maps/<folder>/, see Maps and Terrain) in 3D and saves them in place, in the formats the engine and the world server load. It is a standalone app; the editor does not need to be open.

Open. File > Open Project... (or --project <dir>) lists maps/*/map.json in the Maps panel; click one to open it (one map at a time; unsaved edits ask Save / Don't Save / Cancel first, and so does closing the window). New Map... asks for a folder (letters, digits, _, -), a name, an id (the lowest unused; a used id is refused) and 1-8 by 1-8 tiles; nothing is written until you save. The title shows * while there are unsaved edits.

3D view (behind the panels): the map's tiles with its material, lit like the game. Right drag (or Alt + left drag) orbits, middle drag pans, the wheel zooms, F frames the map. Overlays: tile borders, the player spawn (with its heading), areas (portals in blue, the selected one with corner handles), spawns (with heading), patrol paths, zone objects (a dot each; obstacles' and interactables' shapes outlined on the ground), the brush ring. They are drawn over the terrain, not hidden by hills. Zone objects also show as their prefabs, as in game.

Objects

Zone objects are prefabs placed on the map's tiles (formats: World Server, Maps, Objects; in game: Engine, Terrain). The project's .prefab files are listed in the Objects panel.

  • Types: Visual (grass, flowers: client only, blocks nothing), Obstacle (rocks, walls, trees: blocks players and NPCs; the server knows only its shape) and Interactable (blocks like an obstacle, and a player can activate it; the server publishes its event).
  • Place Object: pick the prefab and the type, then click the terrain: the object stands on the ground there (y snapped), yaw 0, scale 1. A new obstacle or interactable gets a 1 m box shape; a new interactable gets the next free id on the map and a server entry (range 3, event <prefab name>.activated).
  • Select and move: with no tool, click an object's dot to select it (or pick it in the list) and drag to move it on the ground. Moving one into another tile moves it to that tile's file, an interactable's server entry with it.
  • Fields: type (an interactable turned obstacle loses its id and server entry; a visual keeps an old shape unused), prefab, position (x, z; y follows the ground), yaw (degrees here, radians in the file), scale (the prefab only), shape (Box half extents, turned by yaw, or Cylinder radius and height, in metres, standing on the object). An interactable also has its id (unique on the map: a used one is not taken), name, and the server-only range, event and data (a JSON object, checked as you type: text that isn't one shows the problem and keeps the last valid data; empty removes it). The server entry's pos, yaw, shape and name always follow the object.
  • Overlays: a dot per object (green visuals, orange obstacles, blue interactables with #id name, the selection in yellow) and each shape's outline on the ground (16 points for a cylinder). The 3D view draws each object's prefab, scaled and turned; a tile's objects are rebuilt when its file changes.
  • Scatter (visuals only): tick prefabs (one is picked at random per object), set the radius, how many per dab, random yaw or not, the scale range and the seed. Drag on the terrain: a dab on mouse down and another each time the brush has moved its radius, each placing that many visuals at random points of the circle, on the ground (points off the map are skipped). The whole stroke is one undo step. Erase visuals turns the brush into an eraser that removes every visual inside the circle (obstacles and interactables stay). The random numbers come from the seed (xorshift32, the same on every machine): changing the seed or pressing Restart starts its sequence again, so the same seed and strokes give the same objects.
  • Save writes each changed tile's objects/ and .server/interactables/ file and deletes a tile's files once it has none. Unknown keys in the files are kept. Re-bake the navmesh (Bake) after placing, moving or removing an obstacle or interactable.

Generated terrain

Generate (Terrain panel) replaces the heights of every declared tile with fBm Perlin noise: Seed (or Randomize), Scale (metres per noise feature, default 256), Octaves (5), Persistence (the amplitude ratio between octaves, 0.5) and Lacunarity (the frequency ratio, 2). The noise is sampled at each sample's map position, so tiles sharing an edge get the same samples (no seams, whatever the tile layout), and it is stretched over the whole height range: the lowest sample is the range's min, the highest its max. The same seed and settings on the same tiles give the same heights. The player spawn moves up or down onto the new ground. One Generate heights is one undo step.

Height colors is a gradient over the height range: stops at a position (0 % = the range's min, 100 % = its max) with a color. Between two stops the color blends linearly; below the lowest and above the highest it is that stop's. Add stop, Remove (at least 2 stay), drag a position or pick a color; each change is one undo step. The default is sand, grass, rock, snow. It is kept in map.json as "terrainColors" (see Terrain).

Create texture & material (Terrain panel) sets the map's material to materials/<folder>_terrain.mat, "terrainUv": "map" (one texture over the whole map) and the default colors if the map has none, as one undo step. The 3D view shows the result straight away; nothing is written until you save. Then every save writes:

File Content
textures/<folder>_terrain.png 8-bit RGB, the color of the ground at each pixel: 1 px per metre over the bounding box of the declared tiles (256 px per tile), shrunk to fit 4096 px on the longest side; grey where no tile is. Row 0 is the box's min z
materials/<folder>_terrain.mat white base color times that texture, metallic 0, roughness 0.9

Both are re-baked on every save of the map, so the texture follows sculpting and color edits. These two paths are the only files the zone builder writes outside maps/: other materials and textures are never touched, and if one of them already exists before the map has been saved using it (someone else's file), the save is blocked with a problem on that file. Picking another material in the Map panel keeps it; the generated files are then no longer written.

Save (Ctrl+S, File > Save) first checks the map as the world server would load it: kast_map's parse_manifest, parse_areas and parse_spawns for every tile's file, spawn ids unique on the map, spawn files on declared tiles, the map id unused by the project's other maps, portals to an existing map, onto its tiles and not into a portal there, valid terrainColors, no foreign file at the generated terrain texture or material path, every objects file (parse_objects: any bad entry) and interactables file (parse_interactables) on a declared tile, interactable ids unique on the map, and each interactable object with a server entry of the same id in its tile's file (and each entry with an object). Any problem: nothing is written, and Problems lists them all (file and message, as the server reports them). Only files that changed are written; a map opened and saved unchanged keeps every byte. Undo / Redo (Ctrl+Z / Ctrl+Y, Edit menu) cover every edit; a brush stroke or a drag is one step.

Command line (tests and scripts; edits run in order, each one undo step):

kast_zone_builder [--project dir] [--map folder] [edits...] [--frames N] [--screenshot out.png] [--size WxH]
                  [--window-pos X,Y] [--no-vsync] [--log-fps] [--sculpt-loop] [--headless] [--no-recycle]
                  [--focus x,z,distance] [--panel name] [--select id] [--prompt-remove-tile tx,tz]
                  [--mapbake exe] [--bake]
edits: --new-map folder[,W,H[,id]]  --map-id N  --material path  --set-spawn x,z[,heading]  --add-tile tx,tz
       --remove-tile tx,tz  --falloff F  --sculpt x,z,radius,metres (negative lowers)  --flatten x,z,radius,height[,f]
       --height-range min,max  --import-png tx,tz,file  --export-png tx,tz,file
       --add-area id,priority,x0,z0,x1,z1  --add-polygon id,priority,x,z,x,z,x,z...  --area-parent id,parent
       --area-portal id,map,x,y,z,heading  --move-area-vertex id,i,x,z  --delete-area id
       --add-spawn id,npc,x,z[,heading[,respawnSec]]  --move-spawn id,x,z  --delete-spawn id
       --add-path spawnId,wait,loop(0|1),x,z,x,z...
       --add-object type,prefab,x,z[,yaw[,scale[,box,hx,hy,hz | cylinder,r,h]]]
       --set-interactable id,range,event[,name[,data JSON object]]  --move-object tx,tz,i,x,z  --delete-object tx,tz,i
       --scatter x,z,radius,count,seed,scaleMin,scaleMax,prefab[+prefab...]  --erase-visuals x,z,radius
       --generate-heights seed[,scale,octaves,persistence,lacunarity]  --terrain-colors pct,r,g,b,pct,r,g,b...
       --create-terrain-material  --undo  --redo  --validate  --save  --expect-save-fail

--terrain-colors takes 4 numbers per stop (at least 2 stops): the position in % of the height range, then red, green and blue 0..1, e.g. --terrain-colors 0,0,0,1,100,1,0,0 for blue at the bottom and red at the top. --generate-heights 7 uses the default scale, octaves, persistence and lacunarity. Objects are addressed by tile and index in its objects file (--move-object 0,0,2,300,40), interactables by id. --scatter is one stroke of one dab with a fresh seed (random yaw); --set-interactable's data is the rest of the value, commas and all (--set-interactable 1,3,shrine.activated,Meadow Shrine,{"message":"Hi"}). --select object:tx,tz,i selects an object for a screenshot.

A failed edit or save exits 1. --headless runs the edits (and --bake, waiting for it) without a window. --frames runs show the window without taking focus; KAST_WINDOW_POS / --window-pos place it. --bake holds the frame count until kast_mapbake ends and logs how many frames were drawn meanwhile. --log-fps logs the frame rate once a second; --sculpt-loop raises and lowers a brush circling the map every frame (the sculpting benchmark: a Release build with --no-vsync on an 8 x 8 map draws about 300 fps on an RTX 4070 Ti SUPER, rebuilding only the touched tiles' meshes). --no-recycle deletes files for good (the tests use it).
